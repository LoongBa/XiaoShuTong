**决策/修复**（按踩坑顺序）：

1. **FreeSql 版本断层（CPM 3.5.310 vs 框架 refs 3.5.311）**
   - 现象：`dotnet run schema export` 抛 `Could not load file or assembly 'FreeSql, Version=3.5.311.0'`
   - 根因：项目 `Directory.Packages.props` 锁 3.5.310，框架 refs（`build\refs\Directory.Packages.props`）已升至 3.5.311 → TKWF.Domain.FreeSql.dll 绑定 3.5.311 找不到
   - 修复：项目 CPM FreeSql 系列对齐 3.5.311（FreeSql/FreeSql.DbContext/FreeSql.Extensions.Linq/FreeSql.Provider.PostgreSQL；FreeSql.Repository 保持 3.5.310 与框架一致）

2. **Dll 模式框架 DLL 不传递 NuGet 依赖**
   - 现象：3.5.311 对齐后仍缺 `FreeSql.DbContext 3.5.311` / `FreeSql.Extensions.Linq`
   - 根因：`TKWF.Domain.targets` 注释明确"框架 DLL 在 Dll 模式下不会自动传递 NuGet 依赖，需消费者显式声明"——Domain.csproj 只引了 `FreeSql.Provider.PostgreSQL`
   - 修复：Domain.csproj 补 `FreeSql` / `FreeSql.DbContext` / `FreeSql.Extensions.Linq`（版本由 CPM 统一）

3. **GraphQL 跨域同名 DTO 冲突（GetWrongQuestionsResDto ×2）**
   - 现象：`The name 'GetWrongQuestionsResDto' was already registered by another type`
   - 根因：HotChocolate 按 C# 短类名注册 ObjectType（非全名）；Learning 与 Stats 域同名 ResDto → schema 构建失败
   - 修复：Stats 版重命名 `GetWrongQuestionsResDto` → `StatsGetWrongQuestionsResDto`（对齐既有 `[GenerateController(ControllerName="StatsWrongQuestions")]` 消歧惯例）

4. **GraphQL 跨域同名 DTO 冲突（WeakPointDto ×2）**
   - 现象：`The name 'WeakPointDto' was already registered`（Services.Shared 共享版 vs Services.Parent 变体版）
   - 根因：批次 3 去重时 Parent 版因形状不同（多 Subject/StateText）保留独立，但同名仍触发 GraphQL 冲突
   - 修复：Parent 版重命名 `WeakPointDto` → `ParentWeakPointDto`

5. **buildSchema.ps1 schema export 输出路径双重拼接**
   - 现象：`DirectoryNotFoundException ...\WebApi\src\XiaoShuTong.WebApi\schema.graphql`
   - 根因：`dotnet run` 以 WebApi 项目目录为工作目录，`--output` 传相对路径被二次拼接

**避坑指南**：

> - **跨域 DTO 命名纪律**：HotChocolate GraphQL 类型按 C# 短类名注册——跨域同名 DTO（Res/Item）必须重命名消歧（惯例：域前缀 `{域}{ClassName}Dto`），ControllerName 消歧只解决控制器，不解决 DTO

> - **schema export 路径**：dotnet run 的 `--output` 用绝对路径，避免双重拼接
> - **MSB3492（obj 缓存损坏）**：shutdown build-server → 删 obj → 逐项目 build，勿在损坏缓存上硬跑
