## 二、审核结论

**总评：通过（框架侧 ADR80 判定由框架组最终确认）**

三代遗留 T7「浏览器端到端走查」首次全链路打通——V0.6.4/05 战绩榜双指标 + 战力榜 单指标在真实后端 + 真实浏览器完整渲染（登录/首页/双榜/myRanking/热力图 5/5 PASS）。发现并闭环两类缺陷：

1. **前端 GraphQL 契约接线缺口（本项目可修，已闭环）**：
   - 缺口 A：`main.tsx` 漏注册 `selectionMap`（codegen 的 operationSelection 已生成但从未接线）→ Use<T>() 无子字段选择 → 400 "must have a selection of subfields"
   - 缺口 B：框架 tkwf-tsclient **1.0.9** Use<T>() 通道不传递变量类型 → `inferGraphQLType` 对对象退化为 `$request: JSON` → 后端 HotChocolate 400 "variable not compatible"（登录因 SDK 内置 mutation 硬编码 variableTypes 未暴露，业务查询全挂）
   - 修复：SDK 升级 1.0.10（框架组 V1.0.10 提供 variableTypesMap 透传能力）+ 本仓库 codegen 补产 operationVariableTypes + main.tsx 双 map 接线
2. **首页 DateTime 契约不一致（本项目可修，已闭环）**：reviewQueue.date 纯日期串 / heatmap start/end 空串 → DateTime 标量 coerce 失败 → 400
3. **框架会话通道缺陷（框架组实验 3 修复，本项目验证）**：GraphQL 登录 `SessionException: Session not found`（REST 同输入成功；会话已写 store 但 GraphQL 通道读不到）→ 框架组部署 `WebSessionManager.NewSessionAsync` 泛型门面统一 HybridCache 类型标签，本项目复验通过

**证据**：
- 浏览器端到端复测 **5/5 PASS**（playwright Edge 通道 + 3015 vite + 5020 WebApi）
- 修复前后请求体对比：`query($request: JSON)` → `query($request: GetRankingsReqDtoInput)`（铁证）
- 两通道交叉验证：GQL 登录 key → GQL 查询 items=3 + **isMe=True**（会话身份完整注入）
- 裸发协议验证：GQL/REST 登录 + GQL 查询 3 请求全绿（ADR80 复验第 1-3 步）
- `pnpm typecheck` **0 错误**

## 四、关键决策

| # | 决策 | 说明 |
|---|------|------|
| ① | selectionMap/variableTypesMap 由 codegen 统一产出 | `scripts/gen-ts-client.ts` 与 ts-client.g.ts 同源生成（FieldArg.gqlTypeRaw 保留 `[T!]` 可空组合），main.tsx 一次性注册；新增操作后跑 `npm run gen-ts-client` 即自动覆盖，手写易漂移 | 
| ② | DateTime 一律完整 ISO | HotChocolate DateTime 标量仅接受 ISO 8601（含 T/Z），纯日期/空串 coerce 失败；前端统一 `toISOString()` 完整串或 null |
| ③ | 框架缺陷走部署-复验流程 | 本项目无框架源码（Dll 模式），Session-not-found 根因由框架组定位（HybridCache 类型标签不一致），本项目承担复现证据链 + 部署后复验 |
| ④ | 浏览器走查不依赖 playwright MCP | 系统 Chrome SxS 损坏（依赖集 153.0.8010.12 缺失）导致 MCP spawn UNKNOWN；改用本地 playwright 1.63.0 + Edge 通道（channel:'msedge'）规避，无需修环境 |
