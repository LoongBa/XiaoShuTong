# 长文分段语音交互 - 开发方案（V0.7.6）

## 一、背景与版本规划

### 1.1 背景

依据 `docs/工作计划.md`（last_updated 2026-09-30）P2「长文分段语音」推进。**用户裁定（2026-09-30）**：
- **分段：同意**——R3a/R3b 长文支持分段录制/拼接
- **ASR：近期不实现**——不自采音频转文字，经**客户端（手机/电脑）系统语音输入法**转文字（对齐 `题型与交互设计规范-V0.1.md` §6.1 V3 决策：强制系统语音输入法 L141/144，禁用浏览器 MediaRecorder ASR）

**规范依据**（`docs/2-架构设计/V1/题型与交互设计规范-V0.1.md`）：
- L111：R3a 段落默写 hybrid voice/text，"长文可分段语音"
- L112：R3b 整篇默写 hybrid voice/text，"整篇语音（挑战大，容错宽）"
- L146 原则 3：**分段语音**——长文（R3a/R3b）支持分段录制，逐段拼接判题

**当前实现缺口**（`QuestionCard.tsx` 源码实证）：
- R3a/R3b 用单个 `textarea`（L164-173）：`text` 单状态，语音 mic 追加到同一 textarea（L138 `setText(prev => prev + t)`）
- **无分段感知 UX**：不分段显示/分段追加/分段管理（删除某段重录）；长文整篇一次语音超出系统输入法单次 ASR 长度限制时无引导

### 1.2 版本规划

- WebH5 无独立 MinVer tag（纯静态前端，版本由迭代文档管理）；本轮按领域迭代编号 **V0.7.6** 登记（纯前端交互，后端契约不变）。
- 纯前端 QuestionCard 交互改造，无后端契约变化、无 DTO 变化、无需 ADR、无需 tkwf-tsclient（无 RPC 调用新增）。
- 提交规划：逻辑单元收敛（建议 2 个：QuestionCard 改造一组 + 文档同步一组）。

## 二、任务 T1：QuestionCard 分段交互改造

### 2.1 现状（源码实证）

| 位置 | 现状 | 缺口 |
|------|------|------|

### 2.2 改动设计（分段输入 + 拼接提交，Oracle 决策点见 §五）

**状态改造**：`text: string` → `segments: string[]`（分段列表）+ `currentIndex` 定位"当前段"（语音追加目标）。

**交互语义**（对齐规范 L146 分段录制 + L145 二次确认）：

```tsx
// 分段列表渲染（R3a/R3b 专用，替代单 textarea）
const [segments, setSegments] = useState<string[]>(['']);  // 至少 1 段

// 每段一个 textarea（行内可编辑，二次确认——用户微调后再提交，原则 2）
{segments.map((seg, i) => (
  <Textarea
    key={i}
    value={seg}
    onChange={(e) => updateSegment(i, e.target.value)}
    placeholder={`第 ${i + 1} 段（可分段背诵）`}
    rows={2}
  />
))}

// 追加段：加一段空 textarea（长文可继续分段）
<Button variant="ghost" onClick={addSegment}>＋ 添加一段</Button>

// 每段语音：唤起系统输入法（focus+click 到该段 textarea）→ ASR 回填该段 → 二次确认
// 删除段：长文误录可删除重录（保留至少 1 段）

// 提交：分段拼接（段落间换行）→ onSubmit(fullText)
const submitSegments = () => {
  const full = segments.map(s => s.trim()).filter(Boolean).join('\n');
  if (full) onSubmit(full);
};
```

**关键约束**：
- **至少保留 1 段**（删除最后一段时重置为空段，防无输入区）
- **拼接分隔符 `\n`**：段落间换行——与整篇默写语义一致（答案以文本块拼接），判题 similarity/hybrid 引擎对换行宽容（关键词逐组命中）
- **语音追加到当前段**：`handleMicClick(i)` 唤起第 i 段 textarea 的系统输入法（`useVoiceInput` 的 `activate()` 需绑定该段 ref）——**Web Speech 兜底追加到第 i 段**（`prev + t` 语义不变，但目标为段 i）
- **提交按钮 disable 条件**：全段 trim 后为空 → 禁用（原 `!text.trim()` 等价）
- **题型切换清空**：现有 L73-79 `useEffect` 清空逻辑加 `setSegments([''])`

### 2.3 语音绑定细节

当前 `useVoiceInput(inputRef)` 绑定单个 ref。改造后 R3a/R3b 需要**每段一个 ref**（语音唤起目标 = 当前编辑段）：

```tsx
const segmentRefs = useRef<(HTMLTextAreaElement | null)[]>([]);
// 每段 textarea ref={el => segmentRefs.current[i] = el}
// 语音按钮 onClick={() => handleMicClick(i)}
const handleMicClick = (i: number) => {
  const activated = voice.activate();  // useVoiceInput 绑定 segmentRefs.current[i]
  if (!activated && voice.supported === true && 'startWebSpeech' in voice) {
    voice.startWebSpeech((t) => updateSegment(i, prev => prev + t));
  }
};
```

> ⚠️ `useVoiceInput` 当前签名绑定单个 ref（`targetRef: RefObject<HTMLInputElement | null>`）——R3a/R3b 多段场景需适配：**方案 A**（默认）：保留单 ref hook，`activate()` 前动态设置 `voice.targetRef.current = segmentRefs.current[i]`（需 hook 支持可变 target）；**方案 B**：R3a/R3b 段语音直接复用现有"输入框聚焦 + 系统输入法"模式——每段 textarea `onFocus` 即唤起（系统输入法跟随焦点），Mic 按钮仅作 Web Speech 兜底触发。**Oracle 决策点 M1 裁定**。
