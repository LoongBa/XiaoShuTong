# 长文分段语音交互 - 开发方案（V0.7.6）

## 一、背景与版本规划

### 1.1 背景

依据 `docs/工作计划.md`（last_updated 2026-09-30）P2「长文分段语音」推进。**用户裁定（2026-09-30）**：
- **分段：同意**——R3a/R3b 长文支持分段录制/拼接
- **ASR：近期不实现**——不自采音频转文字，经**客户端（手机/电脑）系统语音输入法**转文字（对齐 `题型与交互设计规范-V0.1.md` §6.1 V3 决策：强制系统语音输入法 L141/144，禁用浏览器 MediaRecorder ASR）

**规范依据**（`docs/2-架构设计/V1/题型与交互设计规范-V0.1.md`）：
- L111：R3a 段落默写 hybrid voice/text，"长文可分段语音"
- L112：R3b 整篇默写 hybrid voice/text，"整篇语音（挑战大，容错宽）"
- L146 原则 3：**分段语音**——长文（R3a/R3b）支持分段录制，逐段拼接判题

**当前实现缺口**（`QuestionCard.tsx` 源码实证）：

- **无分段感知 UX**：不分段显示/分段追加/分段管理（删除某段重录）；长文整篇一次语音超出系统输入法单次 ASR 长度限制时无引导

### 2.2 改动设计（分段输入 + 拼接提交，Oracle 决策点见 §五）

**状态改造**：`text: string` → `segments: string[]`（分段列表）+ `currentIndex` 定位"当前段"（语音追加目标）。

**交互语义**（对齐规范 L146 分段录制 + L145 二次确认）：

```tsx
// 分段列表渲染（R3a/R3b 专用，替代单 textarea）——Oracle M3：最小 1 段
const [segments, setSegments] = useState<string[]>(['']);
const [currentIndex, setCurrentIndex] = useState(0);
const segmentRefs = useRef<(HTMLTextAreaElement | null)[]>([]);

// 每段一个 textarea（行内可编辑，二次确认——用户微调后再提交，原则 2）
{segments.map((seg, i) => (
  <div key={i} className="relative">
    <Textarea
      value={seg}
      onChange={(e) => updateSegment(i, e.target.value)}
      onFocus={() => setCurrentIndex(i)}          // Oracle M1 方案 B：焦点跟随
      placeholder={`第 ${i + 1} 段（可分段背诵）`}
      rows={3}
      className="text-base pr-12 resize-none max-h-[120px] overflow-y-auto"
      ref={(el) => { segmentRefs.current[i] = el; }}
    />
    {segments.length > 1 && (
      <button onClick={() => removeSegment(i)}>删除此段</button>  // M3：至少保留 1 段
    )}
  </div>
))}

// 追加段：加一段空 textarea（长文可继续分段）
<Button variant="ghost" onClick={addSegment}>＋ 添加一段</Button>

// 每段语音：R3a/R3b 走 Oracle M1 方案 B（焦点跟随）——移动端聚焦即唤起系统输入法；
// Mic 按钮仅作 Web Speech 兜底（桌面）或聚焦便捷入口（移动端）。C1 阻塞级闭环：不调用 voice.activate()
const handleSegmentMic = () => {
  const el = segmentRefs.current[currentIndex];
  if (el) el.focus();  // 移动端：聚焦 → 系统输入法语音跟随（主路径）
  if ('ontouchstart' in window) return;  // 触摸设备主路径即聚焦
  if (voice.supported === true && 'startWebSpeech' in voice) {
    voice.startWebSpeech((t) => updateSegmentAppend(currentIndex, t));  // 桌面兜底：Web Speech 追加到当前段
  }
};

// 提交：分段拼接（段落间换行）→ onSubmit(fullText)；全空禁用（C5）
const submitSegments = () => {
  const full = segments.map(s => s.trim()).filter(Boolean).join('\n');  // Oracle M2：\n 换行分隔
  if (full) onSubmit(full);
};

// 提交按钮 disable 分支（C5 闭环）：
//   R3a/R3b → !segments.some(s => s.trim())
//   其余   → !text.trim()
```

**关键约束**：
- **至少保留 1 段**（M3）：`removeSegment(i)` = `setSegments(prev => prev.length <= 1 ? [''] : prev.filter((_, idx) => idx !== i))` + **同步 `segmentRefs.current.splice(i, 1)`**（Oracle 风险补充：ref 数组索引同步）
- **拼接分隔符 `\n`**（M2）：段落间换行——与整篇默写语义一致（答案以文本块拼接），关键词逐组命中不参与换行比对，`\n` 不干扰判题；trim 吃掉段内首尾空白、filter 空段防连续换行
- **语音追加到当前段**（C1）：`updateSegmentAppend(i, t)` = `setSegments(prev => prev.map((s, idx) => idx === i ? s + t : s))`——Web Speech 兜底追加目标 = currentIndex 段
- **题型切换清空**（C4）：现有 L73-79 `useEffect` 清空逻辑加 `setSegments([''])` + `setCurrentIndex(0)`
- **autoResize effect 处理**（Oracle 风险补充）：现有 L82-88 的 textarea 高度自适应依赖 `[text]` 且 `textareaRef` 仅绑定旧 R3a/R3b 单 textarea——改造后 R3a/R3b 用 segmentRefs 数组，**移除 `textareaRef` + autoResize effect**（每段 textarea 自带 `rows=3 + max-h-[120px] overflow-y-auto`，段内长文滚动；R1/R2/O5 用 Input 无需 autoResize）

### 2.3 语音绑定细节（Oracle C1 阻塞级闭环：方案 B 焦点跟随，不改 useVoiceInput）

**Oracle M1 裁定**：采纳方案 B（焦点跟随）——移动端系统语音输入法是**跟随焦点的 OS 级行为**（聚焦任一 textarea 自动唤起），不需要 JS `focus()+click()`；方案 A（动态 target ref）驳回（hook 签名 `RefObject<HTMLInputElement>` 与 textarea 类型不兼容 + 闭包捕获固定 ref 无法动态切换 + 移动端冗余）。

**实施**：
- R3a/R3b **不调用 `voice.activate()`**（该路径留给 R1/R2/O5 单输入，`useVoiceInput(inputRef)` 签名与行为**零改动**）
- 每段 textarea `onFocus={() => setCurrentIndex(i)}` 记录当前段（系统输入法跟随焦点自动唤起——主路径）
- Mic 按钮（R3a/R3b）：移动端（`'ontouchstart' in window`）→ `segmentRefs.current[currentIndex]?.focus()`（便捷聚焦入口）；桌面 → `voice.startWebSpeech(t => updateSegmentAppend(currentIndex, t))`（Web Speech 兜底，`startWebSpeech` 仅依赖 onResult 回调，无 target 绑定）
- 每段 Mic 交互与段 textarea 并列渲染（段尾 mic 图标，复用现有 Mic 组件）

> ⚠️ 原 §2.3 示例（`voice.activate()` 绑定 `segmentRefs.current[i]`）与 hook 签名不兼容（HTMLInputElement vs HTMLTextAreaElement），**已按 C1 重写为方案 B**——实施时严禁恢复原写法。
