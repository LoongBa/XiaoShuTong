## 三、走查发现 G16 系统性缺陷

### 3.1 现象（走查实证）

点"确认解除"→ HTTP 400 `removeBuddy_Execute does not exist on type Mutation`。

### 3.2 根因（3 层，源码实证）

```
[L1 服务端 SG] IsMutationMethod 判定 Xxx_Execute 非 mutation → 全部 *_Execute 进 Query 根
              （schema.graphql removeBuddy L44 / createTask L121 均 Query 段；Mutation 仅 8 认证/AI 字段）
[L2 SDK 客户端] ServiceProxy.createUse() 前缀启发式：MUTATION_PREFIXES 含 remove/create → 判 mutation
              （service-proxy.js L3-11）→ 发 mutation { removeBuddy_Execute } → 400
[L3 SDK 最深] codegen 已生成正确 type:'query' 标记（ts-client.g.ts Query 常量），但 SDK 完全不消费
              （无 explicitQueries 接入，dist 全量扫零命中）→ 丢弃正确信号退回前缀启发式
```

### 3.3 影响面（全量扫描）

| 调用 | 前缀 | SDK 判定 | 服务端 | 结果 |
|---|---|---|---|---|
| removeBuddy_Execute（StudyBuddySection:200） | remove | mutation | Query | **400 实证** |
| createTask_Execute（create.tsx:167） | create | mutation | Query | **400 预期** |
| createStudySession_Execute（appStore:144） | create | mutation | Query | **400 预期（Oracle C1 补漏）** |
| createBank/createGroup/createParentRelation/createPkMatch | create | mutation | Query | 潜在（当前未调用） |
| 其余 ~40 处（accept/reject/list/get/markMastered） | 非前缀 | query | Query | ✅ 正常 |

### 10.5 转报框架组（ts-client SDK，待用户转发）

**问题**：`TkwfConfig.onUnauthorized` 文档 summary 称「未登录/**会话过期**时的回调」，但实现仅在 `Tkwf.User` 无本地 session（`GetUser()` 抛错）时触发；**服务端过期响应**（AUTH_REQUIRED）走 `host.handleError` → `onAuthRequired`——该回调 per-instance 且仅 `Tkwf.getHost()`（private）可设置，`Tkwf.configure` 无法注入 → 最终仅 `onGlobalError` 可兜底（SDK 文档亦自述「返回 401/403 时由 onGlobalError 兜底」，与 onUnauthorized 注释矛盾）。

**建议**：① 修正 `TkwfConfig.onUnauthorized` 文档措辞（仅本地无 session）；② 提供全局 `onAuthRequired` 注入通道（configure 级），或让 onUnauthorized 同时覆盖服务端 401 响应。

**应用侧现状**：XiaoShuTong 已在 `onGlobalError` 按 `AUTH_REQUIRED` 兜底跳登录（`main.tsx`），功能不阻塞；属 API/文档缺口非致命缺陷。
