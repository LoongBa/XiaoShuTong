### 2.2 改动（dashboard.tsx）

**入口**：已订阅态（isSubscribed）下，订阅 Dialog 旁新增「管理订阅」入口（如"查看完整报告"卡下方或订阅提示区），点击拉 `listSubscriptions_Execute` 展示当前孩子的订阅列表。

**展示**：`listSubscriptions_Execute` 无参返回全部孩子订阅 → 前端按 `selectedChild.studentUid` 过滤当前孩子 → 展示 plan/status/periodEndAt（多孩子场景各订阅行标注 studentNickname）。

**取消**：每行「取消订阅」按钮 → `cancelSubscription_Execute({request:{subscriptionUid}})` → 成功提示 + 重拉 dashboardReport 校正 isSubscribed/locked（对齐 handleStartTrial 的重拉范式）→ 失败映射 errorCode 文案（对齐既有错误码表模式）。

**取消后 UI 呈现（Oracle C3）**：Cancelled 周期内仍有权（isSubscribed 保持 true，dashboard.tsx L167 已含 Cancelled 判定）——取消成功后**「管理订阅」入口不消失**，该订阅行显示"已取消（权益至 {periodEndAt} 到期）"，取消按钮置灰/隐藏（不可重复取消）；periodEndAt 过期后 dashboardReport.subscription 变 Expired/null → isSubscribed 自动转 false → 入口消失。

**空态兜底（Oracle C4）**：listSubscriptions 返回 items 中无当前 selectedChild 的订阅（键一致：两者 StudentUid 均 = StudentId.ToString()）→ 显示"暂无订阅"空态而非空白。

**契约注意**：
- `listSubscriptions_Execute` 无 request 包装（args 为 Record<string, unknown>），与 cancel 的 `{request}` 包装不同——勿套同一模式
- `CancelSubscriptionResDto` 无 cancelled 字段——mock 对齐时移除

## 三、任务 T2：账户域昵称/班级富化（档 A+B，tkwf-service）

### 3.1 现状（探索实证）

**空串桩位置（5 Service，6 DTO）**：

| # | 文件 | 行号 | DTO 字段 |
|---|------|------|---------|
| 1 | `Services/Buddy/ListBuddiesService.cs` | L88-89 | BuddyListItemDto.Nickname / .AvatarUrl |
| 2 | `Services/Rank/GetRankingsService.cs` | L128-129 | RankingItemDto.Nickname / .AvatarUrl |
| 3 | `Services/Pk/GetPkResultService.cs` | L71 | PkPlayerResultDto.Nickname |
| 4 | `Services/Parent/ListChildrenService.cs` | L52-53 | ChildItemDto.Nickname / .ClassName |
| 5 | `Services/Parent/ListSubscriptionsService.cs` | L42 | SubscriptionItemDto.StudentNickname |

**实体事实**：
- **无 Users/UserInfo/StudentInfo 实体**（全 Domain 层）——XiaoShuTongUserInfo 仅 Id
- 唯一 Nickname 来源 = `GroupMembers.Nickname`（string? 可空，种子已填"小明/小明家长/小美/小刚"）
- **无任何实体有 AvatarUrl 字段** → 档 C（头像富化）需新增字段/外部账户域 → **本轮不做，降级 P1 提 ADR**
- Groups 有 Name（"七(3)班"）无 ClassName → ClassName 用 Groups.Name 填充（决策点 M1）

**已富化范式参照**：`ListPendingBuddyInvitesService.cs` L47-52（GroupMembers 一次 IN 查 Nickname，多群 GroupBy 取 First，null 兜底 `学生{userId}`）——照抄。

### 3.2 改动（档 A：5 Service 昵称富化 + 档 B：1 Service ClassName）

- 每个 Service 加：`GroupMembers` 一次 IN 查询（按 UserId）→ 字典映射 Nickname → null 兜底 `学生{userId}` → 赋值替代空串
- **Role 过滤（Oracle C1 阻塞级）**：GroupMembers 查询统一加 `x.Role == MemberRole.Student` 过滤——孩子/学生场景存在 Role 歧义（同 UserId 可同时是群 A Student + 群 B Parent），不过滤会取错 Nickname/ClassName。ListPendingBuddyInvitesService 范式不过滤是因为搭子邀请人必然是学生角色（业务约束），孩子场景无此隐式约束。
- `ListChildrenService.ClassName`：`ParentStudentRelations.StudentId` → `GroupMembers.UserId`（过滤 Role=Student）→ `GroupMembers.GroupId` → `Groups.Name`（决策点 M1：Groups.Name 语义等价班级名）
- `ListSubscriptionsService.StudentNickname`：同范式（经 StudentId 关联 GroupMembers.UserId，过滤 Role=Student）
- **AvatarUrl 字段保留空串**（档 C 降级，DTO 字段不动——契约字段存在，仅值恒空）

## 九、Oracle 评审闭环（附条件通过）

评审：Oracle1（2026-09-29）。结论：**附条件通过**。决策点/修正项逐项闭环：

| 项 | 类型 | 结论 | 落地 |
|----|------|------|------|
| M1 ClassName 来源（Groups.Name） | 决策点 | **采纳（附 C1）** | Groups.Name 语义等价班级名；关联键 StudentId=GroupMembers.UserId 类型/语义一致（long，全局用户 Id） |
| M2 N+1 范围（管理端 3 处） | 决策点 | **采纳（附 C2）** | 管理端热路径优先合理；GetOwnerDashboard 已防 N+1 实证 |
| **C1 Role 过滤（阻塞级）** | 修正项 | **采纳** | **5 个 Service 的 GroupMembers 查询统一加 `x.Role == MemberRole.Student` 过滤**——孩子/学生场景存在 Role 歧义（同 UserId 可同时是群 A Student + 群 B Parent），不过滤会取错 Nickname/ClassName |
| C2 码验重方式 | 修正项 | **采纳** | GenerateInviteCodesService 码为随机生成不可预 IN 查——修正为"**生成一批码后一次 IN 批量验重**，冲突重生成"（替代逐条 EntityGetAsync） |
| C3 取消后 UI 呈现 | 修正项 | **采纳** | Cancelled 周期内仍有权（isSubscribed 保持 true）——**入口不消失**，订阅行显示"已取消（权益至 periodEndAt 到期）"，取消按钮置灰/隐藏；periodEndAt 过期后自动转 false 入口消失 |

**风险表补充（C1）**：Role 过滤缺失 → 富化取错（孩子同是某群 Parent 成员时 Nickname/ClassName 取到家长记录）→ GroupMembers 查询加 Role=Student 过滤。
