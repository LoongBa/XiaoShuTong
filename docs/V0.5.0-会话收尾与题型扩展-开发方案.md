# 会话收尾与题型扩展 - 开发方案（V0.5.0）

## 一、本版目标

- 核心交付：
  1. **G-3 70/30 混合比出题（ADR-009 决策一）**：`GetNextQuestionService` 由"纯状态机排序"升级为"分池 + 按已答比例动态池选择"——复习池（到期复习/未掌握）+ 新题池按 7:3 混合出题：每次取题复用已答 attempts 按已答复习占比动态选池（占比 < `ReviewRatio=0.7` → 复习池取排序首，否则 → 新题池取 Id 序首），无状态、无需预设 target，天然交错比例趋近 7:3（学习-BR-04 后半段落地），`OrderByStatePriorityAsync` 池内排序保留（题库-BR-20 兼容）。
  2. **G-4 EndStudySession 会话收尾契约（ADR-009 决策二/三）**：Learning 域新建 `EndStudySessionService`（`[GenerateController][AuthorityFilter][Transactional]`）写入 `StudySessions.EndedAt/CorrectCount/TotalTimeMs`（现全库零写入方）；BR-05 幂等随 EndedAt 生效（已结束会话不再复用）；新增 `LearningErrorCodes.SessionEnded`；`GetSessionQuestionService` 补 EndedAt 校验联动。
  3. **G2 防爬剥字段（ADR-009 决策四）**：`GetNextQuestionService.JsonSafeParseContent`（仅判空）升级为 `StripAnswerFromContent`——按题型白名单保留展示字段（question/options），剔除 answer/keywords/correct_option 答案侧（题库-BR-19 真正落地，V0.4.0 前端 mock 纯字符串掩盖的缺口）。
  4. **R3/O 题型组件扩展（审核报告 §九 4）**：前端 `QuestionCard` 按题型分发（R1/R2/R3a/R3b 文本+语音、O1 radio、O2 checkbox、O3 对错双键、O5 input、R4 卡片展示），`QuestionInput` 分发 + `HintBubble` 抽出；`types/index.ts` 题型联合类型对齐注册表。
  5. **Mic 语音接线（审核报告 §九 5 + 规范 §6.1）**：`use-voice-input` hook——主路径 focus()+click() 唤起系统语音输入法 + 二次确认，兜底特性探测 Web Speech API，不支持禁用 + tooltip。
  6. **endStudy 前端接线 + content 解析适配**：getSessionQuestion 空结果 → endStudySession → 跳 result；中途退出 cleanup/beforeunload fire-and-forget；`parseQuestionContent()` 双兼容（mock 纯字符串 vs 真实 JSON），mock 同步 JSON 形态 content。

- 完成定义（DoD）：
  - 后端：全套件 `dotnet test` **基线不降**（当前记录 360/0/2，**实施前先跑一次 `dotnet test` 确认实际值，以实际值为准**）+ 新增混合比/EndStudy/防爬用例全绿。
  - 生成链路：`endStudySession_Execute` 出现在 `schema.graphql`（SG1/SG2）+ `ts-client.g.ts`（SG3），`ts-client.mock.g.ts` 同步。
  - 前端：`pnpm typecheck` 0 错误；mock 模式 R3a/O1/O2/O3 渲染 + Mic 唤起 + endStudy 触发可见。
  - G2：`getSessionQuestion` 响应 JSON 序列化断言不含 answer/keywords/correct_option。
  - 文档：变更记录追加 + ADR-009 转活跃（Oracle 评审闭环后）+ 审核报告产出入档。

### 后端（全部走 tkwf-service / tkwf-test skill，违反即失败）

#### T1：GetNextQuestionService 混合比改造（tkwf-service）

- **描述**：`src/XiaoShuTong.Domain/Services/Bank/GetNextQuestionService.cs` 在 BR-18 耗尽检查之后、排序取题之前（现 L76-83 之间）插入混合比逻辑。**池选择算法采用"按已答比例动态池选择"（无状态）**——Oracle 评审闭环：GetNextQuestionService 为无状态逐题取（每次调用独立计算，L83 `ordered.First()` 取首元素），原方案"窗口 [R×7,N×3] 循环交错"每次调用重新构建窗口取首元素 → 窗口首恒为复习池排序首 → 前 14 复习 + 后 6 新题 = 分块，与"非前 14+后 6"自相矛盾；改为每次取题按已答比例动态决策，**不需维护会话级状态、不需预设 target**：
  - **分池**：复用 `OrderByStatePriorityAsync` 内的 states 查询（L101-104 只查一次，不重复查询），构建 `stateMap` 后分两池——**复习池** = `stateMap` 存在且 `NextReviewAt <= now && State != Proficient`（BR-20 到期复习；含未掌握/模糊子集）；**新题池** = `!stateMap.ContainsKey(QuestionId)`（无任何记忆状态）。
  - **动态池选择（伪码要点，无状态）**：每次取题复用 L56-58 已查 `attempts` 计数算已答比例——
    ```
    reviewAnswered = attempts.Count(a => 该题属复习池)   // 已答复习题数
    answeredTotal  = attempts.Count                     // 已答总数
    reviewRatio    = answeredTotal == 0 ? 0 : reviewAnswered / answeredTotal
    if (reviewRatio < ReviewRatio)   → 复习池取（OrderByStatePriorityAsync 排序首）
    else                              → 新题池取（Id 序首）
    ```
    `ReviewRatio = 0.7` 常量（ADR-009 决策一"硬编码常量起步"，`private const double ReviewRatio = 0.7`）；已答序列天然交错、比例趋近 7:3（无连续 ≥4 同池题）。
  - **补齐**：目标池为空 → 另一池取首补齐（复习池空 → 新题池取首；新题池空 → 复习池取首）；**仅两池合计为 0 才返回空**（BR-18 语义保留，现 L77-78 提前空返回保留在分池前或补在分池后判两池合计，二者取一，语义等价）。
  - **返回**：动态选中的池排序首元素为 `next`，后续 `Content` 剥字段逻辑见 T2。
  - **BR-20 兼容**：池内排序 StatePriority 保持（**保留按池调用**：复习池走 StatePriority 状态机排序，新题池无状态按 Id 序，两池各排一次；到期复习→未掌握→新题在复习池内不变），混合比仅由跨池选择比例控制，两 BR 不冲突（ADR-009 决策一确认）。
- **涉及文件**：`src/XiaoShuTong.Domain/Services/Bank/GetNextQuestionService.cs`（手写 Service，L49-83 区间改造；`OrderByStatePriorityAsync` 签名保持或拆池内排序私有方法）。
- **skill 路由**：`tkwf-service` {Domain}=Bank, {Entity}=Questions。
- **验收**：见 §六 A1——混合比用例（比例/补齐/动态池选择）全绿 + BR-20 排序回归不破。

```
getSessionQuestion_Execute({sessionUid, bankId})
  → GetSessionQuestionService：BR-06 归属校验 + **EndedAt 校验（已结束 → SessionEnded）**
  → GetNextQuestionService（Callee）：
      BR-17 题库权限 → 已答题目排除 → 可用题目集 available
      BR-18 available 为空 → Success=true 空结果（会话结束信号，前端 T9 endStudy）
      [T1] 分池（复用 states 一次查询）：
          复习池 = stateMap 有记录 && NextReviewAt<=now && State!=Proficient
          新题池 = !stateMap.ContainsKey(qid)
      [T1] 动态池选择（无状态）：已答复习占比 < ReviewRatio(0.7) → 复习池；否则 → 新题池
           （复用 L56-58 attempts 计数；不需维护会话级状态、不需预设 target）
      [T1] 目标池空 → 另一池补齐；两池合计 0 → 空（BR-18）
      [T1] 两池各自 OrderByStatePriorityAsync 排序（复习池状态机序 / 新题池 Id 序）
      [T1] 取所选池排序首为 next；已答序列天然交错，复习:新题趋近 7:3（无连续 ≥4 同池）
      [T2] StripAnswerFromContent：题型白名单剥 answer/keywords/correct_option
  → 返回 GetNextQuestionResDto（复用，Content 为剥字段后 JSON）
```

**会话结束时序（T3 后端 + T9 前端）**

```
场景 A：题集耗尽（BR-18 空结果）
  task.tsx fetchNextQuestion 得 Success=true 无 questionId
    → endStudySession_Execute({sessionUid, endReason:'NaturalExhaust'})
        → EndStudySessionService：BR-39 校验 → 幂等（EndedAt.HasValue→回读）→ 聚合 → 写三字段
    → navigate /student/study/result（sessionResult 为准，endStudy Res 兜底）

场景 B：中途退出（返回 / beforeunload）
  cleanup + beforeunload → fire-and-forget endStudySession_Execute({endReason:'UserExit'})
    （不 await、不阻塞导航；BR-05 续做幂等 + 已答排除保证服务端恢复）
  → 下次进入同任务 createStudySession → BR-05 不再复用（EndedAt!=null）→ 新建会话
```

**R3/O 题型作答时序（T7/T8/T10）**

```
getSessionQuestion → GetNextQuestionResDto（Content=剥字段 JSON）
  → parseQuestionContent(content) 双兼容解析 → QuestionCard 按 type 分发
      R1/R2/R3a/R3b → 文本 + Mic（use-voice-input 唤起系统输入法 → 二次确认）→ userAnswer
      O1 → RadioGroup 单选 / O2 → Checkbox 多选 → userAnswer（选项标识串）
```

### 数据模型

**StudySessions 三字段写入映射（T3，现 L51-68 三字段全库零写入方）**

| 字段 | 类型 | 值来源 | 写入方 | BR |
|------|------|--------|--------|-----|
| EndedAt | DateTime? | `DateTime.UtcNow` | EndStudySessionService（本迭代首个写入方） | BR-05（幂等判定）/BR-39 |
| CorrectCount | int | `AggregateFromAttempts(attempts).CorrectCount`（= Count(Result==Correct)） | 同上 | BR-40 |
| TotalTimeMs | long? | `AggregateFromAttempts(attempts).TotalTimeMs`（= Sum(TimeCostMs ?? 0)） | 同上 | - |

> BR-05 幂等语义随 EndedAt 生效：CreateStudySessionService L56 `x.EndedAt == null` 复用条件（现 L52-60）在 EndStudy 写入后自然生效——已结束会话不再复用，用户完成一次任务后可开新会话（ADR-009 问题 2 闭环）。

**混合比题池划分表（T1）**

| 池 | 判定条件 | 池内排序 | 来源 |
|----|---------|---------|------|
| 复习池 | `stateMap.TryGetValue(qid)` 且 `NextReviewAt <= now` 且 `State != Proficient` | OrderByStatePriorityAsync（StatePriority：NotMastered 0 < Fuzzy 1 < Mastered 2 < Proficient 3） | 学习-BR-32 队列语义（跨模块读 MemoryStates） |
| 新题池 | `!stateMap.ContainsKey(qid)`（无任何记忆状态记录） | 按 `q.Id` 稳定序 | - |

- 动态池选择（无状态）：每次取题复用 L56-58 已查 `attempts` 计数——`已答复习占比 = 已答复习题数 / 已答总数`（已答 0 视为 0）；`已答复习占比 < ReviewRatio(0.7)` → 复习池取（StatePriority 排序首），否则 → 新题池取（Id 序首）；不需维护会话级状态、不需预设 target（Oracle 评审闭环：窗口交错在逐题取首模式下退化为分块）。
- 补齐：目标池为空 → 另一池取首补齐；两池合计 0 → BR-18 空结果。
- 天然交错：已答序列复习:新题趋近 7:3（无连续 ≥4 同池题）；`ReviewRatio = 0.7` 常量（ADR-009 决策一"硬编码常量起步"）。

**content 白名单字段表（T2）**

| 字段 | 展示/答案侧 | R1/R2/R3a/R3b | R4 | O1/O2/O3 | O5 | O4 |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| question | 展示 | ✅ | ✅ | ✅ | ✅ | ✅ |
| options | 展示 | - | - | ✅ | - | - |
| cardId | 展示（知识卡片关联） | ✅ | ✅ | ✅ | ✅ | ✅ |
| answer | 答案（R4 例外=卡片正文） | ❌ | ✅（展示载荷特例） | ❌ | ❌ | ❌ |
| keywords | 答案（判题关键词） | ❌ | - | ❌ | ❌ | ❌ |
| correct_option | 答案 | - | - | ❌ | - | - |
| pairs | 答案/展示混合 | - | - | - | - | ⏸ 后置定义 |

> 白名单实现于后端 `StripAnswerFromContent`（按 `next.QType.ToString()` 路由）；前端 `parseQuestionContent` 仅消费下发后的展示形态。
