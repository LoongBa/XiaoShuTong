# 错题本真实契约接线与标准答案展示 - 开发方案（V0.6.9）

## 一、背景与目标

### 1.1 背景

V0.6.8 闭环了三项后端配合项（taskId/studentId/Answer），其中 **2c WrongQuestionsDto.Answer 标准答案**已透出（内容权威源优先 + Keywords 重组兜底，`[DtoField(IsComputed=true)]`）。V0.6.7 审核报告 §四-② 登记："wrong.tsx 缺答案字段 → 本次只走查登记不改 UI 设计"——本迭代消费该字段。

**现状核查（explore + 代码实证）**：

1. **wrong.tsx 从未接任何真实数据源**：
   - 读 `store.wrongAnswers`（`WrongAnswer[]`，9 字段：id/questionId/knowledgePointId/title/wrongAnswer/correctAnswer/wrongCount/isMastered/createdAt）
   - `appStore.ts` 的 `wrongAnswers: []`（初始空）+ `setWrongAnswers`（整体替换）**全仓库 0 真实调用者** → 页面恒空态（与 V0.6.7 发现的"纯 mock 假象本质是未接数据源"同构）
   - `handleMarkMastered`/`handleMoveBack` 是**纯本地 store 假交互**——与后端 BR-23 自动流转**冲突**（见下）

2. **契约字段错配**：前端 `WrongAnswer` 类型字段（title/wrongAnswer/correctAnswer/knowledgePointId）与契约 `WrongQuestionsDto`（knowledgePoint/summary/answer/wrongCount/mastered/lastWrongAt/subject）**无一对得上**——mock 契约无 title/wrongAnswer/correctAnswer，只有 summary（错因摘要）+ V0.6.8 新增 answer（标准答案）

3. **已掌握流转是后端职责（BR-23）**：`SubmitAttemptService` L331-371 实证——Wrong/Partial 计入 WrongQuestions；**连续 2 次 Correct（跨会话）→ Mastered=true**。UI 设计文档 L261"连续答对 2 次转已掌握分组"即此。前端本地 toggle 会造成与后端状态漂移。

4. **mock 数据未同步 answer**：`mock/data.ts` getWrongQuestionsResDtos 主场景 3 条（2 未掌握 + 1 已掌握）无 answer 字段（V0.6.8 codegen 刷新了 ts-client.g.ts/ts-client.mock.g.ts，但手写 data.ts 未补）

5. **契约能力**（ts-client.g.ts 实证）：
   - `wrongQuestions_Execute(request?: { mastered, subject, pageIndex, pageSize })` → `{ success, errorCode, items: WrongQuestionsDto[], total }`
   - 支持 `Mastered` 布尔过滤 + Subject 过滤 + 分页——**双 tab 可直接用 mastered 参数分别查询**，无需前端二次过滤

### 1.2 目标

1. **真实接线**：wrong.tsx 接 `wrongQuestions_Execute`——未掌握 tab 查 `mastered:false`、已掌握 tab 查 `mastered:true`（或单查全量前端分组，见 §四 决策 ①）
2. **标准答案展示**：错题卡展示 `answer`（V0.6.8 2c 消费）——错题本属作答后复习场景，不违反防爬 BR-19（V0.6.8 已论证）
3. **假交互移除**：删 `handleMarkMastered`/`handleMoveBack` 本地 toggle——已掌握流转归后端 BR-23 自动（前端不伪造）；"移回错题本"无后端写操作 → 登记配合项
4. **类型对齐**：`WrongAnswer` 类型废弃或改造为契约直用（决策 ②）——消除 title/wrongAnswer/correctAnswer 死字段
5. **mock 补齐**：`data.ts` getWrongQuestionsResDtos 补 `answer` 字段（对齐 V0.6.8 契约），空场景保留

### 1.3 范围决策（不做什么）

| 不做 | 理由 | 归属 |
|------|------|------|
| "移回错题本"后端写服务（MarkMastered 切换） | 无后端对应操作，需新增 Service + 测试，超前端接线范畴 | 登记配合项 |
| 错题本分页 UI（无限滚动/加载更多） | 当前题量小（<100 条），全量拉取足够；UI 设计无分页交互 | 后续按需 |
| 重练入口改造（当前 navigate 到 task 页） | 重练需错题定向出题链路，后端 GetNextQuestion 无"错题专练"模式 | 登记配合项 |
| subject 学科过滤 tab | 契约支持但 UI 设计无此交互；本次双 tab 已覆盖 | 不做 |

## 四、技术方案

### 4.1 页面结构（wrong.tsx 改造后）

```
WrongAnswersPage
├── 顶部导航（返回首页）
├── Tab 切换（待复习 N / 已掌握 N）——契约 mastered 参数分查
├── 加载态（Loader2 居中）/ 错误态（errorCode 展示 + 重试）
├── 未掌握 tab（mastered:false）
│   └── 错题卡：
│       ├── knowledgePoint（知识点标题）
│       ├── summary（错因摘要，绿底"标准答案"位改：错因灰底 + answer 绿底）
│       ├── wrongCount + lastWrongAt（错 N 次 · 日期）
│       └── 重练按钮（navigate /student/study/task，登记配合项）
├── 已掌握 tab（mastered:true）
│   └── 已掌握卡（opacity-70 + 绿勾，无操作按钮——移回登记配合项）
├── 复习建议提示卡（保留）
└── BottomNav
```

**展示字段映射**（契约直用，无本地类型转换；Oracle C1：删除"你的答案"槽位概念——契约无用户作答字段、UI 设计 L261 仅"知识点/错因"，对齐为三信息位）：

| 页面位 | 契约字段 | 说明 |
|--------|---------|------|
| 标题 | `knowledgePoint` | 知识点（如"乘法分配律"） |
| 错因位（灰底，标签"错因"） | `summary` | 错因摘要（契约原义） |
| 标准答案位（绿底，标签"正确答案"） | `answer` | V0.6.8 标准答案（**本次核心消费**） |
| 次数 | `wrongCount` | 错 N 次 |
| 日期 | `lastWrongAt` | 最近错误时间（slice 10） |
| 分组 | `mastered` | 后端 BR-23 自动流转，前端只读 |

> 页面空态文案对齐 UI 设计 L262「没有错题，记得很牢！」正面空态（Oracle C5）——未掌握空态与已掌握空态均按设计原文/三步式模板。

### 4.2 查询策略（决策 ①）

双 tab **分别查询**（mastered:false / mastered:true），非前端过滤：
- 优点：与契约能力对齐、已掌握大列表不拖慢未掌握渲染、计数天然准确（响应 total）
- 实现：`loadWrong(mastered: boolean)` 共用函数，tab 切换触发（`activeTab` 依赖）；**React 18 快速切 tab 仍有竞态**（旧请求晚返回覆盖新），用 cancelled flag 防旧请求覆盖（Oracle C4 表述修正）
- **计数策略（Oracle M2，选方案 A）**：进入页面两 tab 各查一次拿 `total` 用于"待复习 N / 已掌握 N"计数显示，只渲染当前 tab items（错题量 <100，预算 2 次轻量查询可接受）
- 切 tab 时清错误态重新加载（Oracle C5 补充）

### 4.3 类型对齐（决策 ②）

**契约直用**：wrong.tsx 不再依赖 `store.wrongAnswers`/`WrongAnswer` 类型，直接消费 `WrongQuestionsDto`。
- `WrongAnswer` 接口：全仓库仅 wrong.tsx 使用 → 从 types/index.ts 删除（grep 确认 0 其他引用）
- `store.wrongAnswers`/`setWrongAnswers`：0 真实写入者 → 从 appStore.ts 删除（state 项 + setter + persist partialize 白名单 + useAppStore 解构）
- 学习数据（LearningStats）不涉及本次

### 4.4 假交互移除

- 删 `handleMarkMastered`（本地 set isMastered=true）——后端 BR-23 自动，前端操作会漂移
- 删 `handleMoveBack`（本地 set isMastered=false）——无后端写操作支撑
- 已掌握 tab 卡不显示操作按钮；"移回错题本"交互登记配合项（需后端 MarkMastered Service）
- `handlePractice`（重练）保留：navigate 到 task 页；重练定向出题登记配合项

### 4.5 mock 补齐

`data.ts` getWrongQuestionsResDtos 3 条补 `answer`：
- wq-001 乘法分配律 → `answer: "a(b+c)=ab+ac"`
- wq-002 分数除法 → `answer: "除以一个数等于乘它的倒数"`
- wq-003 成语运用 → `answer: "望文生义，指不懂某一词句的正确意义，只从字面上去附会"`

（对齐 V0.6.8 契约：ts-client.g.ts selection 已含 answer（L161 实证）；**ts-client.mock.g.ts WrongQuestionsDtoSchema 已确认含 `answer: { kind: "string" }`（L1046，required）**——数据补齐系修复潜在 mock 校验/typecheck 失败，非可选优化（Oracle C3）

> Oracle M2 决策：双 tab 计数用方案 A——两 tab 各查一次拿 total，只渲染当前 tab items。
> Oracle 评审结论：**附条件通过**，C1/C3/C4/C5 已闭环（见上），M1（展示槽位语义）已落实删除"你的答案"槽位。
