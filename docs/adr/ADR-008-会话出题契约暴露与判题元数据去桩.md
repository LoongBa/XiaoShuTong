# ADR-008 会话出题契约暴露与判题元数据去桩

## 状态

活跃（2026-09-24 V0.4.0 开发方案 Oracle 评审闭环后转活跃）

## 目的与目标

**目标**：让学生端作答流（WebH5 task.tsx）在真实后端端到端跑通——会话创建后能逐题取题、判题不因题目元数据缺失而失败。**达成状态**：① 前端获得"取下一题"的 RPC 契约（`getNextQuestion_Execute`）；② 判题/提示/结果/错题/聚合五个消费点从真实题库数据源读取题目元数据，而非静态注册表桩。3 句话内：本 ADR 解决"取题契约缺失"与"判题数据源是测试桩"两个端到端阻塞点，使 V0.4.0 迭代的前端接线可落地。

## 问题

**问题现象**：WebH5 `task.tsx` 目前用 `MOCK_QUESTIONS` 常量 + 本地 `includes()` 判题，`useAttemptFlow` hook 已建但零调用。要接真实后端时撞上两个硬阻塞：

1. **取题契约不存在（G-1）**：`GetNextQuestionService`（`src/XiaoShuTong.Domain/Services/Bank/GetNextQuestionService.cs`）实现了完整出题逻辑（BR-17 题库权限 / BR-18 题集耗尽空结果 / BR-19 防爬不含答案 / BR-20 状态机排序），但类声明为 `internal class`（L17），**无 `[GenerateController]`** → 不出现在 `.TKWF/Domain_Api.md`、`schema.graphql`、`ts-client.g.ts`，前端没有任何"取下一题"通道。该服务设计注释明示"Callee 被学习域调用"（L10），但全库 **0 调用方**——设计意图从未接线。
2. **判题元数据是测试桩（G-2）**：`LearningQuestionRegistry`（`src/XiaoShuTong.Domain/Tools/LearningQuestionRegistry.cs`）是全局静态字典 + 测试 `Register()` 注入，被 **5 个服务**消费：`SubmitAttemptService`（L67，判题需要 AnswerKeywords/Hint/QType/BankId/Subject）、`GetHintService`（L35，Hint）、`GetSessionResultService`（L70，KnowledgePoint）、`GetWrongQuestionsService`（L74，KnowledgePoint）、`KnowledgeMasteryAggregationJob`（L53-54，Subject/KnowledgePoint）。而真实数据已存在于 `Questions` 表（`Keywords`=KeywordGroup[] JSON、`KnowledgePoints`、`QType`）与 `Banks` 表（`Subject`）——**真实题目 ID 在注册表中必然缺失** → `submitAttempt` 必报 `QUESTION_NOT_IN_BANK`，端到端必失败。

**触发场景**：task.tsx 从 mock 切换到真实 `createStudySession → getNextQuestion → submitAttempt` 链路的第一天。

**现有方案不足**：注册表桩是切片验证期的临时手段（注释明示"题库域/判题服务在切片 03 实施，本切片以注册表代替"），切片 03 尚未排期，而 V0.4.0 的端到端接线不能等——需要在本迭代去桩。

## 使用场景

**适用场景**：
- S1：学生端新学会话——`createStudySession_Execute` 产出 sessionUid → 逐题 `getNextQuestion_Execute` 取题 → `submitAttempt_Execute` 判题（本迭代）
- S2：复习会话——复习队列进入，复用同一取题通道按 BR-20 状态机排序（到期复习优先）
- S3：判题/提示/结果/错题/聚合五消费点读取真实题目元数据（本迭代去桩覆盖）
- S4：无后端开发——mock 模式经 `tkwf-tsclient-mock` 提供 `getNextQuestionResDtos` 数据（前端接线期）

**不适用边界**：
- ✗ 不解决 70/30 新题/复习混合比（BR-04）——本 ADR 只暴露既有 BR-20 状态机排序能力，混合比属 G-3 延期项
- ✗ 不解决"结束会话"契约（G-4，EndedAt 写入）——属另一决策，不在本 ADR 范围
- ✗ 不改变判题契约本体（`SubmitAttemptResDto` 5 字段已定稿，仅接线消费）
- ✗ 题库导入/预处理的 Keywords 生成（Bank 域既有职责，不动）

## 决策

### 决策一：G-1 取题契约——Learning 域薄包装对外暴露，Bank 域 Callee 保持 internal

**选定：B 方案（Learning 域新增包装 Service）**

- `Bank/GetNextQuestionService` **保持 internal Callee 不动**（设计意图正确：取题是题库域的防爬读操作，不直接对外）
- 新建 `Learning/GetSessionQuestionService`：`[GenerateController][AuthorityFilter<XiaoShuTongUserInfo>][Transactional]`，内部 `User.Use<GetNextQuestionService>().ExecuteAsync(...)` 转发
- 请求契约带会话上下文（SessionUid/BankId），响应复用 `GetNextQuestionResDto`（Success/ErrorCode/QuestionId/Type/Content/KnowledgePoint/KnowledgeCardId）
- 域归属：会话取题属学习域职责，对外 RPC 入口归 Learning 域（与 CreateStudySession/SubmitAttempt 同域），Bank 域保持纯 Callee

**放弃的方案**：
- **A 方案（Bank 域直接加 `[GenerateController]`）**：最小改动但违背服务设计注释的"Callee 被学习域调用"意图；Bank 域对外 RPC 面混入学习会话语义，域边界污染；且 AuthorityFilter 属学习域用户体系。
- **C 方案（会话创建时预装载题集）**：一次下发整批题目，违背 BR-19 防爬 DRM（背一题取一题），直接否决。

### 决策二：G-2 元数据去桩——`Questions`/`Banks` 真实读取 + Hint 落库

**选定：A 方案（真实数据源替换静态桩，注册表降级为测试专用）**

- 新增只读封装（建议 `Tools/QuestionMetaProvider` 或直接在各服务 `User.Use<QuestionsDataService>()` + `BanksDataService`）：
  - `AnswerKeywords` ← `Questions.Keywords`（KeywordGroup[] JSON，判题关键词服务端专用）
  - `KnowledgePoint` ← `Questions.KnowledgePoints.FirstOrDefault()`
  - `QType` ← `Questions.QType.ToString()`
  - `Subject` ← 经 `BankId` join `Banks.Subject`
  - `BankId` ← `Questions.BankId`
- **Hint（背景钩子）落库**：`Questions` 表无 Hint 列（DOMAIN_MAP L329-346 无此字段），题库四件套的"背景钩子"存在于 bank.v1.json。去桩需**新增 `Questions.Hint` 列**（可空 string，题库导入时从背景钩子写入；存量数据先空 → 判题 Hint 空串不致命，引导分支给出通用鼓励语）——涉及 Entity 变更，走 `tkwf-entity` skill + xCodeGen 重生成
- `LearningQuestionRegistry` **保留但不被业务服务消费**：降级为测试专用注册设施（测试仍可 Register 注入自定义元数据），5 个业务消费点全部切换真实读取
- 兼容策略：`LearningQuestionRegistry.Exists()` 语义由"静态字典存在"改为"真实题库存在性查询"，或测试直接改用真实 InMemory 题库数据（tkwf-test InMemory DAC 已支持）——实施时二选一，倾向后者（测试与生产同源）

**放弃的方案**：
- **B 方案（注册表改为懒加载门面，接口不变）**：静态类无法注入 DataService，改造等于重写且保留错误抽象层级；不如直接读真实表。
- **C 方案（导入时批量预填注册表）**：数据不同步风险高（导入/复核后需重刷），静态字典无法承载多租户隔离，否决。

## 后果

- **正面**：① 前端获得完整端到端链路（createSession → getNextQuestion → submitAttempt → sessionResult）；② 判题/提示/结果/错题/聚合五处与真实题库同源，测试与生产数据一致；③ Bank 域 Callee 设计意图保留，域边界清晰；④ 判题契约本体不动，上一迭代 353/0/2 基线不受破坏。
- **负面/风险**：① `Questions.Hint` 列新增触发 Entity + xCodeGen + 契约重建（改动面中等）；② 存量题库无 Hint → 引导分支线索为空，需前端兜底文案；③ `GetSessionQuestionService` 薄包装增加一层转发；④ 5 个消费点改造 + 既有测试断言可能引用注册表桩（需同步测试数据源）——风险可控，回归由全套件验证。
- **后续待办**：G-3（70/30 混合比）、G-4（EndStudySession）另立决策；mock `getNextQuestionResDtos` 补表（走 tkwf-tsclient-mock）。
