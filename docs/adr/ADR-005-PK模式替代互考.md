# ADR-005 PK 模式替代互考模式（含异步降级）

## 状态

活跃

## 上下文

- 问题描述：V2 阶段 2 规划"群内分享题库、好友互考"（互考模式：A 同学出题 B 作答）。评估与设计阶段发现：互考依赖双方题库权限、出题质量不可控、操作链路复杂。同时趣味学习场景需"同学比一比/挑战闯关"（用户明确需求）。
- 约束条件：V3 非分数排名原则（不展示分数排名，仅坚持天数+★增长数）；微信 H5 实时性受限（SignalR 在 X5 内核可能不可用，30s 轮询降级）；AI 点评需"有趣且介绍知识"。
- 相关需求：V3 三阶段2 群组社交；用户需求"同学互考/比一比挑战闯关"
- 关联 ADR：ADR-002（场景引擎承载）

## 选项

### 选项 A：保留互考模式（A 出题 B 答）

- 描述：同学 A 从自己题库选题，生成考卷给 B
- 优点：私域题库流转，社交感强
- 缺点：依赖双方题库权限（V3 私域冲突）；出题质量不可控；操作链路复杂（Oracle 评审 D3 指出防作弊/防泄露缺失）

### 选项 B：PK 模式（系统出题，双方作答，AI 点评）（选定）

- 描述：系统从指定题库按知识点/难度统一出题，连续 10 题（可配 5/10/20），双方同题同序作答（每题 30s），总分高者胜→同分比用时→平局；结束后 AI 评分 + 趣味点评（亮点/薄弱点/错题知识彩蛋/胜负祝词）
- 优点：系统出题公平可控；胜负规则清晰（同分比用时）；AI 点评"有趣+介绍知识"贴合用户需求；PK 数据 state_coupling=isolated 不污染记忆状态
- 缺点：实时同步依赖 WebSocket（H5 可能不可用）；需要独立趣味点评 Prompt

### 选项 C：PK 模式 + 异步回合制备选（最终选定）

- 描述：在 B 基础上，微信 H5 WebSocket 不可用时降级异步回合制——同一组题、各自独立计时、提交后合并计分，胜负规则不变
- 优点：Oracle 评审 D1（高严重度）指出 H5 30s 轮询撑不起同步 PK；异步降级保证功能可用；同步/异步对用户透明
- 缺点：异步模式缺少实时对抗感

## 决策

选定：选项 C（PK 模式 + 异步回合制备选）

理由：Oracle 评审（D1，高严重度）确认 PK 实时性与 V3 技术基线（H5 30s 轮询）冲突；系统出题保证公平与私域合规；异步降级在 P1a 技术 PoC 验证 WS 可行性后决定默认模式；AI 点评与 V3"非分数"精神一致（PK 分不进全局排名，仅单局竞技）。

## 后果

- 正面影响：趣味学习场景落地；系统出题公平；AI 点评传播知识；H5 兼容有兜底
- 负面影响 / 风险：同步模式实时性依赖 WS；AI 点评成本（每次 PK 一次 LLM 调用，计入 D04 成本模型）
- 后续待办：P1a PK 技术 PoC（WS 可行性）；D02 pk_matches/pk_players/pk_attempts 落地；趣味点评-Prompt 已创建（v1.0）
