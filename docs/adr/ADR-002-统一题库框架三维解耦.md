# ADR-002 统一题库框架：三维解耦（学科×题型×学习目的）

## 状态

活跃

## 上下文

- 问题描述：语文古诗文题库已完整落地（435 原始题 + 1278 训练题 + 背景钩子 + Prompt 库），需扩展英语/历史/地理/生物/化学多学科，并支持背记/检验/趣味（PK）多学习目的。若按学科各自实现，将产生大量重复逻辑。
- 约束条件：现有语文资产零废弃迁移；新增学科/题型/场景不改变框架代码；判题容错度、卡片模板按学科差异。
- 相关需求：V3 功能规划（三步走）；D01 目标
- 关联 ADR：ADR-001（技术栈基础）

## 选项

### 选项 A：按学科独立实现

- 描述：每学科一套题库/判题/状态机
- 优点：无抽象成本，各学科可自由定制
- 缺点：重复代码爆炸；题型判题逻辑无法复用；扩展成本线性增长

### 选项 B：统一 JSON + 多字段大表

- 描述：一张题表塞所有学科字段
- 优点：表结构简单
- 缺点：字段冗余严重；题型契约无法约束；判题路由无法按题型分派

### 选项 C：注册表驱动三维解耦（选定）

- 描述：学科注册表（容错度/卡片模板/Prompt 覆盖）× 题型注册表（Schema/判题策略/Prompt）× 场景引擎（背记/检验/PK），五层架构（L5 场景→L1 资源）正交组合
- 优点：新增学科=注册表加一行；题型可跨学科复用（R1 补全=语文上句接下句/英语英译中/历史事件年代）；Oracle 评审 7.5/10 认可骨架
- 缺点：抽象层初始设计成本；需对齐补丁（V1.2 已修 5 处）

## 决策

选定：选项 C（注册表驱动三维解耦）

理由：学科/题型/学习目的是正交维度，组合即查表零新增代码；语文作为首个完整适配器验证了抽象可行性；五层架构（L5 场景/L4 调度/L3 判题/L2 题型契约/L1 资源）单向依赖清晰。

## 后果

- 正面影响：多学科扩展成本趋近于零；题型逻辑跨学科复用；判题/Prompt/状态机统一
- 负面影响 / 风险：抽象层复杂度；语文"古诗文默写"特性（S1-S4/7维作者卡）已深度耦合适配器，英语/历史语义不同需子型化演进（R3a/R3b 已先行）
- 后续待办：P1 .txt→JSON 解析器；P3 英语适配器（评估 R1 翻译子型）
