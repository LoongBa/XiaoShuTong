# ADR-009 会话收尾契约与 70/30 混合比出题

## 状态

活跃（2026-09-24 V0.5.0 开发方案 Oracle 评审闭环后转活跃）

## 目的与目标

**目标**：闭环学习域两个已登记的需求缺口——① 学习-BR-04 后半段"混合比 30% 新题 + 70% 复习"（G-3）；② 会话收尾字段写入（`StudySessions.EndedAt/CorrectCount/TotalTimeMs`，G-4）+ 防爬契约修复（BR-19 content 剥答案，G2）。**达成状态**：取题服务按 30/70 混合比出题（复习/新题交错，BR-20 状态机排序保留）；新增 `endStudySession` 契约写入会话收尾三字段，前端题集耗尽/主动退出时调用，BR-05 幂等随 EndedAt 生效；取题响应 content 严格剥离答案与关键词（BR-19 真正落地）。3 句话内：本 ADR 定"混合比算法 + 会话收尾契约 + 防爬剥字段"三个决策，使 V0.5.0 迭代闭环 V0.4.0 审核报告 §九 2/3 与遗留缺口。

## 问题

**问题现象**：
1. **G-3 混合比未实现**：`GetNextQuestionService.OrderByStatePriorityAsync`（L97-113）当前为"到期复习 → 未掌握 → 新题"纯状态机排序——有到期复习就全出复习，新题可能被无限挤压到队尾，学生长期见不到新题；学习-BR-04（Business.md L71）明确要求"混合比 30% 新题 + 70% 复习"但从未实施（V0.4.0 方案 L41 登记延期）。
2. **G-4 会话收尾无契约**：`StudySessions` 实体 `EndedAt/CorrectCount/TotalTimeMs` 三字段存在（L51-68）但**全库零写入方**（Grep 实证）→ BR-05 幂等"同任务 EndedAt==null 复用"**永远命中**（同一任务永远复用同一会话，用户完成一次任务后无法开新会话）；会话无结束信号，历史会话无法审计；`GetSessionQuestionService` 的 EndedAt==null 校验因无写入方而 moot（V0.4.0 注释登记的 G-4 联动项）。
3. **G2 防爬未真正落地**：`GetNextQuestionService.JsonSafeParseContent`（L126）**只判空不剥字段**——`answer`/`keywords`/`correct_option` 原样下发前端，违反题库-BR-19"响应不含答案与关键词（防爬 DRM 核心）"。V0.4.0 前端 mock 用纯字符串 content 掩盖了此缺口，真实后端联调必现。

**触发场景**：学生端真实后端端到端联调第一天（V0.4.0 审核报告 §八 #8 优先建议）；用户完成一次任务后再开新会话；O 系列题目前端渲染时（若 content 含 correct_option 则答案泄漏）。

**现有方案不足**：混合比无实现（纯状态机排序）；会话结束无契约（EndedAt 无写入方）；防爬是注释声称、代码未兑现（JsonSafeParseContent 只判空）。

## 使用场景

**适用场景**：
- S1：新学会话出题——`getSessionQuestion` 每次返回时按 70/30 在"到期复习/未掌握/新题"间交错（每 7 题复习穿插 3 题新题或等价加权）
- S2：复习会话出题——复习池充足时全复习（混合比语义允许复习占比 100%，BR-20 到期优先仍成立）
- S3：会话结束——题集耗尽（BR-18 空结果）时前端调 `endStudySession` 写 EndedAt/CorrectCount/TotalTimeMs；用户中途退出同样调用
- S4：续做/再开——已结束会话再 createStudySession → BR-05 不再复用（EndedAt!=null），新建会话；进行中会话（EndedAt==null）仍复用
- S5：防爬——`getSessionQuestion` 响应 content 仅含展示字段（question/options 等），不含 answer/keywords/correct_option

**不适用边界**：
- ✗ 不解决 TaskAssignments.Progress 推进（BR-24 归 SubmitAttempt 职责，V0.6.0+ 迭代项，ADR-009 明确不联动）
- ✗ 不引入会话超时定时 Job（触发时机选"前端主动 + 题集耗尽兜底"，Job 兜底 V0.5.0 不做，后续评估）
- ✗ 不解决 O4 连线组件 / O3 swipe 手势（前端范围裁剪，O4 因题库仅 4 题砍到后置，记开发方案）
- ✗ 不改变判题契约本体（SubmitAttemptResDto 5 字段已定稿，仅消费）

## 决策

### 决策一：G-3 混合比——分池抽比 + 交错，常量起步

- **题池划分**（在 `OrderByStatePriorityAsync` 之前）：
  - **复习池**：`MemoryStates` 存在且 `NextReviewAt <= now && State != Proficient`（BR-20 到期复习；含未掌握/模糊子集，池内 StatePriority 排序保证未掌握优先）
  - **新题池**：`!stateMap.ContainsKey(QuestionId)`（无任何记忆状态记录）
  - 不做第三池细分（未掌握/模糊在复习池内经 StatePriority 天然排序）
- **抽比**：`reviewTarget = (int)Math.Round(QuestionCount * 0.7)`；`newTarget = QuestionCount - reviewTarget`（默认 QuestionCount=20 → 14 复习 + 6 新题）
- **补齐规则**：复习池不足 → 新题补差额；新题池不足 → 复习补差额；**仅两池合计为 0 才返回空**（BR-18 语义保留）
- **交错策略**：非"前 14 复习 + 后 6 新题"，采用**窗口交错**——按复习:新题 = 7:3 加权（如窗口 [R,R,R,R,R,R,R,N,N,N] 循环，或按比例随机交错），学习体验连续、避免新题扎堆
- **配置化**：V0.5.0 **硬编码常量**（`ReviewRatio = 0.7` 建议置于 GetNextQuestionService `private const`），无运营配置面板需求；后续如需可切 Config/会话入参（记后续待办）
- **BR-20 兼容**：题库-BR-20"到期复习优先"语义仍成立（池内排序 StatePriority 保持）；学习-BR-04 混合比补齐；两 BR 不冲突

### 决策二：G-4 EndStudySession 契约——新 Service + 幂等 + 公共聚合器

- **新 Service**：`Learning/EndStudySessionService`（`[GenerateController][AuthorityFilter<XiaoShuTongUserInfo>][Transactional]`，internal class，tkwf-service 路由）
  - `ExecuteAsync(EndStudySessionReqDto, ct)` → `EndStudySessionResDto`
  - Req（同文件内联）：`SessionUid: string`（必填）+ `EndReason: string?`（可选枚举 NaturalExhaust/UserExit/Timeout，语义标记）
  - Res：`Success/ErrorCode/SessionUid/EndedAt/CorrectCount/TotalTimeMs`（写回值回显，前端结果页兜底）
- **幂等**：`if (session.EndedAt.HasValue) return Success + 当前值`（不重复聚合写，避免覆盖；前端重复调用友好）
- **聚合口径复用**：从 `GetSessionResultService` 抽**私有静态聚合器** `AggregateFromAttempts(attempts)`（CorrectCount = `Count(a => a.Result == JudgmentResult.Correct)`；TotalTimeMs = `Sum(a => a.TimeCostMs ?? 0)`；NewStarCount/BlockedPoints 亦归位），GetSessionResult 与 EndStudySession 共同调用，保证口径一致
- **写入**：`EndedAt = DateTime.UtcNow; CorrectCount/TotalTimeMs = 聚合值; SessionsDs.EntityUpdateAsync`——**仅写 StudySessions，不联动 TaskAssignments**（BR-24 归 SubmitAttempt，V0.6.0+）
- **错误码**：新增 `LearningErrorCodes.SessionEnded = "SESSION_ENDED"`（3002）
- **联动补全**：`GetSessionQuestionService` 增加 EndedAt 校验——`session.EndedAt.HasValue → Fail(SessionEnded)`（V0.4.0 注释登记的 G-4 联动项）

### 决策三：触发时机——前端主动 + 题集耗尽兜底（无 Job）

- **主触发（A）**：前端调 `endStudySession`——覆盖三种场景：题集耗尽（BR-18 空结果后）、用户中途退出（返回/离开）、结果页跳转前。UI 设计文档-v2 交互时序 7"中途退出进度增量已保存"语义直接对应
- **兜底（B）**：题集耗尽时空结果时前端必须先 endStudy 再跳结果页；若前端漏调，进行中会话仍可被 BR-05 复用（不阻塞），统计延迟到下次调用
- **不实施（C）**：定时 Job 超时扫描（V0.5.0 不引入，避免复杂度；后续评估 24h 超时 Job）

### 决策四：G2 防爬修复——content 剥字段（后端领域层）

- `GetNextQuestionService` 的 content 下发改为**结构化剥离**：仅保留展示字段（如 question/options/O 系列选项），**剔除 answer/keywords/correct_option/pairs 的答案侧字段**（BR-19 真正落地）
- 实现：`JsonSafeParseContent` 升级为 `StripAnswerFromContent`——反序列化后按题型白名单保留展示字段，重新序列化下发
- **归属**：后端 `tkwf-service` 任务（非前端方案内绕过）；前端 mock 同步改 JSON 形态 content 对齐真实契约（G1）
- O 系列 options 保留下发（展示必需），correct_option 剔除（答案）

### 决策五（范围裁剪，记方案非 ADR 决策项）

- **O4 连线 / O3 swipe** 后置：O4 需手写连线组件且真实题库仅 4 题，V0.5.0 不做；O3 用"对/错"双键（`button` 变体）替代 swipe 手势
- **Mic 语音**：已有规范 §6.1 决策（强制系统语音输入法、禁用 MediaRecorder ASR），**不需要新 ADR**——前端实现主路径（唤起系统输入法）+ 特性探测兜底 Web Speech API + 不支持降级禁用

## 备选方案

- **G-3 前置式**（前 70% 复习 + 后 30% 新题）：实现简单但新题扎堆在会话尾部，学习体验差 → 弃，选交错
- **G-3 随机概率抽比**（每次 70% 概率复习）：简单但无法保证窗口内比例稳定（可能连续 10 题新题）→ 弃，选窗口交错
- **G-4 无新 Service，GetSessionResult 兼写**：读服务带写副作用，职责混杂 → 弃，独立 EndStudySessionService
- **G-4 定时 Job 兜底**：引入复杂度 + 延迟关闭影响统计 → 弃（V0.5.0），前端主动为主
- **G2 前端剥字段**：前端不消费 answer 字段即可——但答案已下发客户端即泄漏（可被爬虫/抓包），防爬必须服务端剥 → 弃前端方案

## 后果

- **正面**：① 学习-BR-04 混合比需求闭环；② 会话生命周期完整（创建→作答→结束→再开），BR-05 幂等语义真正生效；③ 防爬 DRM 真正落地（BR-19）；④ GetSessionResult 与 EndStudy 聚合口径一致；⑤ 触发时机明确，前端契约清晰。
- **负面/风险**：① 混合比改造影响 GetNextQuestionService 核心出题逻辑（回归面中等，测试覆盖 BR-04/BR-20）；② EndStudySession 新契约 + 错误码 3002 需前端同步接线；③ 既有测试（GetNextQuestion 排序 / CreateStudySession 幂等）断言可能需更新（幂等语义随 EndedAt 生效）；④ G2 剥字段后前端 content 渲染需适配 JSON 形态（parseQuestionContent）；⑤ 存量进行中会话无 EndedAt（历史数据）——幂等语义对存量会话兼容（EndedAt==null 仍复用，可接受）。
- **后续待办**：BR-24 TaskAssignments.Progress 联动（V0.6.0+）；会话超时 Job（后续评估）；混合比 Config 化（后续）；O4 连线组件（题库成规模后）。
