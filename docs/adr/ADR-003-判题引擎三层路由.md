# ADR-003 判题引擎：三层路由 + 阈值对齐三元判题

## 状态

活跃

## 上下文

- 问题描述：V2 原设计"每次答题调大模型"成本不可控（V3 估算 100-300 元/月实际偏低）。需在成本、延迟、准确率间平衡，且须保留 V3 判题三元结果（correct/partial/wrong）。
- 约束条件：V3 判题契约 `result/confidence/matched_keywords/missing_keywords/hint`；AI 判题成本模型（本地关键词须拦截 60-70% 请求）；单次判题延迟 P95 ≤3s。
- 相关需求：V3 四（三）2 AI 导师判题逻辑
- 关联 ADR：ADR-002（框架层承载）

## 选项

### 选项 A：全部调 LLM

- 描述：每次答题都走大模型
- 优点：实现简单，判题准
- 缺点：成本失控（Oracle 评审指出：跳过 partial 会吞并三元结果）；延迟高

### 选项 B：本地关键词全判 + LLM 兜底（阈值未对齐）

- 描述：关键词 ≥80% 直接判 correct，<80% 走 LLM
- 优点：拦截率高，成本低
- 缺点：**≥80% 直接判 correct 跳过 partial**——漏核心关键词但达 80% 时误判 correct，违反 V3 三元契约（Oracle 评审 C1，高严重度）

### 选项 C：三层路由 + 阈值对齐三元（选定）

- 描述：rule（客观题比对）→ keyword（≥85% correct / 60-85% partial / <60% LLM）→ LLM（超时 3s 降级本地规则引擎）
- 优点：保留 partial 独立结果；本地拦截 65% 请求控成本；降级链路完整；阈值与 V3 置信度（≥0.85/0.5-0.85/<0.5）对齐
- 缺点：阈值需 500 题测试集校准（V3 决策 4）；keyword 需同义词组+权重结构表达语义容错

## 决策

选定：选项 C（三层路由 + 阈值对齐三元判题）

理由：Oracle 评审（V1.1→V1.2）确认 ≥80% 一刀切会吞并 partial，违反 V3 核心"引导容错"；三层路由既控成本（本地拦截 65%）又保三元结果完整；keywords 升级为 `{aliases[], weight, required}` 支持"唐太宗=李世民"语义容错。

## 后果

- 正面影响：判题准确率可校准；成本可控（月 LLM ≈¥800-1,200，D04 修正值）；partial 反馈完整
- 负面影响 / 风险：阈值依赖测试集校准；本地关键词引擎需实现同义词组匹配
- 后续待办：500 题测试集校准（P1）；keywords 解析器实现
