# 真实后端端到端联调与掌握度前端消费 - 开发方案（V0.6.3）

## 一、本版目标

- 核心交付：
  1. **真实后端端到端联调（历 V0.4.0/V0.5.0/V0.6.0/V0.6.1/V0.6.2 五连优先建议，本次补齐——Oracle 闭环#6 补 V0.6.1）**：起 WebApi（localhost:5020，SQLite 文件库）+ WebH5（localhost:3015，vite proxy →5020），浏览器跑通全链路：登录（联调放行）→ 学生任务会话 → 作答判题（historyAccuracy 透出）→ Progress 推进 → 会话收尾 → 家长报告。历迭代验证止于 Contract 测试 + mock typecheck——本次首次真实 HTTP/GraphQL/浏览器验证。
  2. **联调阻塞消解（摸底确认的三处硬阻塞）**：
     - **B1 登录放行**：`XiaoShuTongUserHelper` 实现联调专用认证（白名单直接返回 UserInfo，不查库不校验 credential），前端 `login.tsx` authType 从非法 `'wechat'` 修正为合法枚举 `'WE_CHAT_APPLET'` + `'MOBILE_WEB'`。
     - **B2 种子数据**：`OnEnsureDataReadyAsync` 从空壳补最小化链路种子（群主/学生/家长/群组/题库/题目/任务/分配/家长学生关系），否则登录后无任何业务数据可跑。
     - **B3 数据库**：`FreeSqlDataTypeName` 配置键切 SQLite 文件库 + Domain.csproj 补 `FreeSql.Provider.Sqlite`（CPM 已有 3.5.311）——Program.cs 零改动。
  3. **historyAccuracy 前端消费（审核报告 §七-1）**：家长端 dashboard 接真实 `dashboardReport_Execute` 的 `subjectsMastery.accuracy`（后端已就绪，替换硬编码 `MOCK_SUBJECT_MASTERY`）；mock `data.ts` 补 6 处 `submitAttemptResDtos.historyAccuracy`，mock 模式与真实模式双通道完整。
- 完成定义（DoD）：
  - **联调打通**：WebApi 启动 + 浏览器全链路走查成功（登录→任务→作答→收尾→报告），关键断言（登录 payload.success / 作答 historyAccuracy 非空 / Progress 推进 / 家长报告 subjectsMastery 渲染）截图留证。
  - 后端：全套件 `dotnet test` **394/0/2 基线不降** + 联调放行/种子无破坏性变更。
  - 前端：`pnpm typecheck` 0 错误；mock 模式走查可用（6 处 historyAccuracy 补齐）。
  - 文档：开发方案 + 审核报告 + 变更记录入档；联调阻塞/端口认知统一（mock-server 注释 5156、schema-settings 5000 遗留值清理或标注）。

### T4：最小链路种子（OnEnsureDataReadyAsync，tkwf-service 邻接）

- **描述**：`src/XiaoShuTong.Domain/XiaoShuTongDomainInitializer.data.cs` `OnEnsureDataReadyAsync` 从 `Task.CompletedTask` 空壳补最小链路种子（`IFreeSql repo` 现有性判断幂等——参考文件头注释 L15-19）：
  1. **群主/学生/家长身份**：无 Users 表（DOMAIN_MAP 确认，UserId 裸 long 外键）——身份即 `XiaoShuTongUserInfo.Id`（登录放行白名单同值：xiaoming=10001 / owner01=10002 / parent01=10003），**不建 Users 表**（保持无表架构）。
  2. **群组链路**：`Groups`（OwnerId=10002，RankEnabled=true）+ `GroupMembers`（10001 学生成员，10003 家长关联）；
  3. **题库链路**：`Banks`（语文示例 bank，Subject=Chinese）+ `Questions`（3-5 题，含 Keywords JSON/Hint/背诵篇目，复用 Contract 测试种子范式）；
  4. **任务链路**：`Tasks`（QuestionCount=题数，QuestionIds, Scenario=Memorize）+ `TaskAssignments`（TaskId+UserId=10001，Status=Pending，Progress=0, ConsumedQuestionIds 空）；
  5. **家长学生关系**：`ParentStudentRelations`（10003 → 10001）。
  - **UId 显式赋值（Oracle 闭环#2）**：实体未实现 `IEntityTracked` 时框架不自动生成 UId（V0.1.8 实证 21 个 UId 约束失败），种子插入前**每实体显式 `UidGenerator.NewId()` 赋值**（复用 Contract 测试种子范式，见 tests/ 各域种子初始化器）；GroupMembers 等含 UId 唯一索引的表尤其注意。
  - **模型可读性**：种子经 `repo.Insert(...)`（IFreeSql），不引入 DataService；枚举值对齐 DOMAIN_MAP（TaskStatus/AssignmentStatus/Subject/BankPurpose 等）。
  - **时序**：种子仅插基表数据（Groups/Banks/Tasks 等），不依赖聚合视图（PkPlayerStatsView 无种子需求）——建表后即可，与视图同步时序无耦合（Oracle 确认非阻塞）。
- **验证**：`dotnet test` 基线不降（T4 纯 InitializeAsync 后数据，不干扰测试 Reset——测试 Fixture 每 Fact Reset 清库重种，与 T4 无冲突；补 1 用例断言种子存在性可选）；`dotnet run` 后 `repo.Select<Groups>().Any()` 为 true（psql/SQLite 客户端或 GraphQL 查询验证）。
- **skill 路由**：`tkwf-service` {Domain}=Shared（种子为跨域初始化，非单域 Service）
- **验收**：WebApi 首次启动后库内有群组/题库/任务/分配/家长关系（浏览器 GraphQL Playground 或 Scalar UI 查询验证）。

## 五、关键决策与风险

| # | 决策/风险 | 说明 |
|:-:|----------|------|
| ① | **SQLite 而非 PG 联调** | 仓库无 docker-compose/PG 先例，Tier 1.5 已全链路验证 SQLite 方言（含 PkPlayerStatsView.ViewSqlSQLite）；`FreeSqlDataTypeName` 配置键实现 Program.cs 零改动；生产 appsettings.json 保持 PG 不动——联调环境与生产配置解耦 |
| ② | **联调放行是临时认证** | `OnLoginByWeChatAppletAsync` 白名单直接返回身份是**开发/联调专用**，生产必须被 OnLoginByPasswordAsync/微信 OAuth 替代——类注释 + 审核报告风险区双重标注，防止误入生产；不与既有 Guest 路径冲突 |
