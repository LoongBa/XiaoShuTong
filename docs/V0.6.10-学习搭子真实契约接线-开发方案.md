# 学习搭子真实契约接线 - 开发方案（V0.6.10）

## 一、背景与目标

### 1.1 背景

V0.6.7 审核报告 §七 遗留："学习搭子（rank MOCK_BUDDIES → buddies_Execute）——独立功能域另立"。本迭代闭环该遗留。

**现状核查（explore Buddy 域契约实证）**：

1. **前端现状**：
   - `rank.tsx` L30-34：`MOCK_BUDDIES` 3 条硬编码（id/name/streakDays），L439 `<StudyBuddySection buddies={MOCK_BUDDIES} onInvite={() => console.log('invite buddy')} />`
   - `StudyBuddySection.tsx`：`Buddy` 接口 `{id, name, avatar?, streakDays}`，MAX_BUDDIES=5，空位「+邀请」按钮，空态文案「还没有学习搭子，快邀请好友一起学习吧！」（与 UI 设计 L575 一致）；邀请弹窗（复制链接/微信邀请/海报）纯前端 alert 模拟

2. **后端契约（已实证，7 Service + 错误码表）**：
   - **`listBuddies_Execute` 可直接接线**：无参查询（`args?: Record<string, unknown>`），返回 `{success, errorCode, items: BuddyListItemDto[]}`；**空数组即空态**（BR-24 无搭子返回空列表非错误）
   - `BuddyListItemDto` 7 字段：buddyId（关系 Uid）/ userId（搭子用户 Id）/ nickname（**账户域切片恒空串**）/ avatarUrl（**恒空串**）/ streakDays / status（**恒 "Accepted"**，BR-25 仅查 accepted）/ rank（RankSnapshotsDto 可空，对方最新快照，无则 null）
   - **邀请能力后端已存在**：`inviteBuddy_Execute({inviteeUserId: Long!})` + accept/reject/remove/buddyRank 全套（UC-8.1~8.6，错误码 6001-6006）
   - **邀请入参缺口**：`inviteeUserId` 是好友的 long Id——当前**无"搜索/发现好友"服务**，且 nickname/avatarUrl 恒空串（账户域未实施）。前端无法获得"可邀请的好友 id"→ 邀请交互的**入口数据源是缺口**

3. **mock 现状（已就绪）**：`data.ts` listBuddiesResDtos 2 条（含 2 搭子：小红 5 天/小刚 3 天 + 空场景 items:[]）；ts-client.mock.g.ts ListBuddiesResDtoSchema 完整 + `defineListBuddiesResDto` + mock handler 已有 → **无需补 mock**

### 1.2 目标

1. **真实接线**：rank.tsx 删 MOCK_BUDDIES，接 `listBuddies_Execute`（无参）真实数据
2. **字段映射**：BuddyListItemDto → StudyBuddySection.Buddy（buddyId→id、nickname||学生{userId}→name、streakDays→streakDays）；nickname 空串时「学生{userId}」兜底（与 parent/dashboard children 同范式）
3. **空态对齐**：`items.length === 0` → StudyBuddySection 现有空态文案天然生效（对齐 UI L575"还没有学习搭子，快邀请好友一起学习吧！"）
4. **邀请交互保留占位**：inviteBuddy 后端可用但好友发现缺口 → 邀请按钮保留现有 UI（弹窗模拟），登记配合项（好友发现/账户域昵称头像）
5. **错误处理**：listBuddies 失败（success=false/RPC 抛错）→ 搭子区静默空态（非阻塞——搭子是辅助区，失败不炸页面）

### 1.3 范围决策（不做什么）

| 不做 | 理由 | 归属 |
|------|------|------|
| 邀请搭子真实提交（inviteBuddy_Execute 接线） | 入参 inviteeUserId 无来源（好友发现缺失）——无法在 UI 让用户选"谁" | 配合项（好友发现服务） |
| 接受/拒绝邀请 UI（accept/reject） | 需"待处理邀请"列表契约（当前后端仅从受邀方视角接受，无已收邀请查询） | 配合项 |
| 解除搭子（removeBuddy 接线） | UI 无解除交互，且搭子头像点击无菜单 | 不做 |
| nickname/avatarUrl 富化 | 依赖账户域（跨模块，V0.6.5 既有后续项） | 配合项 |

## 四、技术方案

### 4.1 接线（rank.tsx）

```tsx
// 删 MOCK_BUDDIES 常量（L30-34）
const [buddies, setBuddies] = useState<BuddyItemLocal[]>([]);

// 学习搭子（V0.6.10：listBuddies_Execute 真实拉取；空数组=空态 BR-24）
useEffect(() => {
  if (!isLoggedIn) return;
  let cancelled = false;
  const loadBuddies = async () => {
    try {
      const res = await Tkwf.User.Use<ListBuddies_ExecuteService>().listBuddies_Execute();
      if (cancelled) return;
      if (res.success) {
        setBuddies((res.items ?? []).map(toBuddyLocal));
      }
      // 失败成功与否都静默（搭子辅助区非阻塞；空数组走空态文案）
    } catch {
      // RPC 抛错：搭子区保持空态，不炸页面
    }
  };
  void loadBuddies();
  return () => { cancelled = true; };
}, [isLoggedIn]);

const toBuddyLocal = (b: BuddyListItemDto): BuddyItemLocal => ({
  id: b.buddyId,
  name: b.nickname || `学生${b.userId}`,  // 账户域空串兜底（同 parent children 范式）
  streakDays: b.streakDays ?? 0,
  // rank 可空：本次不展示（趋势箭头属于排行榜区域，非搭子卡；登记可后续消费）
});
```

```tsx
<StudyBuddySection buddies={buddies} onInvite={() => console.log('invite buddy')} />
```

### 4.2 本地类型（避免污染 gql 类型）

`rank.tsx` 内定义 `interface BuddyItemLocal { id: string; name: string; streakDays: number; }`——与 StudyBuddySection.Buddy 兼容（满足 id/name/streakDays；avatar 可选不传），不手改组件接口。

### 4.3 错误处理决策

- `success=false` → 静默空态（不 setLoadError——搭子为辅助展示区，失败不应阻塞排行主区）
- RPC 抛错 → `catch (e) { console.warn('[buddy] listBuddies failed', e); }` 静默降级但保留可观测性（Oracle C2）
- 与 wrong.tsx 的区别：wrong 是主内容页需错误态，rank 搭子是副区域静默降级

### 4.4 加载态与登出（Oracle M1/C3）

- 补 `buddiesLoading` 状态：加载期间不渲染搭子区内容（占位空白），数据返回（成功或失败）后再渲染；**空态文案仅 `loading===false && items.length===0` 时显示**——避免用户等待时误见"还没有搭子"
- 登出态清空：`if (!isLoggedIn) { setBuddies([]); return; }`——不残留上一用户搭子数据（Oracle C3）

### 4.5 邀请交互

- 保留现有 StudyBuddySection 邀请弹窗（复制链接/微信邀请/海报均为前端模拟）
- `onInvite` 仍 console.log 占位——**登记配合项**：好友发现服务 + inviteBuddy_Execute 接线（依赖账户域/好友搜索）

## 六、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| listBuddies 无参调用签名（Record<string, unknown>） | 调用方式与带 request 的 Service 不同 | ts-client.g.ts L1846 实证 `listBuddies_Execute(args?: Record<string, unknown>)`——不传参直接调用（与 listChildren_Execute 同范式，Oracle 实证） |
| 联调种子无搭子数据 | 走查搭子区恒空态 | mock 场景覆盖 2 搭子；联调种子可补 StudyBuddies（配合项） |
| StudyBuddySection.Buddy 接口本地类型不匹配 | TS 报错 | 用 BuddyItemLocal 局部类型映射，props 满足子集即可（avatar 可选缺省） |
| mock handler "单条"标记（Oracle M2） | 可能返回单个 ResDto 而非 {items:[]} | **已实证闭环**：`db.queryOne("listBuddiesResDtos")` 返回整条 ListBuddiesResDto（含 items），"单条"指单 ResDto 非 items——mock 已就绪无需补 |
