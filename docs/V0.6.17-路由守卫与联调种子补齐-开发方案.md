# 路由守卫 role 门禁 + 联调种子补齐 - 开发方案（V0.6.17）

## 一、背景与目标

### 1.1 背景

**① 路由守卫（V0.6.11 §七 登记）**：V0.6.11 已实现 login role 分跳（xiaoming→student/owner01→teacher/parent01→parent），但**各端路由仅检查 isLoggedIn，无 role 校验**——student 账号可直接 URL 导航 `/teacher/dashboard` 越权访问。审核报告登记"生产上线前各端路由补 role 门禁"。本迭代提前落地（联调环境已有多端账号，越权可实证）。

**② 联调种子补齐（V0.6.9/10/14/16 联动）**：各迭代审核报告累计登记：
- V0.6.9/14：错题本走查需要 WrongQuestions 数据（V0.6.14 已实现重练/标记，但种子无 Attempts→无法驱动 BR-23 生成错题）
- V0.6.10/16：学习搭子走查需要 StudyBuddies 数据（V0.6.10 listBuddies 已接、V0.6.16 候选已接，但种子无搭子记录）

**现状核查**：
1. **路由平铺结构**（routeTree.gen.ts 实证）：/student/*、/teacher/*、/parent/* 全部直接挂 root，无布局级父路由——beforeLoad 守卫需在页面级逐个加（14 页，重复）或**根组件全局守卫**（统一处理更优）
2. **__root.tsx**：root 布局无 beforeLoad，RootComponent 包 QueryClientProvider + Outlet
3. **登录态**：useAppStore.currentUser.role（student/teacher/parent）已持久化（V0.6.11）；login 分跳已实现
4. **种子**（XiaoShuTongDomainInitializer.data.cs 实证）：群组 group-demo-73 + 成员 10001（小明学生）/10003（家长）/10011（小美）/10012（小刚）+ 题库 3 题 + 任务 + TaskAssignments + ParentStudentRelations + DailyStats/KnowledgeMastery/RankSnapshots——**无 Attempts、无 WrongQuestions、无 StudyBuddies**

### 1.2 目标

1. **全局路由守卫**：根组件监听路由变化，按 pathname 前缀门禁：
   - `/student/*` → 需 `role === 'student'`
   - `/teacher/*` → 需 `role === 'teacher'`
   - `/parent/*` → 需 `role === 'parent'`
   - 不匹配 → navigate 到对应端首页（teacher→/teacher/dashboard、parent→/parent/dashboard、student→/student/home）；未登录 → /auth/login
2. **联调种子补齐**：
   - 补 Attempts（3 学生 × 2 题作答，Wrong 记录驱动）→ WrongQuestions 自动生成（BR-23）或直插 WrongQuestions（RankSnapshots 直插先例，免依赖图谱）
   - 补 StudyBuddies：10001-10011 accepted（小明-小美已成搭子）+ 10001-10012 pending（小明-小刚待接受）→ listBuddies 走查 + 候选列表排除已有关系展示

### 1.3 范围决策（不做什么）

| 不做 | 理由 | 归属 |
|------|------|------|
| 页面级 beforeLoad 逐页加 | 14 页重复；根组件全局守卫统一处理更优雅（平铺路由拓扑） | 不做 |
| Auth 权限服务端硬校验 | 后端 RPC 已有 [AuthorityFilter]（登录态），role 粒度门禁属前端体验（后端按数据 RLS 已隔离）；生产可后续加服务端 role claim | 生产配合项 |
| 种子补 Intelligence/完整作答历史 | 种子只为走查链路，最小补（错题本 2 条 + 搭子 2 条） | 不做 |

## 二、方案要点

### 2.1 全局路由守卫（前端，__root.tsx root beforeLoad——Oracle M1：路由原生更优，无闪跳）

```tsx
// __root.tsx：root route beforeLoad（Oracle M1 采纳——路由解析前同步拦截，优于 useEffect 免闪跳/无限次）
import { redirect } from '@tanstack/react-router';
// 共存：createRootRouteWithContext 内增加 beforeLoad（读 Zustand store 同步态）
beforeLoad: ({ location }) => {
  const { currentUser, isLoggedIn } = useAppStore.getState();
  const path = location.pathname;
  // 未登录 → 非 /auth/* 去 login（根路径 / 一并跳转，Oracle 补登）
  if (!isLoggedIn) {
    if (!path.startsWith('/auth/')) throw redirect({ to: '/auth/login' });
    return;
  }
  // role 门禁（V0.6.17）：按路径前缀校验；不匹配 → 对应端首页
  const role = currentUser?.role;
  if (path.startsWith('/teacher') && role !== 'teacher')
    throw redirect({ to: role === 'parent' ? '/parent/dashboard' : '/student/home' });
  if (path.startsWith('/parent') && role !== 'parent')
    throw redirect({ to: role === 'teacher' ? '/teacher/dashboard' : '/student/home' });
  if (path.startsWith('/student') && role !== 'student')
    throw redirect({ to: role === 'teacher' ? '/teacher/dashboard' : '/parent/dashboard' });
}
```

- beforeLoad 同步在路由解析前拦截（目标页不渲染，无闪跳）；`throw redirect()` 天然单次（Oracle M1）
- 读 store 用 `useAppStore.getState()`（同步快照，persist 已恢复 currentUser/role）
- 现有各页 isLoggedIn useEffect 保留（双保险，不改）
- 根路径 `/` 未登录一并跳 /auth/login（Oracle 补登）
