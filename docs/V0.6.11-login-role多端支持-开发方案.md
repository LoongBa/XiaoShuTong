# login role 多端支持 - 开发方案（V0.6.11）

## 一、背景与目标

### 1.1 背景

V0.6.8 审核报告:102 P3 登记："login.tsx role 恒 student：teacher/parent 走查受限于 UI 登录（契约层已验证）"。V0.6.7 开发方案:159 记录临时绕过："走查用直接路由导航（绕角色跳转），不走登录跳转"。

**现状核查（explore 契约审计实证）**：

1. **后端 Roles 已正确赋值**（XiaoShuTongUserHelper.cs:46-76 白名单，手写源码）：
   - `xiaoming`(10001) → `Roles=["student"]`（小明）
   - `owner01`(10002) → `Roles=["owner"]`（群主老师）
   - `parent01`(10003) → `Roles=["parent"]`（家长）
   - **但登录契约不透出**：`LoginPayload`（schema.graphql:1080）全字段 success/userName/displayName/sessionKey/accessToken/refreshToken/expiresAt/deviceId/extensions——**无 role 字段**；`extensions: [ExtensionEntry!]`（key/value）恒为空，无约定 key 语义 → 前端拿不到角色

2. **前端 role 全凭硬编码**：login.tsx:57-64 构造 `mockUser` 写死 `role:'student'`（`:61`），`payload` 仅取 displayName——**与后端 Roles 完全脱钩**

3. **UserRole 类型断层**（types/index.ts:4）：`'student' | 'teacher' | 'parent'`——**无 'owner'**；后端用 `'owner'` 表达群主（owner01 DisplayName="群主老师"），语义对应前端 teacher 端但字符串不匹配

4. **路由守卫零 role 校验**：router.tsx 无守卫；teacher/parent/student 路由均只检查 `isLoggedIn`，不校验 role → student 账号可直接导航 /teacher/dashboard

5. **登录跳转逻辑已就绪**：login.tsx:22-33 role 分支跳转（student→/student/home、teacher→/teacher/dashboard、parent→/parent/dashboard）**已写好但永不触发**（role 恒 student）

6. **UI 设计 L82-85**：登录页单微信按钮 + "登录流程：微信授权 → 判断身份（学生/群主/家长）→ 分别进对应首页"——**身份由后端判定，前端无角色选择 UI 设计**（生产形态）

7. **mock 缺口**：mock/data.ts loginPayloads 仅 xiaoming 一条（:20-26），无 owner01/parent01 payload

### 1.2 目标

1. **走查解锁（P3 闭环）**：login.tsx 支持三端登录——联调账号选择（学生小明/群主老师/家长），登录后 role 正确分跳 /student/home、/teacher/dashboard、/parent/dashboard
2. **role 来源修正**：role 由 userName 映射派生（对齐后端白名单 Roles 语义），不再恒写死 'student'；owner→teacher 前端映射（UserRole 无 owner，owner01="群主老师" 语义即 teacher 端）
3. **mock 补齐**：loginPayloads 补 owner01/parent01 两条
4. **契约缺口登记**：后端 Roles 未透出 LoginPayload.extensions——生产前配合项（生产登录走 OnLoginByPasswordAsync/微信 OAuth，届时契约须携 role）
5. **路由守卫缺口登记**：无 role 校验（student 可越权）——本次不改（联调阶段），登记生产配合项

### 1.3 范围决策（不做什么）

| 不做 | 理由 | 归属 |
|------|------|------|
| 后端 Roles 透出 LoginPayload.extensions | 涉框架登录链路改造（AuthController/LoginPayload 组装），触框架红线风险高；联调走查不依赖 | 生产配合项 |
| 路由守卫 role 校验 | 全部路由已实现未校验（改造面大），联调阶段学生访问 teacher 页无生产危害 | 生产配合项 |
| 真实微信授权流程 | UI 设计"微信授权→后端判身份"是生产形态；联调无真实微信通道，白名单账号直接映射 | 生产 |
| UserRole 加 'owner' 枚举值 | 前端三端路由体系（student/teacher/parent）已稳定，owner01 语义=teacher 端，映射即可 | 不做 |

## 四、技术方案

### 4.1 联调账号选择（UI 形态）

登录页主按钮（微信一键登录）保留——生产语义不变。主按钮下新增**联调账号切换**（走查工具，不破坏生产形态）：

```tsx
// 联调账号（Development 走查用；生产走真实微信授权，此区块废弃）
const DEV_ACCOUNTS = [
  { userName: 'xiaoming', name: '学生 · 小明' },
  { userName: 'owner01',  name: '群主 · 群主老师' },
  { userName: 'parent01', name: '家长 · 家长' },
];
const [devUser, setDevUser] = useState('xiaoming'); // 默认学生
```

- 主按钮文案不变（微信一键登录），点击用当前选中 devUser 调 `Tkwf.Guest.loginByContext`
- 账号选择：三枚小胶囊按钮（默认选中 xiaoming），仅展示当前联调身份
- 注释明确：联调工具区块，生产登录（真实微信授权）时移除，role 由后端契约携带

### 4.2 role 映射（userName → 前端 UserRole）

```tsx
// 与后端白名单 Roles 语义对齐（XiaoShuTongUserHelper.cs:46-76）
// owner → teacher：前端 UserRole 无 owner，owner01="群主老师" 语义即 teacher 端（路由 /teacher/dashboard）
function resolveRole(userName: string): 'student' | 'teacher' | 'parent' {
  switch (userName) {
    case 'owner01': return 'teacher';
    case 'parent01': return 'parent';
    default: return 'student'; // xiaoming 及未来学生
  }
}
```

### 4.3 登录后分跳

复用现有 login.tsx:22-33 分支逻辑——`mockUser.role` 用 `resolveRole(payload.userName)` 替代恒 'student'；id/name 同步修正：

```tsx
const mockUser: User = {
  id: payload.userName === 'owner01' ? 'owner-1' : payload.userName === 'parent01' ? 'parent-1' : 'student-1',
  name: payload.displayName || DEV_ACCOUNTS.find(a => a.userName === payload.userName)?.name || '用户',
  avatar: '',
  role: resolveRole(payload.userName),
  streakDays: 0,
  classId: ''
};
```

登录后：`hasAgreedPrivacy ? navigate(role 分跳) : navigate('/auth/privacy')`（现有逻辑，role 修正后生效）。

### 4.5 走查流程闭环（Oracle C2/C3 实证闭环）

- **privacy 跳转修复（C3，真实缺陷）**：privacy.tsx `handleAgree`/`handleGuardianConfirm` 恒跳 `/student/home` → 改为按当前用户 role 分跳（复用 login.tsx 的 role 分支逻辑）。`hasAgreedPrivacy` 已同意时（刷新回 privacy 页）同样按 role 分跳。
- **登出（C2）**：student/profile 已有（logout+回登录页）；teacher/parent 端无登出 → **补 teacher/parent 端登出按钮**（顶部导航返回 + 个人入口内登出，最小实现：页面内"退出登录"按钮调 logout + navigate login）。
- **走查会话重置**：`logout()` 清空 currentUser/isLoggedIn（appStore.ts:111 实证完整）→ 走查三端切换 = 登录页选账号 → 各端登出 → 回登录页选另一账号。

### 4.6 登记（生产配合项）

- **后端 Roles 透出 LoginPayload.extensions**：生产登录（OnLoginByPasswordAsync/微信 OAuth）契约须携 role（`{key:"roles", value:"owner"}` 约定），前端从 extensions 读——D03 契约文档补约定
- **路由守卫 role 校验**：生产上线前各端路由补 role 门禁（学生不可越权进 teacher/parent）
- **UserRole 'owner' 归一**：若生产端引入群主独立端而非 teacher 端，需加 owner 枚举（当前映射 teacher 够用）

## 六、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| owner→teacher 映射是前端语义推断 | 后端 Roles 与前端 UserRole 命名断裂 | 注释明确对齐白名单语义；变更记录登记生产配合项（UserRole owner 归一） |
| extensions 恒空（后端不透出） | 无法从响应读 role，只能前端映射 | 联调阶段接受前端映射；生产配合项登记（extensions 透出） |
| 隐私协议流程（首次登录 <14 岁） | 新账号首次登录进隐私页 | 现有 hasAgreedPrivacy 逻辑保留，不因 role 改造受影响 |
| 联调账号区块生产残留 | 生产登录页出现"群主/家长"开发按钮 | 注释 + 变更记录标注生产移除；UI 设计保持单按钮主形态 |
