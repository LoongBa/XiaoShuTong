# 好友发现 + 邀请接线 - 开发方案（V0.6.16）

## 一、背景与目标

### 1.1 背景

V0.6.10 审核报告 §七 登记配合项："好友发现服务：inviteBuddy_Execute 接线前置（入参 inviteeUserId 无来源）——登记配合项（需后端好友搜索/群成员选择）"。

**现状核查（后端 Service 实读 + 契约实证）**：

1. **InviteBuddyService 已就绪**（UC-8.1，V0.6.10 前已存在）：
   - `inviteBuddy_Execute({inviteeUserId: long})` → `{inviteId, expiresAt}`（+7 天）
   - BR-14 accepted ≥5 → 6003 / BR-15 当日 >10 → 6005 / **BR-16 同群组/同年级（OR）→ 6006** / BR-17 重复（pending/accepted）→ 6002 / BR-18 +7 天
   - 入参 `InviteeUserId` 直接 long Id（账户域 Uid→Id 映射未实施）
2. **好友发现源缺口**：学生视角无现成"可邀搭子候选"查询：
   - `members_Execute({groupId})`（ManageGroupMembersService）是**群主专属**（BR-08 仅 Owner）——学生不可调用
   - 学生需"我的群"（GroupMembers 反查）→ 同 GroupId 其他学生成员（排除自己 + 已有搭子关系）
3. **实体字段**（DOMAIN_MAP 实证）：
   - `GroupMembers`：GroupId/UserId/Role（Student/Parent）/**Nickname（群内昵称可用）**/JoinedAt
   - `Groups`：Name/Grade/Status
   - `StudyBuddies`：InviterId/InviteeId/Status（Pending/Accepted/Rejected/Removed/Expired）/ExpiresAt
4. **前端现状**：StudyBuddySection 邀请弹窗（L90-114）纯 alert 模拟（复制链接/微信邀请/海报），无真实好友选择；rank.tsx 已接 listBuddies（V0.6.10）但邀请占位 console.log

### 1.2 目标

1. **后端新增 ListBuddyCandidatesService**：当前用户可邀搭子候选列表——同群组成员（GroupMembers.Nickname 展示）+ 排除自己 + 排除已有 Buddy 关系（Pending/Accepted）+ 排除非学生（Role=Parent）
2. **前端邀请弹窗接真实**：弹窗内展示候选列表（昵称群名）→ 点"邀请"调 inviteBuddy_Execute → 成功提示（幂等/错误码 toast）
3. **邀请交互闭环**：候选列表（发现）+ inviteBuddy_Execute（邀请）+ listBuddies（V0.6.10 已接展示）全链路真实

### 1.3 范围决策（不做什么）

| 不做 | 理由 | 归属 |
|------|------|------|
| 全库好友搜索（搜索框） | 搭子 BR-16 限定同群组/同年级——候选天然限同群；UI 无搜索设计 | 不做 |
| 接受/拒绝邀请 UI | 需"待收邀请"查询服务（V0.6.10 登记另一配合项），本迭代 focus 发起端 | 后续迭代 |
| 搭子解除（removeBuddy）接线 | UI 无解除交互（V0.6.10 不做项延续） | 后续迭代 |
| 同年级跨群候选 | BR-16 OR 语义，但 UI 简化先同群（跨群候选引入群选择复杂度） | 后续按需 |

## 二、方案要点

### 2.1 新增 BR（先 tkwf-business 物化）

| BR | 内容 |
|---|---|
| 搭子-BR-33 | 候选列表：同群组成员（Role=Student）+ 排除自己 + 排除已有搭子关系（Pending/Accepted）+ 排除 Parent 角色；展示 GroupMembers.Nickname + Group.Name |
| 搭子-BR-34 | 候选查询无邀请动作（只读；权限=当前用户群成员身份） |

### 2.2 ListBuddyCandidatesService（Buddy 域新增，tkwf-service）

```csharp
// Services/Buddy/ListBuddyCandidatesService.cs
[GenerateController]
[AuthorityFilter<XiaoShuTongUserInfo>]
internal class ListBuddyCandidatesService(DomainUser<XiaoShuTongUserInfo> user)
    : DomainServiceBase<XiaoShuTongUserInfo>(user)
{
    // BR-33：同群学生成员（排除自己/已有搭子/Parent）→ 候选列表
    public async Task<ListBuddyCandidatesResDto> ExecuteAsync(CancellationToken ct = default)
}
```

- ReqDto：无参（当前用户隐式）
- ResDto：`{success, errorCode, items: [
    { userId: long, nickname: string, groupName: string, groupId: long }
  ]}`
- 逻辑：
  1. `GroupMembers` 按 `UserId == me` 查我的群 GroupId 集合
  2. 同 GroupId 查其他成员（`Role == Student`，排除 UserId == me）
  3. 查 StudyBuddies 排除已有关系（`InviterId==me&&InviteeId==other` 或反向，Status ∈ {Pending, Accepted}）
  4. Group.Name 填充 groupName；GroupMembers.Nickname 填充 nickname（空串兜底 `学生{userId}`）
  5. GROUP BY UserId 去重（多群同人）

### 2.3 前端 StudyBuddySection 改造

- `onInvite` 从 console.log 改为打开真实弹窗：
  - 打开时调 `listBuddyCandidates_Execute` 拉候选
  - 候选列表（nickname + groupName 徽章）→ 行内"邀请"按钮 → `inviteBuddy_Execute({inviteeUserId})`
  - 成功 → toast"邀请已发送" + 关闭弹窗；**再次打开弹窗时重拉候选（已邀请的人从候选移除，避免重复点邀请触发 6002）——Oracle C2**
  - 失败 → errorCode 文案映射（6003 搭子数满 / 6005 当日超限 / 6006 非同群 / 6002 已邀请；**6001 不在发起端触发——accept/reject 端"邀请不存在"，前端候选邀请不映射——Oracle C3**）
- **候选空态（Oracle C1）**：候选列表为空时弹窗内展示"暂无可邀请的同班同学" + 引导保留复制链接/海报渠道
- **已邀请待接受态（Oracle C5）**：候选排除 Pending/Accepted 不展示"已邀请"态；用户"我邀请的人去哪了"出口 = listBuddies（该列表返回 Accepted 搭子）∪ 待收邀请列表（V0.6.10 §七 另一配合项，本迭代不做）
- 保留现有复制链接/海报（次要渠道，**同年级跨群可邀但候选不展示——需走此渠道，Oracle C4**），主交互=候选列表邀请

### 2.4 mock 补齐

- `listBuddyCandidatesResDtos`：2 候选（学生X by groupName）
- `inviteBuddy` 已有 mock（V0.6.10 检查过）——确认字段对齐

## 五、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 候选与 BR-16 门控不一致 | 候选列表含非同群用户 → 邀请被 6006 拒 | 候选取同群成员（BR-16 同群即满足）；跨年级不做（范围决策） |
| 多群同人去重 | 候选重复展示 | GROUP BY UserId 聚合 groupName 拼接 |
| 已有搭子关系过滤 | 候选含已搭子/已邀请 → 邀请 6002 | 排除 Status ∈ {Pending, Accepted} |
| GroupMembers.Nickname 空 | 候选昵称空串 | 兜底 `学生{userId}`（同 V0.6.15 范式） |
| 联调种子无多成员 | 候选列表空/单 | 种子补 GroupMembers 多学生（V0.6.17 种子补齐联动） |
