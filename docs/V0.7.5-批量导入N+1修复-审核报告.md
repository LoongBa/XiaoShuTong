## 二、改动逐项审查

### T1 ImportQuestionsService（读侧一次 IN + 写侧批量 + 文件 IO 移出循环）

| 原位置 | 原形态 | 新形态 | 审查结论 |
|--------|--------|--------|---------|
| L75-78 | `foreach` 题 → `EntityGetAsync` 判重（读 N+1） | 循环前一次 `EntitySelectAsync(bankId)` → `HashSet<string>` 内存判重 | ✅ 无循环内查询；`HashSet(StringComparer.Ordinal)` 判重语义与原 `x.QuestionId == q.QuestionId` 一致 |
| L89-91 | 循环内 `LoadOrCreateContentFileAsync` + `Save`（整文件读改写） | 循环前 Load 一次、循环内仅内存 `Add`、`toCreate.Count>0` 时循环外 Save 一次 | ✅ 语义等价（原逻辑每题判重通过后必 Save；新逻辑有新增才 Save——全部重复时不写文件，与"无新增不落盘"一致） |
| L94-106 | `foreach` 题 → `EntityCreateAsync`（写 N+1） | 收集 `toCreate` → `EntityCreateBatchAsync` 一次 | ✅ BR-15 原子（`[Transactional]` + sealed 批量单事务）；返回 List 含回填 Id 本轮不依赖 |

**BR 保持**：BR-11/12/13 权限预检不变；BR-14 部分失败行号（解析失败 + 重复跳过）不变——`imported = parsed.Questions.Count - failures.Count(f => f.StartsWith("题目 "))` 逻辑原样保留。

### T2 ImportBankJsonService（读侧一次 IN + create/update 分列批量 + 文件 IO 移出循环）

| 原位置 | 原形态 | 新形态 | 审查结论 |
|--------|--------|--------|---------|
| L103-104 | `foreach` 题 → `EntityGetAsync` upsert 判重（读 N+1） | 循环前一次 `EntitySelectAsync(bankId)` → `Dictionary<QuestionId, Questions>` 内存判定 | ✅ 无循环内查询；`ToDictionary(StringComparer.Ordinal)` 键语义与原判等一致 |
| L113-116 | 循环内 Load + RemoveAll + Add + Save | 循环前 Load 一次、循环内同实例 RemoveAll+Add（内存 upsert）、循环外 Save 一次 | ✅ 语义等价（upsert：同 QuestionId 替换）；单方法单线程无并发 |
| L120-146 | create / update 逐条提交（写 N+1） | `toCreate` → `EntityCreateBatchAsync`；`toUpdate` → `EntityUpdateColumnsBatchAsync(toUpdate, q => new { q.Content, q.Keywords, q.KnowledgePoints, q.Topic, q.Hint }, ct)` | ✅ **C4 闭环**：列表达式指定 5 列（列精度，规避整实体覆盖未改列如 Status/Difficulty/UId）；v4.10.38 ADR83 起两 API 均支持游离实体（**M2/C3 闭环**：论证理由已从"attach 约束"改写为"列精度"） |

**BR 保持**：幂等键 = QuestionId upsert（不重复创建）；ADR-010 决策六 Hint join 不变；Content 镜像 cardType/card 字段不变；BR-15 原子不变。
