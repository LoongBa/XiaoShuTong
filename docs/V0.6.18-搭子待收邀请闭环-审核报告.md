## 二、审核结论

**总评：通过**

搭子域"收到→处理"环节闭环——学生收到邀请后首次有查看/处理入口（待收列表 + accept/reject 真实接线），搭子全链路（发现 V0.6.16 → 发起 → **收到 → 处理** → 列表 V0.6.10）贯通。核心交付：

1. **搭子-BR-35/36 物化（B1）**：待收列表语义（InviteeId=me + Pending + ExpiresAt ≥ now 惰性过期，与 accept/reject 6002 的 `ExpiresAt < now` 互补一致）+ 只读/无分页（量级受 BR-15 ≤10/日 + BR-18 +7 天约束 ≈70 条，同 ListBuddies/ListBuddyCandidates 范式）；BR-35 显式记录惰性过期副作用（BR-17 只看 Status 不看 ExpiresAt，过期 Pending 仍阻塞重邀——本轮不修正，后续迭代）；§3.4 状态机图注 Expired 惰性语义；头部上限搭子-32→36。
2. **ListPendingBuddyInvitesService（S1）**：无参 ExecuteAsync → `{items: [{inviteId, inviterUserId, nickname, avatarUrl, invitedAt, expiresAt}]}`——StudyBuddies 表达式树过滤（InviteeId=me/Pending/未过期）→ InviterId 一次 IN 查 GroupMembers 昵称（防 N+1，多群 GroupBy 取 First，null 兜底 `学生{userId}`）→ InvitedAt 倒序。编译 0 警告 0 错误。
3. **前端待收邀请区块（F1）**：StudyBuddySection 加"待处理邀请 (N)"区块（M1 红点视觉强调）——挂载拉 `listPendingBuddyInvites_Execute`、accept → `acceptBuddyInvite_Execute({inviteId})` + 重拉 + `onBuddyChanged?.()` 刷新搭子列表（M2）、reject → `rejectBuddyInvite_Execute` 仅重拉（C10）；6001/6002 提示 + 重拉、6003 提示保留（C6）；网络异常 catch 不重拉（C4）、finally 清 processingId（C5）；空态隐藏区块（M1）。rank.tsx loadBuddies 提升组件级 useCallback（C2 实现前提）。
4. **mock 补齐（F2）**：listPendingBuddyInvitesResDtos 2 条（小刚 3 天前/小红 1 天前，倒序验证）；buildSchema+gen-mock 契约刷新（Services 68→69）。

## 四、关键决策

| # | 决策 | 说明 |
|---|------|------|
| ① | 待收空态隐藏 + 有内容红点强调（Oracle M1 采纳 A 附条件） | 待收是被动触发（别人邀请我），空态高频不应占位；有内容时标题带 N + 红点——区块是唯一发现入口，防漏处理 |
| ② | onBuddyChanged 回调复用 loadBuddies（Oracle M2 采纳 A） | 单一数据源（rank.tsx 持有 buddies state）不破坏；前置 C2：loadBuddies 从 useEffect 闭包提升组件级 useCallback |
| ③ | 惰性过期副作用记录不修正（Oracle M3 采纳 A） | 待收查询只读不触碰写路径；BR-17 只看 Status 致过期 Pending 仍阻塞重邀——BR-35 物化记录，后续迭代修正 BR-17 查询条件 |
| ④ | 无分页（Oracle M4 采纳） | 量级有限（BR-15 ≤10/日 × BR-18 +7 天 ≈70 条），同 ListBuddies/ListBuddyCandidates 范式；BR-36 注明 |
| ⑤ | reject 不触发 onBuddyChanged（C10） | 拒绝的邀请人本来就不是搭子，搭子列表不变；避免多余 RPC |
