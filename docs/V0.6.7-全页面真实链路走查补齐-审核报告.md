## 二、审核结论

**总评：通过**

V0.6.6 审核报告 §七"其余页面真实数据链路未逐一走查"遗留项落地深度修复。explore 全矩阵揭示了**远超"页面没接线"的结构性根因**：

1. **store 双轨断裂（根因）**：`home.tsx:39-41` 本地 `useState` 遮蔽 store 同名 setter → 首页真实 API 数据困在页内；`appStore.ts` 的 6 个 setter 无真实数据写入者、`initMockData`(:226) 全仓库 0 调用 → review/wrong/heatmap/self/profile 5 页读到的 store 恒为 `[]`。**"纯 mock"假象本质是"从未接到任何数据源"**。
2. **契约错配 8 项**：rank subject 小写英文 vs 契约 `All/语文/…`（静默失效）、task taskId `Number(UId)`=NaN 恒 null、teacher `String(groupId)` 错当 groupUid + 5 处不存在的响应字段（学生表/逾期/进度/截止/key 全错）、parent 4 个已返回字段未消费、`/parent/progress` 死路由。
3. **零调用页面 4 项**：self/profile 接真实契约；review/heatmap 由 P0-1 store 回写自动复活。

**修复交付（提交 `ffff633`）**：
- 批次一（断链）：P0-1 store 回写（streakDays 保持本地，Oracle M1 决策）+ P0-2 删 initMockData + P1-1 记忆状态统一映射 + P1-2 标题占位
- 批次二（契约）：P0-3 taskId 防退化 + P0-4 detail 路由 + P0-5 subject 枚举 + P1-3~7 teacher/parent/rank 共 8 项
- 批次三（接线）：self `listBanks_Execute` 聚合学科卡 + profile `memoryStates_Execute` 计数
