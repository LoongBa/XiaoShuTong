# 任务进度重算热路径优化 - 开发方案（V0.6.1）

## 一、本版目标

- 核心交付：
  1. **重算热路径优化（审核报告 §九 建议 2 / ADR-010 后续待办）**：`SubmitAttemptService.SyncTaskProgressAsync` 从"每次作答全量跨会话重算（O(N²)）"改为 **"增量维护 consumed 集合 + 完成时全量校验"**——每次作答只查本题跨会话 attempts（O(本题尝试数)），Progress 由持久化集合大小派生；任务完成（Progress=100）时触发一次全量重算校验防漂移（保留 ADR-010 决策一"重算天然幂等/抗漂移"优势）。
  2. **消费判定口径不变**（BR-24）：消费 = 该题有 Correct 或尝试数 ≥ MaxAttempts(2)；Progress = 消费题数 / Tasks.QuestionCount × 100；Pending→InProgress（首次推进）；Progress≥100 → Completed + CompletedAt；TaskId=null（个人会话）不推进；Completed 幂等（AllowRedo 重做不改变）。
- 完成定义（DoD）：
  - 后端：全套件 `dotnet test` **383/0/2 基线不降** + 新增增量场景用例（跨会话消费累积 / 幂等不重复推进 / 重做不重复 / 完成时校验重建）全绿。
  - 构建：`dotnet build src/XiaoShuTong.Domain/XiaoShuTong.Domain.csproj` 0 错误。
  - 文档：Business.md 增量修订（BR-24 实现口径补"增量+完成时校验"）+ 变更记录 + 审核报告入档。

### T2：SyncTaskProgressAsync 增量改造（tkwf-service，{Domain}=Learning）

- **描述**：`src/XiaoShuTong.Domain/Services/Learning/SubmitAttemptService.cs`：
  - **签名变更**：`SyncTaskProgressAsync(StudySessions session, long userId, CancellationToken ct)` → `SyncTaskProgressAsync(StudySessions session, long userId, string questionId, CancellationToken ct)`（**QuestionId 全域 string**——Attempts.QuestionId/DOMAIN_MAP 均 string 业务键，非 long；Oracle 闭环#1）；调用点 L234 传 `request.QuestionId`。
  - **保留**：早退豁免（TaskId null/Completed/Pending 定位——BR-05）；`assignment.SessionId = session.Id`；`StartedAt ??= now`。
  - **增量核心（替换 L400-425 全量重算）**：
    1. 解析 `assignment.ConsumedQuestionIds` → `HashSet<string>(StringComparer.Ordinal)`（逗号分隔；异常/空串 → 空集合，对齐 V0.6.0 L415 字符串集合范式）
    2. 跨会话桥接保留（会话数少、代价小）：`taskSessions` → `sessionIds`
    3. **只查本题**（关键优化）：`questionAttempts = AttemptsDs.EntitySelectAsync(a => a.UserId == userId && a.QuestionId == questionId && a.SessionId != null && sessionIds.Contains(a.SessionId.Value))`——含本次已写入（L178-195 在调用点前）
    4. **消费判定（口径不变）**：`if (questionAttempts.Any(a => a.Result == JudgmentResult.Correct) || questionAttempts.Count >= MaxAttempts) consumedSet.Add(questionId);`
    5. `assignment.ConsumedQuestionIds = string.Join(",", consumedSet.OrderBy(x => x, StringComparer.Ordinal))`；`totalCount = task?.QuestionCount ?? consumedSet.Count`；`Progress = Clamp(Round(consumedSet.Count/totalCount*100), 0, 100)`
    6. **状态迁移不变**：Pending→InProgress；`Progress >= 100 → Completed + CompletedAt`（含完成时校验，见下）
  - **完成时全量校验（新增私有方法，Oracle 闭环#4 触发放宽）**：当 `consumedSet.Count >= totalCount - 1`（近完成）时（而非 Progress==100——漂移缺题会使 Progress 永不达 100 而漏触发）：
    - 全量重算（复用 V0.6.0 逻辑：全部 taskSessions → 全部 attempts → GroupBy 判消费）
    - 比对 `consumedSet` 与全量结果：**不一致 → 以全量结果重建集合**（防并发/遗留/增量漂移，保留决策一"抗漂移"）
  - **查询量变化**：每次作答 taskSessions(O(会话，1-3)) + 本题 attempts(O(1-2))——去掉全任务 attempts 全量扫描。
- **涉及文件**：`Services/Learning/SubmitAttemptService.cs`（L234 调用点 + L378-437 方法体）
- **skill 路由**：`tkwf-service` {Domain}=Learning {Entity}=SubmitAttemptService
- **验收**：`dotnet build` 0 错误；全套件测试基线不降；新增用例见 T4。

## 五、关键决策与风险

| # | 决策/风险 | 说明 |
|:-:|----------|------|
| ① | **增量 vs 全量语义边界** | BR-24 判定口径、状态迁移、Completed 幂等**全部不变**——仅实现路径从"每答全量重算"改为"本题增量 + 完成时全量校验"。ADR-010 决策一"重算而非增量"针对的是"Progress += 步进"方案（需回退/易重复推进）；本方案用**持久化集合**（幂等 Contains）+ 完成时全量校验，保留抗漂移优势，属实现优化而非推翻决策。**Oracle 闭环#2：已修订 ADR-010"后续待办+后果"登记本实现路径（非重新决策，是文档同步）** |
| ② | **并发增量丢失（Oracle 闭环#3 修订论证）** | 多会话并发作答同一任务：两写者基于旧集合各自 +1，后写者覆盖丢前写者增量。**论证修订**：不宣称"与 V0.6.0 行为等价"（V0.6.0 全量重算是 Attempts 纯函数零漂移，V0.6.1 持久化集合可漂移）；改为 **"单学生单任务单活动会话 UX 假设下风险可接受"**——产品上同一任务同时有多个活动会话的概率极低（学生逐题作答、会话不并发）；残余风险由完成时全量校验兜底（受限于④）并记入 ADR-010 已知限制。可选增强（本版不做）：TaskAssignments 行版本号乐观并发（检测丢失更新后触发重算）——成本/概率不匹配，登记后续项 |
| ③ | **集合序列化格式** | 逗号分隔排序（`string.Join(",", OrderBy(StringComparer.Ordinal))`），确定性输出便于 Diff 测试断言；StringLength=2000 覆盖 50 题任务（~650 字符）量级 |
| ④ | **完成时校验触发边界（Oracle 闭环#4）** | `Progress >= 100` 才校验 → **若集合漂移（缺题）导致 Progress 卡 <100，校验永不触发**。对策（采用②）：触发条件放宽为 `set.Count >= totalCount - 1`（接近完成即触发全量校验）——漂移缺 1-2 题时仍能发现并重建；同时 §六 DoD 标记该限制为已知项（完全杜绝需周期 Job，成本不匹配，登记后续项） |
| ⑤ | **历史数据兼容** | 存量 assignment.ConsumedQuestionIds 为空串 → 解析为空集合；首次作答后该题达消费即入集合，Progress 从真实派生（与全量重算结果一致，无迁移成本）。**Oracle 闭环#6：T4 补升级兼容测试用例**（空集合 + 预存 attempts → 首次作答 Progress 一致） |
| ⑥ | **Dto/契约零变化** | `[DtoFieldIgnore][JsonIgnore]` 保证 TaskAssignmentsDto、GraphQL/REST、ts-client、AdminWasm/WebH5 契约不受影响——纯后端内部优化。**Oracle 闭环#7：§六 DoD 补 `schema.graphql` diff 为空检查**（防 SG 生成器对 string 字段隐式暴露） |
