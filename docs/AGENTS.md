## 核心规则（简要）

- **版本链**：0-产品规划-V1 → 1-需求分析/V1/ → 2-架构设计/V1/ → 3-开发迭代/子系统/V1/ → 4-部署运维/V1/ → 6-使用指南-V1
- **MinVer 版本**：`V{major}.{minor}.{patch}`，子版本自动递增（V3.1.11→V3.1.12）
- **大版本**：V3→V4 建子目录隔离，旧版不删
- **小版本**：同目录新增文件，命名 `V3.1.11-采集频率优化-开发方案.md`
- **开发方案/审核报告命名**：`V3.1.11-采集频率优化-开发方案.md` / `V3.1.11-采集频率优化-审核报告.md`，中间段是本次版本核心内容简称
- **子系统划分**：A-子系统A / B-子系统B / C-子系统C 为占位，确定子系统后重命名
- **Commit 纪律**：避免频繁，积累后统一提交
- **Tag 纪律**：必须有开发方案 + 审核报告且征得同意，才能打 tag
- **ADR**：不修改，仅状态变更，全局引用
- **草稿→归档**：定稿后拆分到正式目录，原稿移入 `草稿/归档/`
