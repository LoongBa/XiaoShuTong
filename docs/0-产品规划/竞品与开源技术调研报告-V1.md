## 二、memo.cards 线索证伪

**用户线索**："memo.ai 已重定向/更名为 memo.card，前身主攻 PDF 转 Markdown"

**DNS 实测**：
- `memo.card` → DNS 名称不存在（`Resolve-DnsName memo.card -Type A` → "DNS 名称不存在"）
- `memo.ai` → 解析到 GitHub Pages IP（185.199.108.153），返回域名停放页："This domain might not be for sale / Contact: bboyseiok@deepest.ai"

**结论**：memo.card 域名不存在，"memo.ai 重定向到 memo.card"在技术上不可能。线索无法验证，可能是记忆混淆。

**最接近的候选**：
- memocard.org（kubk/memo-card，Telegram 闪卡，145⭐，MIT）——间隔重复+打卡热力图+ChatGPT 管理卡组，**无文档导入、无背诵**
- MemoCards: AI flashcards（iOS，2025 上架）——唯一有 PDF→闪卡的，但仅 5 个评分

## 三、智谱学习搭子调研

**来源**：ai-bot.cn 工具描述、二哥实测文章（GitHub）、aiboss88 新闻

**核心功能**：
- 资料输入：PDF/PPT/云知识库/URL，每项目最多 10 文件/500M
- 四层思维导图：项目标题→章节→核心内容→知识点
- AI 讲解 + **实时可视化演示**（⭐ 最大亮点：交互演示项目，如索引分类/事务隔离/缓存穿透动画）
- 随堂小测：单选/多选，答错给提示
- 知识闪卡：一键生成图片式闪卡（GLM-Image，多种风格）
- 实时问答、进度跟踪、原文对照、共享学习项目、课程认证

**对背诵场景评估**：
- 可视化演示对古诗词/课文**帮助趋近于零**
- 主要面向理解型学习（技术文档/教材），无背诵场景评测
- 知识闪卡是图片式总结，不是传统翻转卡

**借鉴点**：知识闪卡（图片记忆法）、随堂小测（AI 出题）、四层思维导图（知识点整理）
**不借鉴**：实时可视化演示（对背诵无价值）

## 四、Cortex 调研

**仓库**：PndaMan/cortex，30⭐ / 10 forks / 346 commits，Apache-2.0，创建 2026-06-03，活跃至 v1.0.35

**定位**：Local-first NotebookLM 替代品，Tauri 桌面学习 OS

**技术栈**：Tauri 2 + Rust + SQLite + sqlite-vec + Svelte 5 + TypeScript

**核心功能**：文档导入（PDF/PPTX/DOCX/网页/YouTube/音频/图片OCR）→ cheatsheet/闪卡/测验/音频概览/思维导图/带引用聊天

**FSRS 间隔复习**（✅ 确认）：
- 手写 Rust 实现 FSRS-4.5（`repo.rs:2220-2275`，约 60 行纯数学）
- 17 权重，decay -0.5，factor 19/81，retention 0.9
- 迁移历史：0008_srs.sql（SM-2）→ 0016_fsrs.sql（加 stability/difficulty）
- 有单元测试（`srs_fsrs_schedule_progresses_and_lapses`、`fsrs_math_is_sane`）

**GLM 接入**（⚠️ 配置级，非一等公民）：
- 全库搜索 `zhipu|glm|智谱|bigmodel` = 0 命中
- 但有 `custom` OpenAI 兼容端点 provider（`llm.rs:494-502`）
- Issue #4 正是 custom 端点连接失败（有已知 bug）

**背诵场景**：❌ 全库搜索 `recit|背诵|chant|memoriz` = 0 命中

**借鉴价值**：
- ✅ FSRS-4.5 算法（60 行可移植到 JS）——但等价于直接用 `ts-fsrs`/`py-fsrs`（MIT）
- ✅ 闪卡生成 prompt 约束（"短答案+加粗关键词"，对背诵卡适用）
- ❌ 应用本体不集成（Tauri 桌面端，与小程序零代码复用）

## 五、DeepTutor 调研

**仓库**：HKUDS/DeepTutor，38.7k⭐ / 4.9k forks，Apache-2.0，创建 2025-12-28，最新 v1.6.4（2026-09-02）

**论文**：arXiv:2604.26962 "DeepTutor: Towards Agentic Personalized Tutoring"

**核心能力**：Chat Agent Loop + Partners（SOUL.md 人格 + IM 通道）+ Memory 三层（L1 trace / L2 curated / L3 synthesis）+ Mastery Path + Immersive Reading + Question Bank + Book typed blocks + Multi-Engine RAG + Guardian 角色

**zhipu GLM 适配器**（✅ 实证原生内置）：
- `provider_registry.py`：`ProviderSpec(name="zhipu", env_key="ZAI_API_KEY", backend="openai_compat", default_api_base="https://open.bigmodel.cn/api/paas/v4")`
- `init_wizard.py`：`LLM_FALLBACK_MODELS["zhipu"] = ("glm-4.6", "glm-4.5", "glm-4-flash")`
- 搜索 provider：`zhipu.py`，四档引擎（search_std/search_pro/search_pro_sogou/search_pro_quark）
- 原生工具调用：v1.4.11 起支持 native function calling
- 端点在国内（open.bigmodel.cn），无需翻墙

**借鉴价值**：
- ✅ Learner Profile 字段设计（age/grade/curriculum/reading_level/explanation_style）
- ✅ Question Bank 三元组（你的答案/参考答案/解释）——与判题契约 matched/missing/hint 异曲同工
- ✅ Guardian 家长角色——直接对标小书童家长端
- ✅ Memory 三层可审计——与小书童 memory_states + attempts 方向一致
- ⚠️ 重框架，MVP 不引入；阶段二可评估 CLI 局部集成

## 六、班级小管家调研（市场威胁）

**来源**：官网 banjixiaoguanjia.com、百度百科、百度知道教程、App Store

**基本盘**：2017 年上线，累计注册近 5000 万，400 万+老师，4000 万+学生，10 万+学校。教育类小程序长期第一。

**功能全景**（16+ 模块）：家校沟通/作业管理/打卡统计/接龙问卷/在线测验/成绩发布/班级网盘/亲属绑定/跟读听写/万能工具箱/红花点评/班级缴费/AI 错题本/口语诊断/智能手环

**对"背诵"场景覆盖**（关键发现）：

| 维度 | 班级小管家 | 小书童缝隙 |
|------|-----------|----------|
| 背诵任务 | "每日阅读"打卡模板（需老师手动改造） | 专用背书任务 |
| 逐字判背诵 | ❌ 无 AI 比对 | ✅ 三层判题引擎 |
| 记忆曲线 | ❌ 无间隔复习 | ✅ FSRS 调度 |
| 质量评估 | 只统计"发了/读了" | ✅ 判题结果驱动记忆状态 |
| 学生激励 | 学生被动接收 | ✅ PK/连胜/★（努力度排名） |
| AI 能力 | 错题本/口语/手环（功能点拼凑，广度扩张） | 深度深耕背书 |

**关键事实**：班级小管家的"跟读"是朗读（照着读），不是背诵（脱稿背）。

**商业模式**：教师端永久免费（官网第一屏"不收费"），家长端有广告+会员。盈利靠企业定制开发。

**合规教训**：
- 班级优化大师 2023 年"付费看排名"被新华社曝光 → 小书童报告不含班级成绩排名
- 班级小管家 2025 年老师发起 150 元收款被教育局责令退款 → 小书童不碰班级收款
- 晓黑板 8000 万用户 2022 年停服 → 纯家校沟通商业模式不成立

**手环**：智能手环体质监测——实质是"校内终端替代"（学校不让带手机）+ 硬件变现，与学习价值无关。

## 七、闪卡调研结论

**来源**：Anki 官方手册、FSRS 文档、间隔重复研究（Cepeda 2006 元分析、Roediger & Karpicke 2006 testing effect、Slamecka & Graf 1978 generation effect）

**结论**：**闪卡不是必要的独立功能，已被 R1/R2 覆盖且被超越。**

| 维度 | 闪卡（识别型） | R1/R2（生成型） |
|------|--------------|----------------|
| 记忆效果 | 中等 | **更强**（Generation Effect, d≈0.5-0.8） |
| 机制 | 翻转看答案（存在"熟悉感错觉"） | 主动产出答案 |
| 与艾宾浩斯兼容 | 是 | 是 |

**建议**：
1. 不新增闪卡题型——R1 已覆盖闪卡 90% 场景且更强
2. R4 知识卡片已承担"参考/识别"角色
3. 可选增强：R1 题内加"显示答案"按钮（降级识别模式）
4. 真正值得投入：FSRS 替代固定间隔（ROI 更高）

## 八·补、AI Agent 编写 uni-app 成熟度调研（支撑 ADR-007）

> 调研背景：《ADR-007 技术栈分端调整》以"AI agent 开发模式"为核心约束，选择 React + shadcn/ui 替代 uni-app。本调研取证验证该决策。

### 结论：uni-app AI 生成成熟度 = 中等；React + shadcn = 高

| 维度 | uni-app | React + shadcn/ui |
|------|---------|-------------------|
| AI 训练语料量 | ⚠️ 41.6K⭐ / 3.6 万周下载 | ✅ 249K⭐ / **1.44 亿**周下载（4030 倍） |
| AI 默认偏好 | ❌ **AI 默认生成 React**（官方承认"北美技术偏好"） | ✅ AI 原生偏好 |
| 幻觉风险 | ⚠️ 需显式提示锁定技术栈 | ✅ 低 |
| 官方 AI 工具 | ✅ uni-agent / AI Rules / MCP（2026 大规模投入） | ✅ shadcn 为 AI 设计 |

### 关键证据：DCloud 官方承认 AI 偏 React

**DCloud 官方"Vibe Coding 最佳实践"文档原文**：
> "AI 存在'北美技术偏好'（训练数据主要源于英语互联网），默认倾向生成：前端 React 体系代码、后端 Java/PHP 等传统技术栈"

**官方提供的"锁定 uni-app"提示词**（强制让 AI 不写错）：
> "你作为一位精通 Vue 3 组合式 API 的资深 uni-app 跨平台应用开发专家，在开发过程中需兼顾 H5、小程序、App 多端兼容性，通过 `#ifdef` 和 `#endif` 条件编译处理平台差异……"

**这直接证明**：AI 默认不会写 uni-app，需要显式提示 + AI Rules + MCP（easycom 组件发现）才能降低幻觉——而其幻觉集中区恰是 #ifdef 条件编译、Vue2/Vue3 混用、uni.* vs wx.* 混淆。

### 语料量实证（GitHub API 实测）

| 项目 | GitHub Stars | npm 周下载 |
|------|-------------|-----------|
| React | 249,074 | 144,782,763 |
| shadcn/ui | 123,030 | — |
| uni-app | 41,599 | 35,926 |
| Taro | 37,665 | 22,259 |

### 对 ADR-007 的支撑

"H5 先用 React、小程序延后 Taro 接续"策略**获强支撑**：
1. React 语料是 uni-app 的 6 倍（Stars）/ 4030 倍（npm）——AI 生成质量差距悬殊
2. **AI 默认偏好 React**（DCloud 亲口承认）——React 是 AI 的"母语"，uni-app 需强制纠偏
3. shadcn/ui 的注册表 + CLI 格式天然为 AI 生成优化
4. Taro（React 阵营，37.7K⭐）为未来小程序迁移保留低成本路径
5. 若未来必须 uni-app，DCloud 的 uni-agent/AI Rules/MCP 工具链已成熟（风险缓和）

**来源**：uniapp.dcloud.net.cn/ai/（AI 专题）、vibe-partner.html（官方承认 AI 偏 React）、doc.dcloud.net.cn/uni-app-x/tutorial/rules_mcp.html、GitHub API stars、npm 周下载量
