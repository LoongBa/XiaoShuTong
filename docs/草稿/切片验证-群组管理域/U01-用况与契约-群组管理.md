## UC-6.1：激活建群（群主凭内测邀请码）

**对应场景**：S01-6.1 → 步骤 1~4
**对应 UI 图**：beta-invite#1~6
**子域**：`Groups`
**事务范围**：CROSS（写 Groups + 标记 BetaInviteCodes used）
**事务策略说明**：群组创建与码标记必须同生共死，任一步失败全部回滚，防止码被占用但群组未建
**故障容忍度**：Required
**权限要求**：`owner`
**关联 R 功能点**：R01-6.1
**API 路由**：`POST /api/v1/groups`

---

### [场景层] — 给 UI/验收看

#### Precondition（进入条件）
1. 用户已登录且角色为群主（Role=owner）
2. 已持有平台发放的内测邀请码

#### Main Flow（主流程）
1. 群主输入内测邀请码 → 系统校验码有效（未使用/未过期）→ 页面校验中态
2. 校验通过 → 群主填写群组名称/学科/年级 → 提交创建
3. 系统创建群组（OwnerId=当前群主）→ 码标记 used → 成功 Toast

#### Alternative Flow（替代流程）
- 2a. 内测码无效/已使用/已过期 → 提示「邀请码无效，请核对后重试」/「邀请码已过期」→ 停留当前页（BR-01，错误码 5201）
- 2b. 内测未开放（平台开关关闭）→ 提示内测未开放 → 停留当前页（BR-05，错误码 5205）
- 2c. 群组名称/学科缺失或超长 → 字段校验提示 → 停留当前页（BR-03，错误码 1002）

#### Postcondition（完成后状态）
- 数据：Groups 已写入；BetaInviteCodes.Status=Used、UsedByGroupId 落库
- 页面：跳转群组管理页 / 状态卡显示已激活群组

## UC-6.6：名单 Agent 整理（BackgroundJob）

**调度规则**：名单导入成功后异步触发
**事务范围**：SINGLE（逐批次更新）
**故障容忍度**：Optional（单批失败记录，不中断）

## UC-6.10：成员凭码激活加入群组

**对应场景**：S01-6.3 → 步骤 1~3
**对应 UI 图**：activate#1~7
**子域**：`Groups`
**事务范围**：CROSS（写 GroupMembers + 绑定码 + 标记 used）
**事务策略说明**：成员写入与码状态更新须原子
**故障容忍度**：Required
**权限要求**：已登录（成员，Role 由名单预设 student/parent）
**关联 R 功能点**：R01-6.9
**API 路由**：`POST /api/v1/beta/activate`

### [场景层]

#### Precondition
1. 微信已授权（OpenId 已建 Users 行）
2. 持有一次性邀请码 + 手机号后四位

#### Main Flow
1. 成员输入 8 位一次性码 + 4 位手机号后四位 → 点击激活
2. 系统校验码有效（未使用/未过期）→ 校验后四位与名单一致 → 绑定微信 ID
3. 系统写入 GroupMembers（Role 由名单预设，InviteCodeId 溯源）→ 码置 used
4. 激活成功 → 进入对应身份首页

#### Alternative Flow
- 2a. 码无效 → 提示「邀请码无效」（BR-26，5202）
- 2b. 码已使用 → 提示「已被使用，请联系群主」（BR-27，5202）
- 2c. 码已过期 → 提示「已过期，请联系群主」（BR-28，5202）
- 2d. 后四位不匹配 → 提示「手机号后四位与名单不符」（BR-29，5203）
- 2e. 内测未开放 → 5205（BR-05）

#### Postcondition
- 数据：GroupMembers 写入；OneTimeInviteCodes.Status=Used、BoundUserId 落库
- 页面：进入学生/家长首页
