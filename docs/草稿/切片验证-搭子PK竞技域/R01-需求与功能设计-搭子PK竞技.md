# 模块 9：搭子 PK 竞技

## 模块描述

学生与**互为 accepted 的搭子**之间进行同题同序的背诵 PK 竞技：发起/加入对战（方式 A 选对手 / 方式 B 对战码）、每题 30s 倒计时即时判分、AI 趣味点评结果页、胜场计入战力榜。核心理念：**好友之间比坚持**（比背诵速度与数量），而非陌生榜单；PK 结果只展示★数/用时，**不出现正确率对比榜**（合规红线）。SignalR 实时同步，微信 H5 降级 30s 轮询。

---

### 9.1 发起 PK（方式 A：选对手）

#### 功能描述

学生从搭子列表选择对手，设置对战范围（学科/题库/题量）发起 PK，对手确认后开局。

#### 操作描述

1. 学生进入 PK 大厅，点"发起挑战" → 从搭子列表选对手
2. 选学科/题库范围 + 题量（默认 10，可选 5/10/20）+ 模式
3. 系统校验互为 accepted 搭子 → 创建对局（pending）→ 生成 4 位对战码
4. 对手收到挑战/对战码 → 确认 → 双方就绪开局

#### 约束条件

- **前置资格：仅互为 accepted 搭子可发起 PK**（非搭子 → 2005/6004 拦截）
- 题量默认 10（可配 5/10/20）；模式默认 sync（同步），微信 H5 不可用 WS 时降级 async
- 创建对局即生成 4 位对战码（InviteCode，供方式 B 加入）
- 对局状态 pending（等待对手确认）

---

### 9.2 加入 PK（方式 B：对战码）

#### 功能描述

学生通过搭子分享的 4 位对战码加入对局，或接受挑战邀请。

#### 操作描述

1. 学生输入 4 位对战码（或点挑战确认）
2. 系统校验对局存在/未满员 + 与发起者为 accepted 搭子
3. 加入成功 → 返回对局配置（题量/每题时长/模式）→ 双方就绪开局

#### 约束条件

- 对战码 4 位（字母+数字）；对局不存在 → 2001
- 对局已结束/不可加入 → 2002；参赛人数已满 → 2003
- 加入者与发起者必须是 accepted 搭子（2005）
- 对战码有效期与复用规则本切片定义（**D02/D03 未定义**，见缺口决策）

---

### 9.3 对战进行（同题同序 + 即时判分）

#### 功能描述

双方就绪后，系统同步出题（同题同序），每题 30s 倒计时，答对 +10 即时反馈，自动下一题。

#### 操作描述

1. 系统取当前题（同题同序：双方同一题同一顺序）→ 下发题目（不含答案）
2. 学生 30s 内作答提交 → 判题引擎即时判定（走判题服务）→ 答对 +10
3. 答对/超时即时反馈 → 自动下一题；重复至题量结束
4. 同分时比总用时；仍相同 → 平局

#### 约束条件

- 每题 30s 倒计时（视觉红条）；答对 +10、答错/超时 0 分
- **同题同序**（双方公平）；自动下一题
- **PK 数据场景隔离**：答题入 PkAttempts（不入 Attempts/不动 MemoryStates，state_coupling=isolated）
- **timeCostMs 客户端上送**（PK 需以用时决胜，与主判题接口服务端计时不同）
- 判题走判题引擎五键契约；部分正确（partial）计分规则**源未定义**（本切片决策，见缺口决策）
- 总时长上限（10 题 × 30s + 缓冲 = 5 分钟），超时未答完按已答计分

---

### 9.4 对手掉线 / 弃权处理（后台）

#### 功能描述

对战任一方离线时，按规则处理：对手离线 30s 判弃权（本方可直接获胜），或断线重连保留进度。

#### 操作描述

1. 玩家网络断开 → 尝试断线重连（进度保留）
2. 对手离线 30s → 系统判弃权（forfeit）→ 本方可获胜或结束
3. PK 中网络断开 → 断线重连，进度保留；重连失败按离线处理

#### 约束条件

- 对手离线 30s → 判弃权（FinishReason=forfeit），己方获胜
- PK 中网络断开 → 断线重连进度保留；重连失败按离线处理
- 掉线判定机制（30s 检测）与弃权写库时机需本切片定义（**D02/D03 仅语义，无作业定义**，见缺口决策）
- 弃权/超时结束的 Status 取值需对齐 PkPlayerStats 视图过滤（**决策：置 finished**，见缺口决策）

### 9.5 PK 结果与 AI 点评

#### 功能描述

对局结束后展示胜/负/平 + 双方得分 + AI 趣味点评（个性亮点/薄弱点/知识彩蛋），胜方庆祝动画；胜场计入战力榜。

#### 操作描述

1. 对局结束（score/forfeit/timeout）→ 系统判定胜负（WinnerId，NULL=平局）→ 写入 FinishReason
2. 系统生成 AI 趣味点评（LLM，独立 Prompt：趣味点评-Prompt.md）→ 写入每位玩家 AiComment
3. 结果页展示：胜负 + 双方得分 + AI 点评 + 知识彩蛋
4. 胜场经 PkPlayerStats 视图聚合计入战力榜（RankSnapshots 次日冻结）

#### 约束条件

- 胜负由 PkMatches.WinnerId 判定（NULL=平局）；结束原因 FinishReason（score/forfeit/timeout）
- **合规红线：PK 结果只展示★数/用时，不出现正确率对比榜**
- AI 趣味点评三要素：个性亮点/薄弱点/知识彩蛋；LLM 失败时 AiComment 留空或兜底文案（**生成失败降级需定义**，见缺口决策）
- 知识彩蛋（knowledgeEggs）为响应态展示，**不落库**
- PK 胜场计入战力榜排名指标（跨模块，模块 7 消费）

---

### 9.6 PK 战绩

#### 功能描述

学生查看个人 PK 历史战绩（总场数/胜/平/胜率/累计分）与待加入对战列表。

#### 操作描述

1. 学生进入 PK 大厅查看"我的战绩"
2. 系统按 PkPlayerStats 视图聚合返回战绩

#### 约束条件

- 战绩 = PkPlayerStats 视图聚合（TotalMatches/Wins/Draws/TotalScore/AvgTimeMs）；胜率在 API 层计算（视图无胜率列）
- 大厅"我的战绩"不展示分数榜（合规）
