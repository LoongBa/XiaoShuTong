# 题型与交互设计规范 V0.1

> 小书童题型与交互的**策略层**设计规范。
> 与《题库建设规范 V1.1》互补：V1.1 管"内容生产"（四件套交付），本规范管"判题与交互策略"（题目级属性路由）。
> 版本：V0.1（2026-09-05 草稿）
> 状态：草稿
> 关联：题库建设规范 V1.1 §七、ADR-002/003/004/005、D01 §8.4、V3 二/三

---

## 一、设计目标

V1.1 的题型注册表已将 `grading`（判题路由：rule/hybrid/llm）与 `interaction`（交互：text_input/single_select...）绑定在**题型**上（R1/O1...）。本规范将其提升为**题目级可覆盖字段**，实现四项目标：

1. **判题策略与题型解耦**：同一知识点可衍生"语音背诵/填空默写/选择作者/排序诗句"多题型，每题独立标记 `judging_strategy` 与 `interaction_type`。
2. **AI 判题作为核心差异化**：从"对/错"二元升级为"引导式反馈"（哪里对了/漏了/可补充），每次判题是一次学习机会。
3. **语音输入作为背诵首选交互**：语音→文字→相似度初筛→AI 兜底链路优化。
4. **PK 模式与趣味题作为用户增长引擎**：社交传播与亲子互动入口，非锦上添花。

---

## 二、三维解耦模型（核心）

### 2.1 三个正交维度

| 维度 | 字段 | 取值 | 绑定层级 | 说明 |
|------|------|------|---------|------|
| 知识点 | `knowledge_points` | — | 题目级 | 不变（V1.1 已有） |
| 判题策略 | `judging_strategy` | exact / similarity / ai_guided / hybrid | 题型级默认 + 题目级覆盖 | 控制引擎内部匹配算法 |
| 交互类型 | `interaction_type` | voice / text / select / drag / swipe / card | 题型级默认 + 题目级覆盖 | 控制前端交互组件 |

### 2.2 与 V1.1 题型注册表的关系（演进而非重写）

V1.1 题型注册表已有 `grading`（路由层：决定走哪个引擎）和 `interaction`（交互层）。本规范**不废弃**这两个字段，而是：

- `grading` → 保留为**路由层**（rule_grader / keyword / LLM 三个引擎选谁）
- `judging_strategy` → 新增为**算法层**（引擎内部用什么匹配：exact / similarity / ai_guided）
- `interaction` → 重命名为 `interaction_type`，提升为题目级可覆盖

```
判题链路：grading（路由）→ judging_strategy（算法）→ interaction_type（交互）
         题型级默认     题型级默认+题目级覆盖    题型级默认+题目级覆盖
```

> **覆盖优先级**（对齐 V1.1 §七.2）：单题级 > 题型级 > 题库级 > 学科级 > 全局默认

### 2.3 question.v1.json 扩展（向后兼容）

在 `content` 下新增两个可选字段（已有 `tolerance` 字段保留）：

```json
{
  "content": {
    "judging_strategy": "ai_guided",
    "interaction_type": "voice"
  }
}
```

缺省时从题型注册表 `grading` + `interaction` 推导，保证现有题库零迁移。

## 三、判题策略分类（judging_strategy）

| 策略 | 匹配算法 | 适用场景 | 成本 | 对应现有 grading |
|------|---------|---------|------|-----------------|
| `exact` | 字符精确比对（含全半角规范化、变体映射） | 选择/判断/连线/标准化填空 | 零 | rule |
| `similarity` | 关键词同义词组命中率（V1.1 已实现）+ 字符相似度（编辑距离/Jaccard） | 语文默写/英语拼写/历史年代 | 零 | hybrid 的第一层 |
| `ai_guided` | LLM 语义判题 + 引导式反馈 | 历史/地理/道法开放问答、语音误差兜底 | LLM 调用 | llm |
| `hybrid` | similarity 初筛 → 阈值不达 → ai_guided 兜底 | 默认推荐策略（成本与准确率平衡） | 部分拦截 | hybrid |

**阈值设计**（对齐 ADR-003 三层路由）：

```
similarity 命中率 ≥0.85 → correct（不调 LLM）
similarity 命中率 0.60-0.85 → partial（不调 LLM）
similarity 命中率 <0.60 → 进入 ai_guided
ai_guided 超时(>3s)/失败 → 降级 similarity + 标记"判题降级"
```

> `hybrid` = `similarity` 初筛 + `ai_guided` 兜底，是 `grading=hybrid` 的算法层细化。

## 四、交互类型分类（interaction_type）

| 交互类型 | 前端组件 | 输入数据 | 典型题型 | 设计依据 |
|---------|---------|---------|---------|---------|
| `voice` | 语音按钮 + 二次确认输入框 | 语音→文字（系统输入法 ASR） | R1/R2/R3a/R3b 背诵 | 背诵本身是"说"，符合自然习惯 |
| `text` | 文本输入框 | 字符串 | O5 填空/X1 简答/X2 论述 | 标准化答案、打字场景 |
| `select` | 单选/多选/判断按钮 | 选项标识（A/B/对/错） | O1/O2/O3 | 触摸点选、碎片时间 |
| `drag` | 拖拽连线/排序组件 | 配对/序列数据 | O4 连线/排序题 | 拖动线条连接端点 |
| `swipe` | 左右滑动卡片 | 方向 | 知识卡片翻阅/判断 | 单手操作、低认知负荷 |
| `card` | 展示型卡片 | 无输入 | R4 知识卡片 | 纯展示 |

**交互选择原则**：
- 背诵类（R 系列）首选 `voice`，降级 `text`
- 客观题（O 系列）固定 `select`/`drag`
- 开放问答（X 系列）首选 `text`，长文用 `text_area`
- 同一知识点可配置多种 `interaction_type` 衍生多题型（如《静夜思》既可 `voice` 背诵，也可 `select` 选作者）

## 五、题型 × 判题策略组合矩阵

| 题型 | 默认 judging_strategy | 可选 interaction_type | 说明 |
|------|----------------------|---------------------|------|
| R1 补全记忆 | hybrid | voice / text | 语音首选，文本降级 |
| R2 逆向补全 | hybrid | voice / text | 同 R1 |
| R3a 段落默写 | hybrid | voice / text | 长文可分段语音 |
| R3b 整篇默写 | hybrid | voice / text | 整篇语音（挑战大，容错宽） |
| R4 知识卡片 | display_only | card | 无判题 |
| O1 单选 | exact | select | — |
| O2 多选 | exact | select | — |
| O3 判断 | exact | select | — |
| O4 连线 | exact | drag | 拖拽连接 |
| O5 填空 | hybrid | text / voice | 语音填空（口述关键词） |
| X1 简答 | ai_guided | text | 开放问答必走 AI |
| X2 论述 | ai_guided | text_area | — |
| X3 计算 | rule_llm | text | 步骤评分 |

**学科级默认覆盖**（对齐学科注册表 `gradingPreference`）：

| 学科 | 默认 judging_strategy | 理由 |
|------|----------------------|------|
| 语文 | hybrid（similarity 为主） | 古诗文容错，关键词命中率通常 ≥85% |
| 英语 | hybrid（spelling_tolerant） | 拼写宽容 |
| 历史/地理/生物/化学 | exact → ai_guided | 事实性 exact，开放性 ai_guided |
| 道德与法治 | ai_guided | 开放性问答为主，相似度判题致挫败 |
| 数学/物理 | exact / rule_llm | 计算/公式精确 |

> 道法、历史开放性问答必须用 `ai_guided`——相似度判题会导致"答了意思对但表述不同"被判错，挫败感强。

## 六、交互设计原则

### 6.1 语音交互（voice）

**链路**：用户语音 → 系统输入法 ASR → 文字 → 二次确认 → 提交判题

**原则**：
1. **强制系统语音输入法**（V3 已决策）：禁用浏览器 MediaRecorder ASR，避免平台碎片化
2. **二次确认必选**：语音转文字后展示可编辑文本，用户微调后再提交（处理口癖/结巴/识别误差）
3. **分段语音**：长文（R3a/R3b）支持分段录制，逐段拼接判题
4. **容错放宽**：语音路径的 similarity 阈值可比文本路径低 0.05（容忍 ASR 误差）
5. **降级路径**：系统无语音输入法 → 降级 `text` 交互，不阻塞背诵

### 6.2 文本交互（text）

**原则**：
1. 标准化答案用 `text`（O5 填空、X1 简答）
2. 支持模糊匹配（同义词、顺序变体）——已由 V1.1 keywords 同义词组实现
3. 长文用 `text_area`（X2 论述）

### 6.3 触摸交互（select / drag / swipe）

**原则**：
1. 不需要语音或打字，直接点选——碎片时间友好
2. 连线题（O4）用 `drag`：拖拽线条连接端点，支持部分给分
3. 排序题（如诗句排序）用 `drag`：拖动重排
4. 知识卡片翻阅用 `swipe`：左右滑动，低认知负荷

## 七、AI 引导式判题 Prompt 设计要点

> 现有 `通用判题-Prompt.md` 已是引导式反馈基线。本节提炼设计要点，供新 Prompt 编写校准。

### 7.1 引导式反馈的三层结构

每次判题输出不仅是 `result`，更是**一次学习机会**：

| 层 | 字段 | 作用 |
|----|------|------|
| 判定层 | `result` + `confidence` | 正确/部分/错误 + 置信度 |
| 诊断层 | `matched_keywords` + `missing_keywords` | 哪里对了、哪里漏了 |
| 引导层 | `hint` | 哪里可以补充（≤20 字线索，不给答案） |

### 7.2 Prompt 设计要点

1. **角色固定**：AI 导师（陪读老师），非判官——"耐心、善于引导"
2. **严禁直接给答案**：hint 只能提供首字/意象/逻辑线索，≤20 字
3. **三元结果**：correct/partial/wrong，partial 是核心创新（"部分对了"比"错了"更激励）
4. **容错维度**：语义等价（"唐太宗"="李世民"）、顺序微调、标点差异、口语化表述
5. **hint_level 联动**：`partial`（求助后答对）时 hint 必须给引导，判题可适当放宽
6. **内容准确性边界**：AI 只判题不给新知识点解释，避免幻觉污染学习内容
7. **输出严格 JSON**：禁止输出其他文字，上层代码只写一份解析逻辑

### 7.3 AI 判题为默认策略的学科（ai_guided）

- **道法/历史开放问答**：相似度判题致挫败，必须 AI 引导
- **地理成因分析**：开放性表述，AI 判语义
- **语文名句理解/赏析**：主观性，AI 判语义正确性

## 八、语音输入链路与误差处理

### 8.1 完整链路

```
用户语音
  ↓ 系统输入法 ASR（强制，禁用浏览器 ASR）
原始文字（可能含口癖/结巴/识别误差）
  ↓ 文本规范化（去语气词、去重复、繁简统一、标点规范化）
规范化文字
  ↓ 二次确认（用户可手动微调）
确认文字
  ↓ similarity 初筛（关键词命中率 + 字符相似度）
  ├─ ≥0.85 → correct（不调 LLM）
  ├─ 0.60-0.85 → partial（不调 LLM）
  └─ <0.60 → ai_guided 兜底（带语音误差提示）
```

### 8.2 语音容错阈值设计

| 阈值 | 文本路径 | 语音路径 | 说明 |
|------|---------|---------|------|
| correct | ≥0.85 | ≥0.80 | 语音降 0.05，容忍 ASR 误差 |
| partial | 0.60-0.85 | 0.55-0.80 | 同步降 0.05 |
| LLM 兜底 | <0.60 | <0.55 | — |

### 8.3 语音误差处理策略

1. **语气词去除**：规范化阶段去除"嗯/啊/那个/然后"等
2. **结巴去重**："床床床前明月光" → "床前明月光"
3. **同音字容错**：交由 ai_guided 处理（如"疑问"="疑是"）
4. **分段判题**：长文分段录制，逐段判题后合并结果
5. **ASR 置信度透传**：若系统 ASR 返回低置信度，直接走 ai_guided（跳过 similarity）

## 九、PK 模式设计

> ADR-005 已定稿"并行 PK + 异步回合制备选"。本节补充用户洞察的"抢答"与"轮流出题"模式。

### 9.1 三种 PK 模式

| 模式 | 机制 | 实现难度 | 适用场景 | 状态 |
|------|------|---------|---------|------|
| **并行 PK** | 各做各的，最后比正确率+用时 | 低（已定稿） | 日常、异步 | P1a PoC |
| **抢答 PK** | 同一题目，谁先答对谁得分 | 高（需实时同步） | 实时对战 | P2（依赖 WS） |
| **轮流出题** | A 出题→B 答→B 出题→A 答 | 中（出题质量管控） | 亲子/同学互动 | P2 评估 |

### 9.2 并行 PK（已定稿，ADR-005）

- 系统统一出题，双方同题同序作答
- 同步实时（WS）/ 异步回合制（H5 降级）
- 胜负：总分 → 用时 → 平局
- AI 趣味点评（`趣味点评-Prompt.md`）
- `state_coupling=isolated`（不污染记忆状态）

### 9.3 抢答 PK（P2）

- 同一题目同时展示，谁先提交正确答案谁得分
- **技术依赖**：WebSocket 实时同步（ADR-005 已指出 H5 X5 内核 WS 风险）
- **降级**：WS 不可用时降级为并行 PK（各做各的）
- **交互**：`select`/`drag` 为主（抢答需快速点选，不适合语音/打字）

### 9.4 轮流出题（P2 评估）

- A 从题库选题 → B 答 → B 选题 → A 答
- **核心挑战**：出题质量不可控（ADR-005 已指出互考模式此问题）
- **缓解方案**：A 从**系统题库**选题（非自创题），保证质量
- **适用**：亲子互动（家长选题孩子答）、同学互动
- **与互考区别**：互考是 A 自创题，轮流出题是 A 从系统题库选题

## 十、趣味题战略定位（用户增长引擎）

> 趣味题不是"锦上添花"，而是**用户增长引擎**。

### 10.1 三大战略作用

| 作用 | 说明 | 落地 |
|------|------|------|
| 课后趣味练习 | 正课之外的调剂，降低疲劳 | 趣味题库（独立 purpose_tag=play） |
| PK 竞赛暖场题 | 降低 PK 门槛，新手友好 | PK 出题池混入趣味题 |
| 复习调剂题 | 长周期复习中的趣味锚点 | 复习队列按比例插入 |

### 10.2 社交传播与亲子互动

- **社交传播**：趣味题（如"古人朋友圈""诗词接龙挑战"）天然适合分享，为应用宣传铺路
- **亲子互动**：家长用轮流出题模式陪孩子背诵，趣味题降低家长参与门槛
- **增长飞轮**：趣味题 → 社交传播 → 新用户 → 背记核心 → 复习 → 趣味调剂 → 再传播

### 10.3 趣味题的判题策略

- 趣味题以 O 系列（客观题）为主，走 `exact` 判题（零成本）
- 趣味点评走独立 `趣味点评-Prompt.md`（非判题）
- `purpose_tag=play` 的题目 `state_coupling=isolated`（不影响记忆状态）

| 学科注册表 gradingPreference | 映射为学科级默认 judging_strategy | 一一对应 |

### 11.2 与四件套结构衔接

| 四件套 | 本规范衔接 |
|--------|----------|
| 篇目清单（L0） | 不变 |
| 背诵内容（L1） | 不变（问题###答案） |
| 背诵训练（L2） | S1-S4 题目可标记 `interaction_type=voice`（默认）或 `text`（降级） |
| 背景钩子（L3） | 不变（"请提示我"交互由 hint_level 联动） |

### 11.3 与四阶记忆状态机衔接（ADR-004）

`interaction_type` 与 `judging_strategy` **不改变**状态机迁移规则，只影响**判题链路**：

```
用户作答（按 interaction_type 采集）
  ↓ judging_strategy 路由判题
  ↓ 输出 result + hint_level
  ↓ ADR-004 状态机按 hint_level × result 迁移
✕△○★ 状态更新
```

- `voice`/`text`/`select` 只是输入方式不同，判题结果格式统一
- PK 场景 `state_coupling=isolated`（趣味题不影响状态机，ADR-004 已定）
- 语音路径的容错放宽（阈值降 0.05）不影响状态机——状态机只看 `result`，不看阈值

## 十二、判题引擎升级建议

### 12.1 rule_grader.py 扩展路径

现有 rule_grader.py 处理 O1-O5（exact 类）。扩展方向：

1. **新增 similarity 引擎**（`similarity_grader.py`）：
   - 复用现有 `_keyword_hit_ratio`（O5 已实现同义词组+权重+required）
   - 新增字符相似度（编辑距离/Jaccard），取 max(关键词命中率, 字符相似度)
   - 输入规范化复用现有 `_norm`

2. **新增 ai_grader.py**（LLM 调用层）：
   - 加载判题 Prompt（按绑定优先级：单题级 > 题型级 > 题库级 > 全局默认）
   - 调用 LLM API
   - 解析统一 JSON 契约（result/confidence/matched/missing/hint）
   - 超时(>3s)/失败降级到 similarity_grader

3. **统一路由入口**（`grade()` 扩展）：
   - 按 `judging_strategy` 路由（exact → similarity → ai_guided → hybrid）
   - hybrid = similarity 初筛 + ai 兜底（对齐 ADR-003 三层路由）

4. **语音容错**：
   - 新增 `voice_normalize()`（去语气词、去重、繁简统一）
   - 语音路径阈值降 0.05（配置化，写入 `grading_config`）

### 12.2 引擎扩展不破坏现有测试

- 现有 `_GRADERS` 字典（O1-O5）不变
- 新增 `_SIMILARITY_GRADERS` 和 `_AI_GRADERS` 字典
- `grade()` 入口按 `judging_strategy` 优先路由，缺省从 `type` 推导（兼容现有题目无 judging_strategy 字段的情况）

### 12.3 AI 判题 Prompt 设计（引导式反馈）

对齐 §七 要点，新 Prompt 编写校准清单：
- [ ] 角色固定为 AI 导师
- [ ] hint ≤20 字，不给答案
- [ ] 三元结果（correct/partial/wrong）
- [ ] 容错维度（语义等价/顺序/标点/口语化）
- [ ] hint_level 联动（none/partial/full）
- [ ] 输出严格 JSON
- [ ] 绑定 50-500 题测试集校准（目标 ≥95%）

### 12.4 语音相似度阈值设计

| 路径 | correct | partial | LLM 兜底 |
|------|---------|---------|----------|
| 文本 | ≥0.85 | 0.60-0.85 | <0.60 |
| 语音 | ≥0.80 | 0.55-0.80 | <0.55 |

- 阈值配置化（`grading_config` 里可覆盖）
- 上线前用 500 题测试集校准（对齐 V3 决策 4）
