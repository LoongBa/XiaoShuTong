## VEntity 设计规格（tkwf-ventity-design 产出，2026-09-07）

> 输入：S01 定稿场景 + UI 热力图/统计页字段来源 + R/S 查询需求。结论：**本切片 4 个查询场景均不建 VEntity**（依据 skill 决策表 + 切片验证约束），查询契约要素供 U01 引用。

### 查询场景全局清单

| 页面 | 查询字段 | 来源表 | 聚合口径 | 跨表 | 判定 |
|------|---------|--------|---------|:----:|------|
| 热力图 | Date / StarredCount / LearnedCount | Learning.DailyStats | 按日（切片 02 写入时已聚合） | 否 | Service 单表查询 |
| 连续天数 | StatDate 序列 → 当前/最长连击 | Learning.DailyStats | 日期连续性派生（业务逻辑） | 否 | Service 派生计算 |
| 学习报告 | LearnedCount / Accuracy / StarredCount / 薄弱点 | Learning.DailyStats + KnowledgeMastery | 周期聚合（Week/Month 动态区间） | 弱（独立聚合组合，无共享粒度） | Service 编排 |
| 错题本 | QuestionId / Subject / WrongCount / LastWrongAt + 题目摘要 | Learning.WrongQuestions + Bank.Questions | 无聚合（按行富化） | 是（按行关联） | Service 内存 join |

### 判定结论（每场景）

1. **热力图 / 连续天数**：单实体聚合 + 业务派生 → skill「不为单实体聚合统计用 VEntity（Service+IQueryable 聚合）」→ **Service 层实现**（复用切片 02 DailyStats DataService）
2. **学习报告**：周期为动态区间（Week/Month 前端换算）且口径在 Service（个人正确率/薄弱点）→ 视图需参数化、口径不落库 → **Service 编排**（DailyStats + KnowledgeMastery 分别聚合）
3. **错题本**：跨表（WrongQuestions × Questions 题目摘要）但**无聚合**，属按行富化 → Service 内存关联即可，不达 VEntity 收益线
4. **切片验证约束（关键）**：内存 DAC（TestingEntityDAC）基于 ConcurrentDictionary，**不支持 SQL 视图查询**（VEntity 走 IEntityReadOnlyDAC，需真实 DB）→ 本切片验证期 Service 实现是唯一可行路径

### 复审补充：PeriodStatsView ── 周期报告聚合视图边缘评估（2026-09-07 收官复审）

> 本轮 tkwf-ventity-design 收官复审新增评估（B2）。结论先行：**维持 Service 层实现，不建 VEntity**——动态周期参数无法入视图，规格留存供生产 DBA 评估。

**表名**：`vw_period_stats`（DisableSyncStructure=true）
**子域**：`Stats`（消费域）
**Id 构造方案**：A 业务唯一键透传（UserId）
**视图类型**：普通视图（物化视图经 DBA 评估）

**引用基表**：Learning.DailyStats + Learning.KnowledgeMastery
**依赖追踪**：DailyStats.UserId/StatDate/LearnedCount/StarredCount/Accuracy、KnowledgeMastery.UserId/Accuracy/KnowledgePoint DDL 变更需核对本视图

**Join 结构**：非 JOIN——两实体独立聚合（DailyStats 周期 SUM/AVG；KnowledgeMastery 全期薄弱点清单），无共享粒度关联
**优化栅栏评估**：GROUP BY（UserId）+ WHERE（StatDate 区间）——窗口函数不做（周期在 EQR 谓词层）

**聚合粒度**：SUM(LearnedCount)/SUM(StarredCount)/AVG(Accuracy) 按 UserId + 时间窗（Week=近7天 / Month=近30天，前端换算，动态区间）

**字段表**（= UI 展示字段超集，显式列名，禁 SELECT *）：
| 字段 | 类型 | 聚合列类型 | 来源列 | 四层一致性核对(UI/属性/?fields) | 可更新列标记 |
|------|------|-----------|--------|------------------------------|:---:|
| UserId | long | — | DailyStats.UserId | 报告按人（BR-11） | 否 |
| LearnedCount | int | SUM | `SUM(DailyStats.LearnedCount) AS LearnedCount` | 周期学习题数 | 否 |
| StarredCount | int | SUM | `SUM(DailyStats.StarredCount) AS StarredCount` | 周期点亮 ★ 数 | 否 |
| Accuracy | decimal? | AVG | `AVG(DailyStats.Accuracy) AS Accuracy` | 周期个人正确率（有记录日均值，BR-11） | 否 |

> 薄弱知识点清单（WeakPointsTake5）不并入本视图：KnowledgeMastery 全期数据 → 单实体查询 + Accuracy 升序 Take5，属 Service 侧简单查询，不达 VEntity 收益线。

**数据权限**：行级 WHERE（仅本人 UserId——EQR 谓词）；无列级隐藏
**性能评估**：预估行数 = 用户数 / 索引建议（DailyStats: IX_UserId_StatDate）/ EXPLAIN 验证要点（StatDate 谓词下推?）
**可维护性**：命名 `vw_` 前缀 / COMMENT ON 文档（口径：周期=Week/Month 动态窗，均值仅有记录日）/ 纳入 git
**查询通道暴露决策**：EQR `User.Query<PeriodStatsView>()` / ExposeRestQuery 关 / GraphQL 开

**判定结论（B2）**：
1. **动态周期 ≠ 视图参数**：Week/Month 由前端换算为 [start,today]，视图需每请求带区间谓词且口径不落库 → 决策表「实时/动态参数 → Service」边缘；视图固定周期（如近7天）会丢失 Month 查询语义
2. **StatsDto 门控通过但收益低**：聚合列 SUM/AVG 齐全（含 AS 别名）→ 可建；但数据源为写入侧已聚合的 DailyStats 单实体，SQL 聚合收益有限
3. **判定**：**维持 Service 编排**（GetPeriodReportService 现有实现，口径一致）；生产若高频可评估物化视图 + EQR 谓词，标注 [待生产确认]
