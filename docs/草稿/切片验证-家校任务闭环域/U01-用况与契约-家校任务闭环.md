## UC-2.1：布置任务（三步向导，前端编排）

**对应场景**：S01-2.1 → 步骤 1~6
**对应 UI 图**：tasks-create#1~7
**子域**：`Tasks`
**事务范围**：CROSS（写 Tasks + 批量创建 TaskAssignments + 跨模块校验群组/题库）
**事务策略说明**：任务与全组分配必须同生共死——任务已建但分配未建会造成学生端看不到任务
**故障容忍度**：Required
**权限要求**：`owner`
**关联 R 功能点**：R01-2.1
**API 路由**：`POST /api/v1/tasks`
**决策**：三步向导 = 前端逐步收集（选题源/配置/预览），**后端单次提交**（D03 无分步接口）

---

### [场景层] — 给 UI/验收看

#### Precondition（进入条件）
1. 已登录且角色为群主
2. 群组存在且当前群主为 Owner；群组有学生成员
3. 已选选题源与配置（前端向导完成）

#### Main Flow（主流程）
1. 群主完成三步向导（选题源 → 配置 → 预览发布）→ 点"发布"
2. 系统校验群组/题库/题目归属 → 创建任务（Active）
3. 系统自动为群组每位学生创建分配（Pending）
4. 成功 Toast + 可"分享到家长群" → 跳转任务详情

#### Alternative Flow（替代流程）
- 1a. 群组不存在/非 Owner → 5001/1004（BR-01）
- 1b. 题库不存在 → 1501（BR-02）
- 1c. 群组无学生成员 → 空态提示先导入名单（BR-03）
- 2a. 题目不属于题库 → 1502（BR-04）

#### Postcondition（完成后状态）
- 数据：Tasks 已写入（Active）；TaskAssignments 批量创建（Pending）
- 页面：跳转任务详情；学生首页任务卡出现

## UC-2.5：任务逾期扫描（BackgroundJob）

**调度规则**：Hangfire 每日 0:00（UTC+8）+ 每次任务发布时触发
**事务范围**：CROSS（扫描 + 批量更新分配状态）
**故障容忍度**：Optional（单任务失败记录，不中断整批）
**关联 R 功能点**：R01-2.5

### Precondition（数据状态条件）
- 存在 DeadlineAt < now 且 Status=Active 的任务
- 存在对应 Status ∈ {Pending, InProgress} 的分配

### Main Flow（系统流程，无用户操作）
1. 扫描到期任务（DeadlineAt < now 且 Status=Active）
2. 将到期任务的未完成分配（Pending/InProgress）置为 Overdue
3. 更新看板逾期统计

### Alternative Flow（数据异常路径）
- 1a. 无到期任务 → 跳过本次执行（BR-20）
- 2a. 单任务更新失败 → 记录日志，继续下一任务（BR-21）

### Postcondition
- 数据：到期分配 Status=Overdue；任务保持 Active（允许重做任务仍可复习）

#### 业务规则

| BR# | 规则说明 | 测试场景 |
|:---:|---------|---------|
| BR-20 | 无到期任务则跳过（幂等） | 无到期 -> 不产生写入 |
| BR-21 | 单任务失败不中断整批 | 某任务数据异常 -> 跳过该任务继续 |
| BR-22 | 到期未完成分配置 Overdue；已完成不变 | 截止后 Pending -> Overdue |
| BR-23 | 允许重做的逾期任务仍可进入复习（不改变 Overdue） | AllowRedo=true 逾期 -> 可复习不改变状态 |
