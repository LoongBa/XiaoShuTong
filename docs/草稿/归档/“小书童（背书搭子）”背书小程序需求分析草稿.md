# “小书童（背书搭子）”产品需求分析和设计 V2

## 一、系统概述

“小书童”是一款基于 **AI 导师引导**与**艾宾浩斯记忆原理**的私域背记工具。其核心逻辑是：**“由专业人士（老师/家长）提供高质量内容，由 AI 导师陪伴学生完成从模糊到熟练的记忆跃迁。”** 不同于传统背诵工具，本产品以“引导容错”为核心，通过多模态交互、个性化复习、私域社交与可视化激励，解决用户“背了就忘、难以坚持、内容泄露”等痛点，同时降低技术落地门槛，便于在师生、家长群中快速推广。

## 二、核心产品逻辑：从“判官”转向“导师”

不同于传统 App “对即对，错即错”的机械判题，本方案强调 **“引导与容错”**，让 AI 从“评判者”转变为“陪伴式导师”，贴合学习场景的实际需求：

- **语义容错**：利用 AI 识别关键词，允许口语化表达、同义表述（如“唐太宗”与“李世民”视为正确），避免因表述差异导致误判。

- **求助引导**：用户卡壳时，AI 提供首字、意象或逻辑线索（如“科举制度的创立朝代，提示：与隋朝相关”），而非直接显示答案，引导用户主动回忆，强化记忆效果。

- **二次确认**：用户使用语音输入法转文字后，可手动微调内容再提交，避免因口癖、结巴或语音识别误差导致的判错，提升答题体验。

## 三、功能规划（三步走战略）

结合产品落地优先级与用户需求，将功能实现划分为三个阶段（V1.x、2.x、3.x），逐步完善产品生态，降低初期开发难度，快速验证核心价值。

### 阶段 1：核心背记版（MVP）—— 解决“记住了”

目标：跑通**单人背诵闭环**，建立自我激励体系，验证核心背记功能的实用性，快速落地 MVP。

1. **题库管理（私域简化）**
   
   1. **上传文件、手动录入与粘贴**：支持“问/答”格式的结构化文本上传、批量粘贴，暂缓 AI 自动提取 PDF 功能，优先保证内容质量与录入便捷性；内容支持单元章节，同时支持单题手动录入、修改与删除和单元章节的管理，满足基础题库维护需求。
   
   2. **隐私保护（私域核心）**：默认所有题库、背诵记录私有，仅用户本人可见，打消老师、家长对教学资料、学生学习数据外流的顾虑，强化私域属性。
   
   3. **基础分类标签**：支持按主题（如“唐朝历史”“英语单词”）、难度等简单分类，自定义标签（如“高频考点”“易错点”），方便用户快速筛选题目。

2. **四阶记忆状态追踪（核心升级）**基于艾宾浩斯记忆原理，将每道题的掌握情况量化为四个阶梯状态，动态调整复习周期，替代传统单一的“正确/错误”判断：
   
   1. **✕ (未掌握)**：多次答错，未形成有效记忆，优先推送复习。
   
   2. **△ (模糊/求助后对)**：需求助提示才能答对，记忆不牢固，缩短复习间隔。
   
   3. **○ (掌握)**：无需提示可独立答对，形成短期记忆，按常规间隔复习。
   
   4. **★ (熟练/进入长期记忆)**：多次独立答对，记忆牢固，延长复习间隔，进入长期记忆序列。

3. **可视化激励体系**
   
   1. **记忆热力图**：借鉴 GitHub 贡献图，颜色深浅代表每日点亮 ★ 的数量，直观展示用户学习连续性与努力程度。
   
   2. **多邻国路线图**：根据单元章节划分，将大章节拆解为路线图、单元和章节关卡（如：唐朝 → 贞观之治 → 科举制度），完成关卡可解锁对应标识，降低背诵压力，提升成就感。
   
   3. **离线成就报告**：支持导出可打印的 **“Todo + Checklist”** 报表，包含当日复习任务、已完成情况、未掌握题目，方便用户假期外出、无网络时离线打卡，衔接线上线下学习场景。

4. **基础背记交互**
   
   1. 多模态答题：支持文字输入（手机自带语音输入法实现语音输入）、语音朗读（浏览器自动朗读）两种方式，适配不同使用场景。
   
   2. AI 导师判题：基于语义匹配判断答案正确性，提供引导提示，记录答题情况与记忆状态。记不住的情况下，用户可点击“请提示我”获得提示信息；回答不完全正确时，提示用户记住要点，达到背记目的，并将判断结果结构化返回给代码，以便记录和用于产生复习序列。
   
   3. 艾宾浩斯复习序列：根据四阶记忆状态，动态计算下次复习时间，优先推送“未掌握”“模糊”的题目，提升背诵效率。

### 阶段 2：群组社交版 —— 解决“坚持住”

目标：引入私域社交（班级/家委会），利用同伴压力与群体激励，提升用户粘性，解决“难以坚持”的痛点，适配师生、家长场景。

1. **群主特权模式**
   
   1. 群主（老师/家长）可创建学习群组，上传题库、分发背诵任务，组员点击即可参与背诵，无需手动组题，降低使用门槛。
   
   2. 群主可查看组员背诵进度、记忆状态，针对性布置复习任务，实现精准辅导。

2. **动态激励日志**
   
   1. **群动态**：实时滚动展示群内成员学习动态，如“XXX 完成了 △→○ 跃迁”“XXX 今日点亮 5 颗 ★”，营造积极的学习氛围。
   
   2. **非分数排名**：摒弃传统分数排名，仅展示“坚持天数”和“熟练度（★）增长数”，避免恶性竞争，聚焦学习过程与进步幅度，保护用户学习积极性。

3. **班级成就汇总**：老师可一键导出全班背诵进度周报，包含班级整体正确率、每位学生的记忆状态分布、未掌握知识点，便于精准了解班级学习情况，优化教学安排。

4. **基础社交互动**：支持群内分享题库、背诵心得，组员可互相鼓励，强化群体凝聚力；支持好友添加，查看好友学习进度，形成一对一陪伴背书模式。

### 阶段 3：生态扩展版 —— 解决“内容源”

目标：建立内容价值链，丰富内容来源，实现产品商业化闭环，提升产品长期生命力。

1. **AI 智能助手**：技术成熟后，引入高质量 PDF/图片转题库功能，支持自动提取“问/答”格式知识点，减少手动录入成本，提升题库创建效率。

2. **题库市集与版权保护**：引入 **DRM 数字版权技术**，搭建题库市集，支持优质题库（如老师原创题库、考试真题题库）付费分享，确保作者利益，鼓励优质内容产出；同时支持免费题库分享，丰富内容生态。

3. **高级 AI 功能升级**：优化 AI 导师引导逻辑，支持个性化提示（根据用户易错点调整提示方式）；引入 AI 错题分析，生成针对性复习建议，提升背诵效果。

4. **商业化拓展**：推出会员服务，解锁高级功能（如批量导出报告、AI 题库生成、专属激励标识）；引入广告合作（精准匹配教育类广告），实现盈利闭环。

## 四、核心技术方案

结合产品落地性、成本控制与用户体验，优先选择“低技术门槛 + 高适配性”的技术方案，同时预留未来升级空间，贴合“微信私域”核心场景。

### （一）终端与架构

1. **形态选择**：**微信 H5 + PWA**
   
   1. 优势：即点即用，无需下载安装，支持微信内直接打开、桌面快捷方式创建，避开 App Store 抽成与审核，降低用户获取成本；适配微信私域场景，便于群内分享、传播。
   
   2. 补充说明：后期若出现强力系统级推送、息屏/后台语音交互、深度群社交集成等需求，可迁移至微信小程序或原生 App（具体触发条件见“备忘录”）。

2. **系统架构**：采用分层架构，确保各模块低耦合、高可扩展，便于分阶段迭代：
   `用户层（微信 H5 + PWA） → 应用服务层 → 数据存储层 → 外部服务层`
   
   1. **用户层**：负责 UI 展示、用户交互（答题、上传题库、群组互动等），适配微信内置浏览器，优化移动端体验。
   
   2. **应用服务层**：处理核心业务逻辑（四阶记忆算法、AI 导师判题、群组管理、统计分析等），采用模块化设计，便于后期功能扩展。
   
   3. **数据存储层**：存储用户数据、题库、答题记录、群组信息等，保障数据安全与访问效率。
   
   4. **外部服务层**：对接第三方 API（AI 判题、语音服务等），降低自建技术成本。

3. **用户认证**：采用“微信授权登录 + 手机号快速绑定”模式，无需手动注册，提升用户注册转化率；同时绑定手机号，保障账号安全性与数据可追溯性。

### （二）技术选型

1. **前端**：
   
   1. 核心框架：基于 Blazor WebAssembly 开发（贴合团队技术栈），兼顾跨平台适配与复杂交互需求；结合 HTML/CSS/JavaScript，优化移动端适配与页面流畅度。
   
   2. 可视化：使用 Canvas 实现记忆热力图、路线图等可视化图表，提升用户体验；引入 WebAssembly 优化复杂图表渲染性能。
   
   3. 交互适配：适配微信内置浏览器，优化触摸操作、页面跳转逻辑，解决弱网场景下的加载问题。

2. **后端**：
   
   1. 语言与框架：ASP.NET Core + Blazor Server（与前端技术栈统一，降低跨语言开发成本），负责 API 接口开发、业务逻辑处理、第三方服务集成。
   
   2. 核心能力：支持 RESTful API 与实时通信（SignalR），适配群组实时动态、进度同步等社交场景。

3. **数据库**：
   
   1. 关系型数据库：PostgreSQL（优先选择，替代 MySQL），存储用户信息、任务信息、统计数据、群组信息等结构化数据，支持复杂查询与事务，确保数据一致性；支持 JSONB 类型，适配题库标签等半结构化数据。
   
   2. 缓存：Redis，缓存高频访问的题库数据、用户当前记忆状态、群组动态，提升 API 响应速度，降低数据库压力。

4. **外部服务**：
   
   1. AI 判题/语义匹配：调用字节跳动系 API（如火山引擎大模型 API），实现语义容错、引导提示等 AI 导师功能，贴合团队技术规划，降低接入成本。
   
   2. 语音服务（TTS/ASR）：前期优先使用浏览器前端 TTS 引擎，降低后端负载；ASR 鼓励用户使用手机自带语音输入法（如豆包、讯飞），提升输入质量；后期可接入火山引擎语音 API，优化语音交互体验。
   
   3. 版权保护：引入 DRM 数字版权技术，保护付费题库内容，防止非法复制、传播。

### （三）关键技术实现方案

1. **四阶记忆算法（艾宾浩斯优化版）**
   
   1. 核心公式：$$Next\_Interval = f(Current\_State, History\_Accuracy)$$，根据当前记忆状态（✕/△/○/★）与历史正确率，动态计算下次复习间隔，替代传统固定间隔模式。
   
   2. 算法规则示例：
      
      - ✕ (未掌握)：下次复习间隔为 12 小时，优先加入下一次背诵任务。
      
      - △ (模糊)：下次复习间隔为 1 天，强化记忆巩固。
      
      - ○ (掌握)：下次复习间隔为 3 天，按常规艾宾浩斯间隔推进。
      
      - ★ (熟练)：下次复习间隔为 7 天，后续逐步延长至 30 天，进入长期记忆序列。
   
   3. 数据依据：基于用户答题记录中的“记忆状态、历史正确率、最后背诵时间”计算间隔，无需用户手动设置，实现个性化复习。

2. **AI 导师判题逻辑**
   
   1. 核心需求：实现语义容错、引导提示，避免机械判题，贴合“导师化”定位。
   
   2. 实现方式：调用字节跳动系大模型 API，对比用户答案与标准答案的语义一致性，识别关键词与同义表述；用户卡壳时，生成引导性提示（而非直接给出答案）；答题后返回判题结果、置信度及简短引导说明。
   
   3. 优化策略：缓存高频题目、常见同义表述，减少 API 调用次数，降低成本；建立本地规则引擎，处理简单题目的关键词匹配，提升响应速度。

3. **语音交互实现**
   
   1. TTS（文字转语音）：优先使用浏览器前端 TTS 引擎，将题目文本转为语音播放，支持调节语速、音色，方便用户“听题”背诵；后期可接入火山引擎 TTS API，优化语音音质与适配性。
   
   2. ASR（语音转文字）：前期鼓励用户使用手机自带语音输入法，将语音转为文字后提交答题，提升输入质量与判题准确性；后期接入火山引擎语音识别 API，实现前端直接录音、转文字，简化操作流程。

4. **私域数据安全实现**
   
   1. 数据加密：所有用户数据、题库内容、答题记录采用加密存储，传输过程启用 HTTPS，保障数据安全。
   
   2. 隐私控制：默认所有内容私有，用户可自主设置题库分享权限；群组内数据仅群主与组员可见，杜绝外部访问，保护私域资料安全。
   
   3. 合规性：遵循《个人信息保护法》，明确用户数据所有权，不收集无关隐私信息，确保产品合规。

## 五、可行性分析

### （一）技术可行性

- **核心技术成熟**：四阶记忆算法基于艾宾浩斯原理优化，逻辑清晰，可通过规则引擎+后端代码实现；AI 判题、语音服务依赖字节跳动系第三方 API，技术门槛低，无需自建模型；微信 H5 + PWA 开发成熟，适配微信生态，开发难度可控。

- **分阶段落地可控**：阶段 1 核心背记功能（题库录入、四阶记忆、基础激励）技术难度低，3-4 个月可完成 MVP 开发；阶段 2、3 功能可基于现有架构迭代，无需重构，降低开发成本。

- **技术栈适配性**：前端 Blazor WebAssembly 与后端 ASP.NET Core 技术栈统一，团队熟悉 Blazor 路线，可快速上手开发；PostgreSQL 与 Redis 适配性强，可满足数据存储与性能需求。

### （二）成本可行性

- **初期成本（阶段 1）**：
  
  - 服务器：云服务器（如阿里云 ECS）基础配置即可支撑初期用户（约 200-500 元/月），后期可根据用户量扩容。
  
  - 第三方 API：阶段 1 优先使用前端 TTS 与手机自带 ASR，AI 判题 API 调用量低，月成本可控制在 100-300 元；后期随着用户量增长，可通过缓存、批量采购降低 API 成本。
  
  - 开发人力：1-2 名前端（熟悉 Blazor）+ 1 名后端 + 1 名产品设计，3-4 个月可完成阶段 1 核心功能。

- **长期成本（阶段 2、3）**：随用户量增长，服务器与 API 成本会上升，但可通过阶段 3 商业化功能（付费题库、会员服务）覆盖；DRM 版权保护技术可按需接入，成本可控。

### （三）用户体验可行性

- **简洁易用**：核心流程（录入题库→背诵→复习）步骤清晰，微信 H5 即点即用，无需下载，降低用户操作成本；AI 导师引导与容错设计，提升答题体验，减少挫败感。

- **激励性强**：记忆热力图、路线图、离线报告等可视化激励，让用户清晰看到自己的进步，提升学习动力；非分数排名与群动态，营造积极的学习氛围，帮助用户坚持背诵。

- **场景适配性高**：离线报告解决无网络场景需求，语音交互适配通勤、运动等场景；私域保护设计，贴合老师、家长的核心需求，便于在班级、家委会群中传播。

### （四）市场可行性

- **需求明确**：学生、考证人群、老师、家长对“高效背诵、私域内容保护、坚持学习”的需求旺盛，尤其适合文科类知识点、语言类单词、教学资料背诵等场景。

- **差异化优势**：相比传统背诵工具，本产品的“AI 导师化、四阶记忆、私域保护、离线报告”四大核心亮点，解决了现有产品的核心痛点，竞争力突出。

- **推广便捷**：微信 H5 形态便于群内分享、传播，无需复杂推广流程；老师、家长作为核心传播节点，可快速带动用户增长，冷启动成本低。

- **商业化空间大**：阶段 3 题库市集、会员服务等商业化功能，可实现盈利闭环；优质教育内容的付费需求旺盛，版权保护设计可吸引老师、机构入驻，丰富内容生态。

### （五）潜在挑战与应对

1. **AI 判题准确性**：复杂题目（如多答案、主观题）可能出现误判。应对：初期限制题型为“客观问答”（有明确答案），后期通过用户反馈优化判题模型；建立人工反馈机制，允许用户纠正判题结果，持续迭代 AI 逻辑。

2. **用户数据安全**：题库和学习记录涉及用户隐私，尤其是老师的教学资料、学生的学习数据。应对：强化数据加密存储与传输，完善隐私控制功能；遵循相关法律法规，明确用户数据所有权，不泄露任何隐私信息。

3. **冷启动问题**：初期题库量不足影响用户体验。应对：提供官方基础题库（如高中历史考点、常用英语单词），鼓励老师、家长上传分享题库，设置“上传奖励”机制（如解锁高级功能）；借助老师、家长的私域资源，快速积累优质内容。

4. **H5 功能限制**：微信 H5 存在推送、后台录音等功能限制。应对：前期通过离线报告、群动态弥补推送不足；明确迁移小程序/原生 App 的触发条件，后期根据用户需求升级，确保功能完整性。

## 六、备忘录：迁移小程序/原生 App 的触发条件

当前采用微信 H5 + PWA 形态，兼顾落地性与推广性，当出现以下需求时，需考虑从 H5 升级至微信小程序或原生 App：

1. **强力系统级推送**：需在特定复习点强制弹出手机通知，提醒用户复习，H5 无法实现系统级推送。

2. **息屏/后台语音交互**：用户需锁屏背诵、后台持续录音答题，H5 无法维持长时间录音权限。

3. **深度群社交集成**：需获取微信群列表、群成员详细信息等敏感 API 权限，实现更精准的群组管理与互动。

4. **复杂功能扩展**：后期引入直播背书、实时连麦等高级功能，H5 性能与权限无法满足需求。
