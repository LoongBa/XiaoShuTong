# 前端页面需求描述（交 UI 设计）

> **状态：已归档（2026-09-06）**——已被《小书童-UI设计文档-v2.md》（V2.2 合并正式版）取代，其交互细节（布局骨架/状态枚举/交互时序/通用组件/文案规范）已并入正式文档。本文件为历史输入规格，仅存档参考。

> 技术栈：React 19 + shadcn/ui + Vite + Zustand（ADR-007）
> 对齐文档：《产品战略与定位 V1》（三方价值模型）、《D05 前端页面结构与测试策略设计 V1.1》（路由）、《D03 API 契约设计》（数据来源）
> 设计理念：**提升背书执行力**──群主布置 → 学生执行 → 家长看成长。每个页面都要能回答"它真的帮孩子记住了吗"
> 优先级：★ = P0（MVP 必须）☆ = P1（首发后续）○ = P2（延后）

---

## 设计语言基调

| 维度 | 约定 |
|------|------|
| 核心视觉 | 清爽、鼓励感。避免"考试压迫感"，用**进度感**（★/进度条/热力图）代替"分数感" |
| 记忆状态色 | ✕灰 / △黄 / ○绿 / ★金（贯穿全端的状态标识） |
| 年龄适配 | 学生端（6-15 岁）：大按钮、图形化、奖励动画；家长端/群主端：信息密度高、表格化 |
| 移动端 | H5 即点即用，底部 Tab 导航，单列卡片流，一次一题 |
| 反馈规则 | 判题后必须有【正确/错误 + 记忆状态变化】的即时视觉反馈，绝不只弹"打卡成功" |

## 3. 首页 `/student/home` ★★核心

**用途**：学生每天的"任务中心"——一打开就知道今天要做什么。

**布局骨架**：
```
┌────────────────────────────┐
│ 下午好，小明  🔥连续7天       │  <- 问候条(Sticky顶部)
├────────────────────────────┤
│ 📋 今日任务                  │  <- 区块1·最醒目
│ ┌────────────────────────┐ │
│ │ 背诵《人文地理·第一章》      │ │
│ │ ▰▰▰▰▰▰▱▱▱▱  4/10        │ │  进度条+截止05-20
│ │ 群主：王老师 截止 明天 18:00 │ │
│ └────────────────────────┘ │
├────────────────────────────┤
│ 🔄 该复习了（3个知识点）        │  <- 区块2·次位
│ ┌────────────────────────┐ │
│ │ △ 黄鹤楼        5天前    │ │
│ │ ○ 大运河        3天前    │ │
│ └────────────────────────┘ │
├────────────────────────────┤
│ [自由背诵] [PK竞技]          │  <- 快捷入口(2x2宫格)
│ [错题本]   [热力图]          │
├────────────────────────────┤
│ 本周 ▰▰▱▱▱▰▱               │  <- 热力图横条
└────────────────────────────┘
```

**内容元素**（自上而下）：
1. **顶部问候条**："下午好，小明" + 连续打卡天数徽章（🔥 N 天）
2. **今日任务卡片区**（最上方、最醒目）：
   - 群主布置的任务卡片：任务名（如"背诵《人文地理·第一章》"）+ 进度条（已背 x/y）+ 截止时间
   - 未布置任务时 → 空态引导"群主还没布置任务，先去自由背诵吧"
   - 多任务时 → 垂直堆叠，最多展示 3 张，其余"查看全部 N 个任务"
3. **到期复习卡片**（次位）：记忆曲线到期知识点清单（"3 个知识点该复习了"）
4. **快捷入口行**：自由背诵 / PK 竞技 / 错题本 / 热力图
5. **今日热力图横条**：本周 7 格星星（今天的亮/暗）

**用户操作**：
- 点任务卡 → 进入任务执行页（4 号）
- 点复习卡 → 进入复习队列页（7 号）
- 点自由背诵 → 选题库（8 号）
- 点热力图 → 全屏热力图（10 号）

**状态枚举**：
| 状态 | 表现 |
|------|------|
| 默认（有任务） | 任务卡置顶，进度条按 已背/总数 |
| 无任务空态 | 任务区显示引导卡"群主还没布置任务，先去自由背诵吧"+ 按钮直达自由背诵，不能是光秃秃空白 |
| 无到期复习 | 复习区块整个隐藏（不占位） |
| 任务已截止 | 任务卡红色截止标"已截止"，进度条半透明 |
| 任务今日截止 | 卡上"今天 18:00 截止"警示色 |
| 首次使用欢迎 | 首日弹窗"今天背一首诗，点亮第一颗★"（不强弹，可关闭） |

## 4. 群组任务执行页 `/student/study/task` ★★核心

**用途**：学生完成群主布置的背书任务（本产品核心场景）。

**布局骨架**：
```
┌────────────────────────────┐
│ ← 返回  背诵《人文地理·第一章》 │  <- 任务头
│ 王老师  截止明天18:00  4/10 │
├────────────────────────────┤
│       第 5/10 题            │  <- 题型tag: R2
│                            │
│    "黄河远上白云间，____"      │  <- 题目区(楷体,居中)
│    想不起来？→(HintBubble)   │
│                            │
│ ┌────────────────────────┐ │
│ │  [ 输入/语音作答框 ]      │ │  提交按钮
│ └────────────────────────┘ │
│                            │
│ ○ ○ ○ ○ ● ○ ○ ○ ○ ○       │  <- 进度点阵,当前高亮
└────────────────────────────┘
```

**内容元素**：
1. 任务头：任务名 + 群主名 + 截止时间 + 总体进度（已背 x/y）
2. 题目区（一次一题，上滑换题）：
   - 题型渲染（R1 上句接下句 / R2 下句接上句 / R3 段落默写 / O 系列点选）
   - 输入方式：文本框（系统语音输入法）+ 或语音按钮
   - "想不起来？"提示按钮（触发 HintBubble，背景钩子）
3. 判题反馈区：正确 → 绿色 + ★点亮动画 + 鼓励语；错误 → 红色 + 正确句展示 + "再看一遍"重背按钮
4. 底部进度点阵（点点代表题目，当前高亮）

**用户操作**：作答 → 判题 → 看反馈 → 下一题 → 全部完成 → 完成庆祝页（激励动画 + "你已完成群主布置的任务"）

**交互时序**（作答→判题→反馈→下一题完整循环）：
1. **进入**：加载第 1 题（题型按 D01 规则取），答题框聚焦（移动端自动调起键盘）
2. **作答**：文本输入 或 语音输入（语音转文字后回填到文本框，可编辑再提交）
3. **提交**：点"提交"或回车 → 请求判题（≤1s 快判），期间"判题中…"转圈，禁用重复提交
4. **正确反馈**：绿色高亮 + ★点亮动画（Stars 粒子）+ 随机鼓励语 → 1.5s 后自动出"下一题"按钮
5. **错误反馈**：红色高标 + 正确句完整展示（楷体）+ 记忆状态提示"这题还不熟，✕" → 两按钮：
   - **“再看一遍”**：原地重看正确句 → 重背当前题（不跳题）
   - **“下一题”**：跳过（该题保持未掌握，进错题本）
6. **卡壳求助**：点"想不起来？" → 展开 HintBubble（S1 首字 → 仍不会 S2 意象 → S3 逻辑逐级加深）→ 求助后答对 = 黄色△（hint_level=partial，D01）
7. **中途退出**：进度增量已保存，再次进入从当前题继续（不重头）
8. **最后一题完成**：自动进入完成庆祝页（5 号页前奏动画："你已完成群主布置的任务"+ 本次点亮 N 颗★ + 分享激励卡可选）

**状态枚举**：
| 状态 | 表现 |
|------|------|
| 作答中 | 答题框可见，提交按钮可点，进度点阵当前题高亮 |
| 判题中 | 按钮 loading"判题中…"，≤1s，禁重复提交 |
| 判题正确 | 绿色反馈区 + ★点亮动画 + 鼓励语，"下一题"1.5s 后出现 |
| 判题错误 | 红色反馈区 + 正确句展示 +【再看一遍/下一题】双按钮 |
| 求助后答对 | 黄色△ 徽章标注"求助后答对"，收益低于独立答对 |
| 作答超长 | 输入框高度约束 3 行内，超出滚动，不撑破布局 |
| 题目为空/加载失败 | 居中占位"题目加载失败" + 重试按钮 |
| 任务全部完成 | 完成庆祝动画，防重复提交（幂等） |

**关键**：完成任务 ≠ 打卡成功——必须展示"背对了哪几句、哪句还卡着"，让执行力可见。

## 9. PK 竞技（3 页） `/student/play/pk-lobby` `pk-battle` `pk-result` ☆

**用途**：趣味竞技激励（闭环中的"有趣"一环）。

- **大厅**：发起挑战按钮 + 待加入对战列表 + 我的战绩（胜/负/平 + 不展示分数榜）
- **对战**：双方同题同序，每题 30s 倒计时，答对+10；同分比用时
- **结果**：胜负 + AI 趣味点评（个性亮点/薄弱点/知识彩蛋）

**交互动线**：
1. **发起挑战**：选学科范围 → 生成对战码（4 位）→ 邀请好友输入码加入 → 双方就绪开局
2. **对战中**：每题 30s 倒计时（视觉红条），双方同题同序 → 答对即时 +10 反馈 → 自动下一题
3. **PK 结果**：胜方庆祝动画 + AI 点评："你《滕王阁》背得飞快，杜甫的《登高》还差点火候"
4. **中途掉线**：对手离线 30s → 判对方自动弃权，己方获胜

**合规**：PK 结果只展示 ★数/用时，不出现正确率对比榜（红线）。

| StreakBadge | 连续天数徽章（🔥） | 7 天档位变色（1-6 灰火/7+ 金火），断签提示"明天继续就保住啦" |
| 判题反馈动画 | 正确★点亮 / 错误红标（全端统一） | 正确：粒子+音效（可关）+仍鼓励；错误：不惩罚音效，只温和提示 |

**通用交互约定**：
- 所有加载态用骨架屏（skeleton），不用全局 spinner（表单提交除外）
- 空态必须三步：**发生了什么 + 为什么 + 下一步做什么**（见文案规范）
- 所有列表下拉刷新 + 触底加载更多；断网时 Toast"网络开小差了" + 重试按钮
- 错误反馈用 Toast（底部，2-3s）+ 操作失败可重试，**不做全屏错误页**（除硬加载失败）

# 四、文案规范（Copy Tone & Voice）

> 全端文案基调：**鼓励、具体、诚实**。不制造焦虑、不敷衍、不夸大。
> 面向 6-15 岁学生，语气像"靠谱的大朋友"，不带爹味、不用网络烂梗。

### 按钮文案

| 场景 | 文案 | 禁用 |
|------|------|------|
| 主操作 | 动词开头："开始背诵 / 提交 / 发布任务 / 开通报告" | "确认 / 确定 / OK" |
| 危险操作 | "删除 / 移出群组 / 注销账号"（红色） | "移除"（歧义） |
| 破坏性确认 | 按钮上直接写后果："确认注销账号（不可恢复）" | 弹窗内才说明 |

### 鼓励语库（判题反馈随机取）

| 情感 | 示例 |
|------|------|
| 正确·全对 | "全对！今天的★都被你点亮了" / "这句百分百原味，老师都要给你点赞" |
| 正确·部分 | "背得很顺！下次试试不看提示" |
| 求助后对 | "提示一下就想起来了，记忆正在长出来" |
| 错题·安抚 | "这题还不熟，谁都会卡，再看一眼就熟了"（**不出现"又错了"等指责**） |
| 复习完成 | "记得牢，才是真的会" |

### 空态文案模板（三步式）

| 场景 | 发生了什么 | 为什么 | 下一步 |
|------|-----------|--------|--------|
| 首页无任务 | "今天没有群主布置的任务" | "休息也是积累" | [去自由背诵] |
| 复习无到期 | "今天没有要复习的" | "记得很牢！" | [回首页看看] |
| 错题本空 | "没有错题" | "说明都会了" | [去挑战新内容] |
| 内测码未领取 | "还没有可领取的内测邀请码" | "内测邀请码由平台发放" | [联系平台开通] |
| 名单为空 | "名单是空的" | "没有可导入的手机号" | [重新粘贴/上传] |
| 激活码无效 | "邀请码无效" | "可能输错或已失效" | [重新输入/联系群主] |

### 状态徽章辅助文案

| 状态 | 文案（学生端） | 文案（群主/家长端） |
|------|---------------|---------------------|
| ✕ 灰 | "再背背" | "未掌握" |
| △ 黄 | "快熟了" | "需巩固" |
| ○ 绿 | "很棒" | "已掌握" |
| ★ 金 | "点亮了" | "熟练" |

### 合规敏感词（全端禁用）

- ❌ 群组分数/正确率排名、优秀率、及格率、平均分对比
- ✅ 允许：坚持天数、完成度、★数、个人对上周（仅与自己比）
- ❌ "X 班倒数第 N" / "你要落后了"（制造焦虑）
- ✅ "这周比上周多背了 3 篇"（具体进步）

# 五、优先级与交付顺序

```
第零批（内测前置，○）：内测邀请码领取/名单导入/CSV导出/成员激活（先于常规用户增长，成员入组必经）
第一批（MVP 学生端，★）：登录/隐私/首页/任务执行/会话结果/复习队列
第二批（学生端 ☆）：自由背诵/PK/统计/个人中心
第三批（群主端 ○）：看板/群组任务管理（晚于学生端，但早于家长端）
第四批（家长端 ○）：成长报告（付费锚点，验证学生留存后再上）
第五批（阶段二）：内容管理（PGC 工具链）
```

# 六、给 UI 设计的关键提示

1. **先接设计系统，再画页面**——色板/字号/间距/圆角 token 见开头"设计系统"章节，全端保持一致
2. **首页"今日任务"必须最醒目**——这是学生每天打开的第一眼，执行力工具的门面
3. **判题反馈不等于打卡**——错误要展示"错在哪、正确是什么"，绝不做"已完成"糊弄
4. **记忆状态色是贯穿语言**——✕灰/△黄/○绿/★金全端统一，让学生看懂"上涨还是回落"
5. **努力度 > 分数**——所有排名/对比只呈现坚持天数/完成度/★数，永不展示正确率排名（合规红线）
6. **家长报告是付费产品**——信息密度可以高，但要"看得懂、有收获"，展示相对进步而非焦虑榜
7. **空态和加载态也是设计**——请按文案规范给每个空态配上"发生了什么/为什么/下一步"三步文案，不要留空白页
8. **移动端一次一题**——答题场景绝不并排多题；大按钮 + 拇指可达区（底部操作区 56px 以上）
