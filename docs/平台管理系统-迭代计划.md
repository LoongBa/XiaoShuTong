# 平台管理系统迭代计划

### 1.2 前端现状（AdminWasm，待建设）

- AntDesign Blazor Pro 脚手架已就位（AdminWasm-V0.1.0）：BasicLayout + 登录页 + 菜单骨架
- **缺失**：业务页面全部未建（Home 为占位欢迎页）；menu.json 为占位路径（全指向 "/"）
- 调用通道：TKWF ApiClient（GraphQL）`DomainUser.Use<IXxxService>()`，DTO 类型在 Domain 项目（Service 内联 record，字段注释齐全）

## 二、迭代拆分

按需求方案 §八 优先级 + 前端可交付单元，拆为 **3 个迭代**：

| 迭代 | 版本线 | 功能范围 | 需求映射 | 目标 |
|:---:|:---:|---------|---------|------|
| **迭代 1** | AdminWasm-V0.2.0 | 内测闭环 + 群组管理 | F0-F5 | 群主可完成建群/导入/发码/导出/成员管理的完整内测链路 |
| **迭代 2** | AdminWasm-V0.3.0 | 任务闭环 + 群主看板 | F6-F8 | 群主可布置任务、查看看板与任务详情 |
| **迭代 3** | AdminWasm-V0.4.0 | 题库管理 + 我的资料库 | F10-F14 | 群主可建题库/导入题目/多学科浏览 |

> 每个迭代独立提交、独立可演示；F9（周报导出）、F12 深度（AI 预处理 UI）按 P1 延后处理。

## 三、迭代 1 详细计划（内测闭环 + 群组管理，F0-F5）

### 3.1 菜单重构

menu.json 从占位改为真实结构：

```
工作台 /owner/dashboard          （迭代 2 建设，先占位）
群组管理 /owner/groups/list      ← 本期核心
├── 群组列表
├── 内测激活建群 /owner/groups/beta-invite
├── 名单导入 /owner/groups/roster-import
└── CSV 导出 /owner/groups/roster-export
任务管理 /owner/tasks            （迭代 2 建设，先占位）
内容管理 /owner/banks            （迭代 3 建设，先占位）
```

### 3.2 页面与 Service 映射

| 页面（Pages/） | 路由 | 需求 | 调用的 Service 接口 | 页面要点 |
|---------------|------|:---:|-------------------|---------|
| `Groups/GroupList.razor` | `/owner/groups/list` | F5 | `IListGroupsService` | 群组卡片列表（名/学科/人数/执行率）；进入详情/成员管理；【激活建群】入口 |
| `Groups/BetaInvite.razor` | `/owner/groups/beta-invite` | F1 | `ICreateGroupService` | 输入 16 位内测码+群组名+学科+年级 → 激活建群；状态：未领取/已激活/已过期 |
| `Groups/RosterImport.razor` | `/owner/groups/roster-import` | F2 | `IImportRosterService` + `IGetRosterPreviewService` | 双 Tab（批量粘贴/文件上传）→ 整理预览（有效/去重/非法）→ 确认 |
| `Groups/InviteCodes.razor` | `/owner/groups/roster-export` | F3 | `IGenerateInviteCodesService` + `IExportRosterCsvService` | 批次列表→生成码→CSV 下载链接（7 天）→分发话术 |
| `Groups/Members.razor` | `/owner/groups/members` | F4 | `IManageGroupMembersService.GetMembers/RemoveMember` + `ISetRankEnabledService` | 成员激活状态/移除（二次确认）/排名开关 |
| `Groups/GroupDetail.razor` | `/owner/groups/detail/{uid}` | F5 | `IListGroupsService` + `IManageGroupMembersService` | 群组详情 + 成员管理 + 内嵌名单导入流程入口 |

### 3.3 前端调用模式（关键）

```csharp
// 注入
@inject DomainUser DomainUser   // 或从 ServiceProvider 解析

// 调用（GraphQL 传输）
var svc = DomainUser.Use<XiaoShuTong.Services.GroupManagement.Controllers.IListGroupsService>();
var res = await svc.Execute(new ListGroupsReqDto { ... }, CancellationToken.None);
// 判错：res.Success == false → 显示 res.ErrorCode
```

### 3.4 验收标准（迭代 1）

| 验收项 | 条件 |
|--------|------|
| 菜单 | 侧边栏正确显示群组/任务/内容结构，路由可导航 |
| 激活建群 | 输入有效内测码+群组信息 → 建群成功 → 码置 used；无效码/过期/内测关闭 → 对应错误提示（5201/5205） |
| 名单导入 | 粘贴/上传 → 预览统计（有效/去重/非法）→ 确认生成码 |
| 生成码+CSV | 批次生成一次性码 → CSV 下载链接（仅后四位+码）→ 分发话术复制 |
| 成员管理 | 激活状态分组展示；移除二次确认不删学习数据；排名开关即时生效 |
| 编译 | `dotnet build src/XiaoShuTong.AdminWasm/XiaoShuTong.AdminWasm.csproj` 0 错误 |

## 六、实施纪律

- 前端页面开发走 **AntDesign Pro 组件模式**（参考 DMP-Lite.AdminUI 的页面写法），不引入新 UI 库
- 数据访问一律 `DomainUser.Use<TService>()`（GraphQL），**不手写 HttpClient/gql 字符串**
- 不读生成源码（*.g.cs / DataServices\*.cs / Entities\*.cs）；DTO 字段以 Service 源文件注释为准
- 每迭代结束：`dotnet build` + 提交（逻辑单元收敛为 1-2 个提交）
- 阶段不 tag（tag 需另行征求同意，遵循 AdminWasm-V 版本线纪律）
