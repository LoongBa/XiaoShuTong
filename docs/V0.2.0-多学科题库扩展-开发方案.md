# 小书童 V0.2.0 开发方案（多学科题库扩展）

## 一、本版目标

- **核心交付**：将题库从"语文单学科"扩展为"7 学科多学科体系"（语文/英语/历史/地理/生物/化学/道德与法治），并落地判题引擎三层路由 + 题型与交互解耦模型。
- **完成定义（DoD）**：全部学科题库入库并格式合规；判题引擎（规则/相似度/AI）测试矩阵全过；系统性检查报告列出的 17 项问题全部闭环。

## 二、范围

### 包含

1. 多学科题库建设（7 学科，四件套结构：篇目清单 / 背诵内容 / 背诵训练 / 背景钩子）
2. 判题引擎三层路由（`rule_grader` / `similarity_grader` / `ai_grader` / 统一入口 `grader`）
3. 判题策略 × 题型解耦模型（Schema 扩展 + 题型/学科注册表 + 交互类型）
4. 文档体系系统性检查修复（P0~P3 全部 17 项）
5. 迁移工具与演示（`txt2json.py` 标记落盘、`demo_grader.py` 全策略演示）

### 不包含

- 数学 / 物理题库（学科注册表已预留，待启动）
- 真实 LLM API 接入（引擎已支持可插拔客户端，生产接线留待 V0.3）
- 应用前端 / 小程序开发（架构设计中）

## 五、技术方案

### 模块结构

```
题库/schema/
├── rule_grader.py          # O1-O5 规则判题引擎（exact）
├── similarity_grader.py    # R 系列相似度判题（语音容错 + 顺序对齐）
├── ai_grader.py            # LLM 语义判题（引导式反馈 + 降级链路）
├── grader.py               # 统一路由入口（judging_strategy 聚合调度）
├── registry.schema.v1.json # 题型/学科注册表统一 Schema
├── question.v1.json        # 题目 Schema（+judging_strategy/interaction_type）
└── txt2json.py             # txt → JSON 迁移（+[js=]/[it=] 标记落盘）
```

### 核心流程

```
题目 → resolve_strategy() → 路由
├─ exact      → rule_grader       （O1-O4 零成本）
├─ similarity → similarity_grader （R 系列语音容错）
├─ ai_guided  → ai_grader         （X1/X2 开放问答引导式反馈）
└─ hybrid     → 本地初筛 + AI 兜底（成本/准确率平衡）
```

### 数据模型

- `judging_strategy`：exact / similarity / ai_guided / hybrid（题目级 > 题型级 > 学科级 > 全局）
- `interaction_type`：voice / text / select / drag / swipe / card（前端交互组件）

## 七、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 语音输入 ASR 误差 | 判题误斥致挫败 | 二次确认 + 容错阈值降 0.05 + 相似度初筛 |
| LLM 成本不可控 | 运营成本上升 | 本地关键词短路（≥85% 零 LLM）+ hybrid 兜底 |
| 段落乱序误判 | 默写判题失真 | 顺序对齐为主信号（已修复） |
| 后台 Agent 输出不可用 | 内容质量风险 | 内容由主代理直接落盘，核验以文件系统为准 |
