## 三、缺陷发现与修复（Sisyphus 审核中实证）

**KnowledgeMasteryAggregationJob UId 缺失缺陷**：

- **现象**：新增多用户测试（用户 A + B 各自聚合）时 `System.Exception: constraint failed`——用户 A create 成功、用户 B create 失败。
- **根因**：`KnowledgeMastery.UId` 为 `string N`（必填），实体**未实现 `IEntityTracked`** → 框架不自动生成 UId。create 分支（V0.7.2 前既有代码）**未设 `UId`** → SQLite UNIQUE(UId) 约束：单用户首个 NULL 允许（SQLite 单 NULL 语义），**多用户第二个 NULL 冲突**。
- **先例印证**：`.TKWF/LOG.md` L257 同源教训（Tier 1.5 SQLite 真实约束暴露 UId 缺失）+ 对照 `RankSnapshotFreezeJob.cs` L145（create 正确设 `UId = UidGenerator.NewId()`）。
- **修复**：create 分支补 `UId = UidGenerator.NewId()`。
- **影响面**：此缺陷**一直存在**（V0.7.2 前），仅当**多用户同时聚合**（生产按需触发/每小时批量多用户场景）才触发——**生产实际会触发**（多用户作答后聚合）。修复后多用户场景正常。
- **归属**：小书童业务代码缺陷（非框架/扩展 bug）——自行修复，无需上报框架组。

| 项 | 结论 | 闭环 |

| M1 快照键 map 精度 | 采纳全键 | ✅ 已落地（RankSnapshotFreezeJob 全键 map） |

| C1 Knowledge 批量查询位置（阻塞级） | 采纳 | ✅ 已提至 ExecuteAsync 外层一次 IN 全用户 |
| C2 BankHint toUpdate 时机 | 采纳 | ✅ 每 chunk 独立 List |

**M2 实证修正说明**：框架 `DataService-API-参考.md` 声明 `EntityUpdateBatchAsync` 可用，但实测（FreeSql SQLite :memory:）`UpdateRange` 要求实体已 attach（"不可更新，数据未被跟踪，应该先查询或者 Attach"）——`EntitySelectAsync` 返回的游离实体不满足。改用 `EntityUpdateColumnsBatchAsync`（DAC 实现走 `Orm.Update().SetSource()`，无需 attach，支持游离实体列表）→ 测试通过。此为**框架批量 API 的使用边界实证**（非框架 bug——API 文档未明示 attach 要求），已记录于方案 §5.2 注释，建议后续向框架组反馈文档补明。
