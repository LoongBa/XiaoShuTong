## 二、审核结论

**总评：通过**

V0.6.8 登记的 P3 缺陷（login.tsx role 恒 student，teacher/parent 无法从 UI 登录走查）闭环。核心交付：

1. **联调账号选择**：主按钮下三胶囊（学生小明/群主老师/家长，默认 xiaoming），点击 `Tkwf.Guest.loginByContext(选中 userName)`——真实 WebApi 按 userName 白名单返回身份（`OnLoginByWeChatAppletAsync`），生产真实微信授权时此区块废弃移除（注释 + 变更记录标注）。
2. **role 映射（M1 语义适配层）**：`resolveRole(userName)`——xiaoming→student / owner01→**teacher**（owner→teacher：前端 UserRole 无 owner，owner01="群主老师" 语义即 teacher 端路由）/ parent01→parent。定位为"后端业务身份 → 前端路由语义"的**永久适配层**（非临时绕过——生产 extensions 透出后输入源改 extensions.role，映射逻辑保留）。
3. **登录分跳解除**：原 login.tsx:22-33 role 分跳逻辑已就绪但 role 恒 student 永不触发——本次 resolveRole 派生 role 后分跳生效（student→/student/home、teacher→/teacher/dashboard、parent→/parent/dashboard）。
4. **privacy 分跳修复（C3 实证缺陷，超出 P3 范围）**：privacy.tsx `handleAgree`/`handleGuardianConfirm` 原**恒跳 /student/home**——owner01/parent01 首次登录走隐私流程会落错学生首页；改为 `homeByRole()` 按当前用户 role 分跳。
5. **teacher/parent 登出（C2 走查闭环）**：两端 header 补"退出"按钮（`logout()` + navigate login）——三端切换走查流程（登录→各端→登出→回登录页换账号）闭环；store.logout 已完整清空 currentUser/isLoggedIn/session/answers（实证）。
6. **契约缺口实证登记**：后端 Roles 已正确赋值（student/owner/parent）但 `LoginPayload` 无 role 字段、extensions 恒空、无约定 key 语义 → 前端 role 只能 userName 映射；mock handler `loginByContext = db.queryOne()` 取第一条（mock 通道不按 userName 命中，**真实 WebApi 按白名单返回身份**——走查链路为真实 WebApi 故无碍，且 mock.g.ts 是生成物禁改）。

## 四、关键决策

| # | 决策 | 说明 |
|---|------|------|
| ① | resolveRole 为永久语义适配层（Oracle M1） | 后端"owner"是业务身份（群主），前端"teacher"是路由语义（老师端）——映射层不可随 extensions 透出而删除，只是输入源从 userName 变 extensions.role |
| ② | owner→teacher 前端映射（非后端改 Roles） | 后端 Roles 是契约语义（可能用于权限校验/数据过滤），改字符串影响面不可控；前端路由语义翻译是正确分层 |
| ③ | privacy 分跳修复（C3） | 原恒跳 /student/home 是**真实缺陷**（非仅走查问题）——owner01/parent01 首次登录落错端，本次按 role 分跳 |
| ④ | mock 通道不修（C1） | mock handler queryOne 取第一条是生成物（禁改）；走查链路是真实 WebApi（按白名单返回身份），mock 仅 dev 预览无碍 |
| ⑤ | id 策略（M2） | mockUser.id 用 'owner-1'/'parent-1'/'student-1' 占位并注释（非后端 userId 10001/2/3）；联调 mock 数据关联用 userId 字段直读，前端 id 不参与 |

- 真实微信授权流程：联调账号区块生产废弃，改真实微信绑定身份 → 后端判身份分跳
