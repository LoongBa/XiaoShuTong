**总评：通过**

V0.6.10 登记的好友发现配合项闭环——学生视角好友发现源从"无"到"同群学生成员候选列表"，邀请交互从纯 alert 模拟到真实 `inviteBuddy_Execute`。核心交付：

1. **搭子-BR-33/34 物化（B1）**：候选列表语义（同群 Role=Student 成员 + 排除自己/已有搭子关系 Pending/Accepted/Parent + Nickname 展示 + 多群去重）+ 只读权限（当前用户群成员身份，非群主专属，区别于 ManageGroupMembersService BR-08）。
2. **ListBuddyCandidatesService（S1）**：无参 ExecuteAsync → `{items: [{userId, nickname, groupId, groupName}]}`——GroupMembers 反查我的群 → 同 GroupId 学生成员 → StudyBuddies 双向排除已有关系 → Groups 一次取群名防 N+1 → GROUP BY UserId 去重。编译 0 警告 0 错误。
3. **前端 StudyBuddySection 改造（F1）**：邀请弹窗从 alert 模拟改真实——打开拉 `listBuddyCandidates_Execute`（再开重拉，C2）、行内邀请 → `inviteBuddy_Execute({inviteeUserId})`、错误码文案映射（6003/6005/6006/6002，6001 不映射 C3）、候选空态"暂无可邀请的同班同学"（C1）、保留复制链接/海报次要渠道（同年级跨群走此渠道，C4）。
4. **mock 补齐（F2）**：listBuddyCandidatesResDtos 3 候选；buildSchema+gen-mock 契约刷新（Services 67→68）。

## 四、关键决策

| # | 决策 | 说明 |
|---|------|------|
| ① | 候选源=同群成员（Oracle M1） | BR-16"同群组/同年级 OR"的充分子集——同群必满足，邀请不会触发 6006；同年级跨群后续按需 |
| ② | 后端新增 Service（Oracle M2 唯一正解） | members_Execute 群主专属（BR-08）学生不可用；后端聚合免 N+1 且不泄漏权限 |
| ③ | 排除已有关系不展示"已邀请"态（M3） | 候选纯净；"我邀请的人去哪了"出口=listBuddies ∪ 待收邀请列表（另一配合项，C5） |
| ④ | 多群去重 GROUP BY UserId（M4） | 同人跨群只出一条；groupName 取首个 |
| ⑤ | 6001 不映射 + 跨群走海报渠道（C3/C4） | 6001 只在 accept/reject 端"邀请不存在"触发；候选仅同群，跨群同年级走复制链接/海报 |
