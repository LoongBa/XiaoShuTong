│     ──────────────────────── ● ● ○  │
└─────────────────────────────────────┘

**AI 导师开场**（产品核心：AI 导师陪伴，不是"考试"）：

> 🤖 "咱们开始背《战国时期的社会变革》。今天的目标是：记住变法的人物、措施和影响。卡住随时点「想不起来？」，我给你线索——但不会直接报答案哦。"

**第一题（R1 补全记忆·上句接下句）**：商鞅变法的时间和成效是？

小宇努力回想："公元前…年…"卡住了 → 点「想不起来？」→ 三级提示逐级加深（S1 首字提示）：
- S1：`"时间是 3、5、6…"`（给数字范围，不给完整）
- 小宇："公元前 356 年！" → 判题关键词命中 `公元前356年`✅ `秦孝公`✅ `商鞅`✅
- **判题结果**：`正确（置信度 0.92）` → 绿色高亮 + ★ 点亮动画
> 🎉 "对！秦孝公任用商鞅主持变法。还记得它让秦国变成什么样了吗？"（AI 追问引导衔接）

**第二题（R1，另一知识点）**：商鞅变法的**政治**措施有？

小宇："确立县制、废除世袭特权…还有…严明法度…"漏了"建立户籍制度"。

**判题引擎（关键词同义词组比对）**：命中 `确立县制`✅ `废除世袭特权`✅ `严明法度`✅；缺失 `户籍制度`❌（权重 required=false）→ 命中率 ≈ 75% → **部分正确（△ 快熟了）**，橙色徽章

> 🤖 "答得不错！还差一点——政治措施有四条，你少了一条。提示：和'人口登记'有关。"
> 💡 记忆状态变化：`✕→△`

**第三题（R2 逆向补全·下句接上句）**：……都江堰发挥防洪、灌溉、水运等多方面作用，使成都平原成为「___」。

小宇："天府之国！" → 判题 `正确`（关键词 `天府之国` 完全命中）。

**任务完成庆祝页**：

```

  本次：答对 12 · 部分对 3 · 求助 1
  点亮 ★ 3 颗 ｜ 记忆状态：✕→△→○→★ 升级轨迹
  王老师已能看到你的进度（执行率 60%→100%）
```

> 📌 **产品机制**：任务闭环（群主布置→学生执行→进度回传看板）；R1/R2 题型 + 关键词同义词组判题 + 三级求助提示；判题反馈"正确/部分/错误 + 记忆状态变化"。

## 二、记忆状态流转总览（一个知识点的生命周期）

以"商鞅变法政治措施"为例：

| 时间 | 场景 | 表现 | 判题 | 状态 |
|------|------|------|------|------|
| 周一早 | 任务执行 | 漏"户籍制度" | 部分正确 | ✕→△ |
| 周一晚 | 30min 短复习 | 补全记忆 | 正确 | △→○ |
| 周四 | 复习队列 | 完整答出 | 正确 | ○→★ |
| 周六 | PK 对战 | 30s 内答出 | 正确 | ★（间隔→30 天） |
| 周日 | 家长报告 | 已点亮 | — | ★ 熟练 |

> **设计精髓**：每个场景都在"执行→反馈→状态迁移→下一个调度"循环里，AI 全程是**陪伴式导师**（容错 + 提示分级 + 鼓励），而非判官——这是小书童区别于传统背记工具的核心。

## 三、唐宋背记完整交互流程模拟（逐屏 UI + 接口调用）

> 真实依据：历史七下《中国历史》2024 修订版（隋唐 7 课 + 辽宋夏金元 6 课）、判题契约 `SubmitAttemptResDto`、求助契约 `GetHintResDto` 分档、复习队列 `GetReviewQueueResDto`、记忆状态机 ✕△○★。
> 真实接口：`submitAttempt_Execute` / `hint_Execute` / `reviewQueue_Execute` / `getNextQuestion_Execute`（GraphQL，走 `@tkwf/tsclient` 的 `Tkwf.User.Use<TService>()`）。

### 3.1 契约基础（AI 判题返回的结构化数据）

**`SubmitAttemptResDto`**（`submitAttempt_Execute` 返回，8 字段）：

```json
{
  "success": true,
  "result": "correct | partial | wrong",
  "confidence": 0.92,
  "matchedKeywords": ["秦孝公", "商鞅"],
  "missingKeywords": ["公元前356年"],
  "hint": "提示：年份里有个'4'，是 6 4 1",   // ≤20 字，判错/部分时才有意义
  "preState": "memorize",
  "postState": "fuzzy",
  "nextReviewAt": "2026-09-23T19:30:00+08:00"  // 艾宾浩斯调度
}
```

**引导/求助独立**：`GetHintResDto = { success, hint, difficultySlot: "s1|s2|s3", hintSource: "keyword|llm|card" }` —— 三级引导（S1 首字/意象 → S2 逻辑 → S3 分步）。

**复习队列**：`GetReviewQueueResDto = { success, items[], overdueCount }`。

#### 🖥 屏 2 · 任务执行页（第 1 题 = 复习穿插题）

**分支 A —— 学生答对（无需引导）**：小宇答"政治比较清明，经济恢复发展，国力增强，文教昌盛，各族友好关系进一步发展。"

**AI 返回**：

```json

  "matchedKeywords": ["政治清明","经济恢复","国力增强","文教昌盛","各族友好"],

```

#### 🖥 屏 3 · 第 2 题 = 新内容（学生答错 → 触发引导）

## 四、JEV 模型适配性分析

> JEV = Judge 判对错 → Encourage 鼓励/引导 → Verify 验证掌握。

| 环节 | 现状 | 完整性 |
|------|------|:---:|
| **J · 判对错** | 两层判题（本地关键词规则 → LLM 语义降级）+ `result`（correct/partial/wrong）+ `confidence` + `matchedKeywords/missingKeywords` | ✅ 完整 |
| **E · 鼓励/引导** | `hint`（≤20 字）+ 独立 `GetHintService`（S1/S2/S3 三档）+ 完成页鼓励语 + 状态升级动画 | ✅ 完整 |
| **V · 验证掌握** | 四阶状态机（✕△○★）`preState/postState/nextReviewAt`，通过间隔调度持续验证 | ✅ 完整 |

**结论**：**JEV 模型非常适合，且当前实现已是 JEV 的实例化**（3 个契合点：判题数据已结构化、前端无需自判"要不要引导"；E 粒度覆盖"引导/不引导/引导后仍错"全分支；V 由状态机承载，非一次性而是持续循环）。

**3 个缺口（严格对齐 JEV 时）**：

| # | 缺口 | 现状 | 建议 |
|---|------|------|------|
| 1 | 无显式"是否需要引导"标志位 | 前端靠 `result == partial/wrong` 推断 | `SubmitAttemptResDto` 加 `needsGuidance: bool` |
| 2 | 引导轮次上限未入契约 | 前端自己数 `attemptCount` | 加 `attemptCount` / `maxAttempts` |
| 3 | Verify 缺"扎实度"细粒度 | 只有 4 阶状态 | 可扩展 `masteryLevel`（近 20 次正确率的 0.5~1.5 系数，见 PRD） |

**最终结论**：后端契约（`SubmitAttemptResDto` + `GetHintResDto` + 状态机）**已覆盖 JEV 全部环节**，前端按契约分支即可实现"是否正确/是否引导/引导词/是否下一题"全部场景，**无需改后端**；严格对齐只需补 `needsGuidance` + `attemptCount` 两字段（后端 1 次小改）。
