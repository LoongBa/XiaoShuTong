## 一、系统概述

“小书童”是一款面向 **6-15 岁学生、群主和家长**的家校互动背书应用。核心理念是**“提升背书执行力”**：**群主布置任务 → 学生执行背诵 → 家长查看成长**。基于 **AI 导师引导**与**艾宾浩斯记忆原理**，通过记忆曲线调度、进度可视化、鼓励式反馈（★/进度条/热力图）、搭子社交与 PK 激励，帮助学生高效完成背诵任务，同时让家长了解孩子的学习进展。

不同于传统背诵工具，本产品以“引导容错”为核心——AI 从“评判者”转变为“陪伴式导师”，通过语义容错、求助引导、多模态交互、个性化复习与可视化激励，解决用户“背了就忘、难以坚持、内容泄露”等痛点，同时降低技术落地门槛，便于在师生、家长群中快速推广。

### 1.1 目标用户

| 角色 | 身份 | 核心诉求 | 端 |
|------|------|---------|-----|
| **学生** | 6-15 岁 | 每天查看群主布置的任务，完成任务获得星星，与搭子 PK 竞技，查看自己的学习进度 | H5（移动端） |
| **群主** | 群组授课教师 | 布置背诵任务，查看全群组执行进度，了解学生掌握情况，**可配置群组排名开关**（**永久免费**） | PC（教研端） |
| **家长** | 监护人 | 付费查看孩子的成长报告，了解学习进展与薄弱点（**付费节点**） | H5（移动端） |

### 1.2 核心使用场景

1. **学生每日任务**：打开 App → 查看今日任务 → 完成背诵 → 获得即时反馈 → 与搭子 PK → 查看进步
2. **群主布置任务**：选题源 → 选知识点 → 设定截止时间 → 发布任务 → 查看全群组执行进度 → 配置排名开关
3. **家长查看报告**：查看孩子今日完成情况 → 学习趋势与薄弱点 → 付费解锁完整报告（10 元/月 / 100 元/年）

## 二、核心产品逻辑：从“判官”转向“导师”

不同于传统 App “对即对，错即错”的机械判题，本方案强调 **“引导与容错”**，让 AI 从“评判者”转变为“陪伴式导师”：

- **语义容错**：利用 AI 识别关键词，允许口语化表达、同义表述（如“唐太宗”与“李世民”视为正确）。
- **求助引导**：用户卡壳时，AI 提供首字、意象或逻辑线索（如“科举制度的创立朝代，提示：与隋朝相关”），而非直接显示答案。
- **二次确认**：用户语音转文字后可手动微调再提交，避免口癖/结巴/识别误差导致误判。

### 2.1 AI 导师边界（V3.0 保留）

- **严禁直接给答案**：提示信息 ≤20 字，只能提供首字/意象/逻辑线索
- **判题三元结果**：`正确 / 部分正确 / 错误`，附置信度
- **判错纠错**：用户可一键“判错了”，反馈进入人工复核队列，计入判题质量统计
- **内容准确性**：AI 只判题不给新知识点解释，避免幻觉污染学习内容

### 2.2 家校互动主链路（V3.1 新增）

```
群主（PC）: 建群组 → 选题源（官方题库/我的资料库/自由编排）→ 布置任务（截止时间）→ 发到家长群 → 配置排名开关
学生（H5）: 首页看今日任务 → 进入任务执行 → 背诵判题 → 完成庆祝 → 复习队列按记忆曲线续背 → 与搭子 PK
家长（H5）: 看今日完成状态 → 坚持天数 → 本周进度 → 学科掌握度 → 付费解锁完整报告
```

- **任务闭环**：群主布置 → 学生执行 → 进度回传 → 群主看板呈现全群组执行率与薄弱点
- **激励闭环**：判题结果驱动记忆状态 → ★点亮 → 排行榜/热力图可视化 → 搭子 PK 竞技 → 分享战报传播
- **付费闭环**：学生留存数据 → 家长报告价值 → 订阅转化（家长为“知情权”付费）

### 2.3 社交关系数据模型（V3.1.2 对齐 D02，核心关系深挖）

> 基线表（Attempts/MemoryStates/StudySessions/DailyStats/KnowledgeMastery/WrongQuestions/Groups/GroupMembers/ParentStudentRelations/Tasks/TaskAssignments/PkMatches/PkPlayers/PkAttempts + Banks/Questions + Users）以 **D02 V1.4 为权威（另见 §四（三））**；本节聚焦 V3.1 新增的社交/排名/订阅关系链与 V3.1.3 内测邀请机制。**命名规范**：表名/列名一律大写驼峰（.NET 习惯），API endpoint 与 JSON 序列化由框架自动转小写驼峰兼容 H5/TS 前端。

**学习搭子 → PK → 排名 的底层关系链**（本版社交功能的数据根基）：

```
邀请关系（pending，7 天未响应 → expired）
   │ ──B 同意──▶ 搭子关系（accepted）──▶ PK 对战资格 + 排名互看
   │                        │
   └────────── 任一方可解除 → removed（历史数据保留）
                              ▼
Users ──< StudyBuddies >── Users（双向 accepted，≤5/人，应用层事务 + trigger 兜底）
     ──< PkMatches / PkPlayers / PkAttempts >──（仅 accepted 搭子；WinnerId + FinishReason）
     ──< RankSnapshots >──（Hangfire 每日冻结；PK 胜场 ← PkPlayerStats 视图计入战力榜）
     ──< Subscriptions >── ParentStudentRelations（家长→学生授权链，多孩子独立计费）
```

- **搭子 = PK 前置资格 + 排名互看特权**：只有互为 accepted 的搭子才能发起 PK、互看排名；解除后历史 PK/答题数据保留
- **PK 胜场反哺排名**：胜负由 `PkMatches.WinnerId` 判定（D02），胜场经 `PkPlayerStats` 视图聚合计入战力榜（不落表）
- **群组开关 = 合规闸门**：战绩榜（正确率维度）受 `Groups.RankEnabled` 控制，默认开启，群主可随时关闭
- **排名不实时落库**：`RankSnapshots` 由 Hangfire 每日 0:00(UTC+8) 批量冻结（避免实时存 Rank 的回溯漂移）；趋势箭头 = 今日 vs 昨日冻结快照对比

**设计语言基调**（对齐 UI v2）：清爽、鼓励感。避免“考试压迫感”，用**进度感**（★/进度条/热力图）代替“分数感”。学生端大按钮、图形化、奖励动画；家长/群主端信息密度高、表格化。判题后必须有【正确/错误 + 记忆状态变化】的即时视觉反馈，绝不只弹“打卡成功”。

### 阶段 1：家校互动背书闭环（MVP）—— 解决“记住了 + 家长看得见 + 搭子一起坚持”

目标：跑通**群主布置 → 学生背诵 → 家长看报告**闭环，叠加**搭子社交 + PK 激励**，建立自我激励与同伴激励双体系，验证核心背书功能与付费模型的实用性。

#### 1. 家校任务闭环（V3.1 新增，核心场景）

- **群主侧**：凭内测邀请码激活建群（群组名/学科/年级）→ 发布任务（选题源 → 配置 → 预览发布三步向导）→ 配置群组排名开关
- **任务属性**：任务名（默认“背诵《XXX》”）+ 截止时间（快捷项：明天/周末/自定义）+ 是否允许重做
- **学生侧**：首页任务卡片（最醒目）→ 任务执行页一次一题 → 进度点阵 → 完成庆祝页
- **进度回传**：群主看板实时呈现今日执行率、平均进度、逾期任务数、薄弱知识点 Top5
- **群主端导出**：群组执行周报（P1；MVP 内先以页面查看为主）

#### 2. 题库管理（私域简化 + 多学科）

1. **多学科体系**：语文/数学/英语/物理/化学/生物/历史/地理/政治。官方题库冷启动（语文 + 趣味免费引流；小三科为群主上传主战场）。
2. **导入与录入**：支持 `问题###答案` 格式的 .txt 结构化文本上传（单文件 ≤10M）、批量粘贴、单题手动录入/修改/删除、单元章节管理。**群主上传 PDF/Word/文本 → AI 预处理生成背诵点 → 人工校验后入库**（生产端工具链）。
3. **隐私保护（私域核心）**：默认所有题库、背诵记录私有，仅用户本人可见。
4. **基础分类标签**：按主题、难度分类 + 自定义标签（如“高频考点”“易错点”）。

#### 3. 四阶记忆状态追踪（核心）

基于艾宾浩斯记忆原理，将每道题的掌握情况量化为四个阶梯状态：

| 状态 | 含义 | 初始间隔 | 最大间隔 | 状态色（V3.1 明确） |
|------|------|:-------:|:-------:|:---:|
| ✕ 未掌握 | 答错/未形成记忆 | 12 小时 | 12 小时 | 灰“再背背” |
| △ 模糊 | 求助后才对 | 1 天 | 2 天 | 橙“快熟了” |
| ○ 掌握 | 独立答对 | 3 天 | 7 天 | 绿“很棒” |
| ★ 熟练 | 多次独立答对，长期记忆 | 7 天 | 30 天 | 金“点亮了” |

**状态转移矩阵（核心）**：

| 当前状态 | 独立答对 | 求助后答对 | 答错 |
|---------|:-------:|:---------:|:----:|
| ✕ | → △ | 停留 ✕ | 停留 ✕（重置间隔） |
| △ | → ○ | → △ | → ✕ |
| ○ | → ○（连续 2 次 → ★） | → △ | → △ |
| ★ | 停留 ★（间隔递增至 30 天） | → ○ | **→ ○（降一级）** |

**边界条件**：
- **首次背诵新题**：答错后 **30 分钟** 复习（艾宾浩斯科学间隔），而非 12 小时
- **“连续 2 次”**：跨 Session 累计，不清零；间隔 ≥7 天的复习答对也计入
- **跨天连续**：每日连续背诵天数按自然日计算，时区 = UTC+8
- **间隔计算**：`Next_Interval = 状态基础间隔 × 历史正确率系数（0.5~1.5）`
- **历史正确率**：近 20 次答题的正确率（含部分正确计 0.5）

#### 4. 可视化激励体系

1. **记忆热力图**：GitHub 风格全年图 + 本周横条（颜色深浅代表每日点亮 ★ 数量）。时间范围切换：本周/本月/本季度/今年/学习天数。
2. **错题本**（V3.1 新增）：错题列表（知识点/错因）→ 重练入口 → **连续答对 2 次转“已掌握”分组**（可“移回错题本”）。空态“没有错题，记得很牢！”。
3. **学习路线图（简化版）**：单元列表 + 完成率进度条 + 解锁状态（不做 Canvas 动画）。
4. **分享战报**（V3.1 新增）：热力图页底部“分享战报”按钮 → 弹窗支持 **4 种风格切换**（简约风/活力风/清新风/优雅风）→ 保存图片/复制文字/复制链接/朋友圈/微信群（MVP 为模拟分享）。

#### 5. 排行榜与学习搭子（V3.1 新增）

**排行榜**：
- **范围选择**：群组 / 年级（互斥按钮）
- **学科筛选**：下拉列表（全部/语文/数学/英语/物理/化学/生物/历史/地理/政治）
- **榜单类型**：
  - **战力榜**（按坚持天数 + 背诵量 + PK 胜场）
  - **战绩榜**（按正确率 + 掌握度）——**受群组全局开关控制**
- **群组全局开关（V3.1 用户决策）**：`Groups.RankEnabled` 默认 `true`（允许）；群主可在群组设置中关闭 → 该群组学生端**隐藏战绩榜入口、榜单不展示**（战力榜不受影响，本就合规）
- **排名列表**：排名序号（前三名特殊样式）+ 头像昵称 + 数值 + 趋势箭头（↑绿上升 / ↓红下降 / →灰持平）
- **排名趋势**：Hangfire 每日冻结排名快照至 `RankSnapshots`，生成趋势箭头（不实时存 Rank，避免回溯漂移）

**学习搭子（双向同意制）**：
- **关系建立流程**：A 发起邀请（海报二维码/链接）→ B 收到邀请确认页“XX 邀请你成为学习搭子”→ **同意 → 关系生效**（accepted）；B 可拒绝/忽略
- **搭子列表**：已添加搭子头像昵称（4-5 个一行），空位显示“+”按钮 → 邀请弹窗 → 生成邀请海报（含二维码）/ 链接
- **排名互看（V3.1 用户决策）**：搭子之间可互相看到对方在群组/年级范围内的**当前排名 + 趋势箭头**（学习搭子区域展示）；仅排名与数值，不暴露答题明细
- 最多 **5 个**搭子（accepted 状态双向约束）；可查看搭子连续打卡天数
- **解除**：任一方可解除搭子关系，PK/答题历史保留
- 无搭子空态：“还没有学习搭子，快邀请好友一起学习吧！”

#### 6. 搭子 PK 竞技（V3.1 纳入 MVP）

**前置条件**：仅限**互为 accepted 的搭子**之间对战（搭子 = PK 资格）。

- **发起方式 A**：从搭子列表选对手 → 选学科/题库范围 + 题量（默认 10 题）→ 对手确认 → 双方就绪开局
- **发起方式 B**：生成 4 位对战码 → 分享给搭子输入加入
- **对战规则**：双方同题同序，每题 30s 倒计时（视觉红条），答对 +10 即时反馈，自动下一题；同分比用时
- **实时性**：SignalR 实时同步，微信 H5 降级 30s 轮询（30s 倒计时下仍流畅）
- **结果页**：胜/负/平 + 双方得分 + **AI 趣味点评**（个性亮点/薄弱点/知识彩蛋，如“你《滕王阁》背得飞快，杜甫的《登高》还差点火候”）
- **数据反哺**：pk_matches 记录胜负 → **PK 胜场计入战力榜排名指标**
- **掉线处理**：对手离线 30s → 判弃权，己方获胜
- **合规**：PK 结果只展示 ★数/用时，**不出现正确率对比榜**

#### 7. 家长成长报告（付费产品，V3.1 明确）

- **成长总览 dashboard**：孩子信息 + 多孩子切换 + 今日任务完成状态 + 坚持天数 + 本周进度 + 各学科掌握度概览
- **进度趋势 progress**：正确率/背诵量时间曲线（周/月切换）
- **薄弱知识点 weakness**：知识点-掌握度矩阵（可下钻到具体篇目）
- **付费规则**：试用期 7 天 → 订阅 **10 元/月或 100 元/年** → **多孩子独立计费** → 到期报告区锁定置灰
- **付费体验**：未付费时报告区预览前 2 项 + 模糊遮罩 + “开通”CTA；试用中黄条倒计时；已订阅隐藏付费入口，提供“管理订阅/取消续费”
- **报告内容红线**：只呈现**相对进步**（本周 vs 上周：多背了 N 篇、薄弱点迁移、坚持天数），**不显示群组正确率排名**（合规）

#### 8. 基础背记交互（Session）

**答题 Session 配置**：

| 参数 | 默认 | 可选 |
|------|:----:|------|
| 题目数 | 20 | 10/20/30/50 |
| 新题/复习混合比 | 30% 新题 + 70% 复习 | 可配置 |
| 排序 | 到期复习优先 → 未掌握优先 → 新题 | - |
| 结束条件 | 做完任务 / 主动退出（进度保存） | - |
| 跳过 | 允许，跳过不改变记忆状态 | - |
| 退出保存 | 中途退出自动保存已答记录 | - |

**交互流程**：
1. 展示题目 → 2. 用户文字输入（强制系统语音输入法）→ 3. 提交判题 → 4. 判题结果（正确/部分/错误 + 引导提示）→ 5. 可点击“想不起来？”（≤20 字线索，S1 首字 → S2 意象 → S3 逻辑逐级加深）→ 6. 记录结果，更新记忆状态

**判题反馈规则**：
- 正确：绿色高亮 + ★点亮动画 + 鼓励语
- 错误：红色高标 + 正确句展示 + “再看一遍”/“下一题”双按钮
- 求助后答对：黄色△徽章（收益低于独立答对）
- 完成任务 ≠ 打卡成功：必须展示“背对了哪几句、哪句还卡着”

**多模态说明**：
- **输入**：文字输入（强制系统语音输入法），**禁用浏览器 MediaRecorder ASR**
- **输出**：浏览器内置 TTS 朗读（Web Speech API），Phase 2 评估 Edge-TTS

#### 9. AI 导师判题（分层架构）

**两层判题架构**：

```
第一层：本地关键词匹配（零成本）
  ├── 题目预置关键词（导入时自动提取/人工补充）
  ├── 用户答案含 ≥80% 关键词 → 直接判"正确"
  └── 命中率 <80% → 进入第二层
第二层：LLM 语义判题（OpenAI API 兼容接口，LLM 供应商不限：火山引擎/DeepSeek/智谱等）
  ├── 超时（>3s）或失败 → 降级本地规则引擎 + 提示用户
  ├── 返回 result / confidence / matched / missing / hint
  └── 置信度 <0.5 判错误，0.5-0.85 判部分正确，≥0.85 判正确
```

**判题接口契约**：

```json
{
  "result": "correct | partial | wrong",
  "confidence": 0.92,
  "matched_keywords": ["唐太宗", "贞观"],
  "missing_keywords": ["年号"],
  "hint": "提示：与年号有关"
}
```

### 阶段 2：群组社交版 —— 解决“坚持住”

目标：引入私域社交（群组/家委会），利用同伴压力与群体激励，提升用户粘性。

1. **群主特权模式**：群主创建学习群组、上传题库、分发背诵任务；可查看组员背诵进度、记忆状态（**授权边界：群主仅可见任务相关数据的统计汇总，题目内容按 DRM 规则**）。
2. **动态激励日志**：群动态（“XXX 完成了 △→○ 跃迁”）；非分数排名（仅展示坚持天数 + ★ 增长数，不做分数排名）。
3. **群组成就汇总**：群主一键导出全群组背诵进度周报。
4. **基础社交互动**：群内分享题库、背诵心得；好友添加、互看进度（双向授权，复用阶段 1 搭子关系）。

**群组 DRM 规则**：
- **引用而非复制**：组员仅获得题库的访问引用，不可导出/转发原文
- **群主撤回题库**：历史学习记录保留，但题目原文不可见（显示“题目已下线”）
- **防爬**：题库接口“背一题取一题”按需加载，不返回明文列表

### 阶段 3：生态扩展版 —— 解决“内容源”

1. **AI 智能助手**：PDF/图片转题库（技术成熟后）。
2. **题库市集与版权保护**：付费题库分享（作者收益）+ 免费题库分享；DRM 采用**账号绑定 + 水印 + 服务端分段渲染 + 法律条款**组合（Web 端无传统 DRM，需组合方案）。
3. **高级 AI 功能**：个性化提示（根据易错点调整）、AI 错题分析、针对性复习建议。
4. **商业化拓展**：会员服务（批量导出、AI 题库生成、专属激励标识）；教育类广告（合规前提：不对未成年人推送个性化广告）。

## 四、核心技术方案

### （一）终端与架构

1. **形态选择**：**微信 H5（首期）+ 小程序（迁移预留）**
   - 首期 H5 即点即用，适配微信私域分享
   - 前端基于 **React + shadcn/ui**，后期经 **Taro**（React 语法）迁移小程序（ADR-007）
2. **系统架构**：分层架构
   `用户层（React H5 / PC）→ 应用服务层（ASP.NET Core Web API）→ 数据存储层（PostgreSQL + Redis）→ 外部服务层（OpenAI 兼容 LLM：火山引擎/DeepSeek 等）`
3. **用户认证**：微信授权登录为主，首次登录需同意隐私协议；未成年人（<14 岁）需监护人同意。

### （二）技术选型（V3.1 修订，对齐 ADR-007）

| 层 | 选型 | 说明 |
|----|------|------|
| 前端 H5（学生/家长） | **React + shadcn/ui + Vite** | ADR-007：AI 协作开发友好度优先；首屏 ≤5s 目标 |
| 前端 PC（群主教研） | **React + shadcn/ui**（复用 H5 组件） | 群组/任务/看板/资料库/排名开关 |
| 小程序（延后） | **Taro（React 语法）** | 微信接入开放后启动；React H5 组件大部分可复用 |
| 后端 | **ASP.NET Core (.NET 10) + Web API** | RESTful API；SignalR 实时群动态与 PK 对战（微信 H5 降级 30s 轮询） |
| 数据库 | PostgreSQL | JSONB 存标签/元数据；RLS 行级安全（数据隔离） |

### （五）安全与合规

1. **未成年人数据**（个保法第 28-31 条）：
   - 不满 14 周岁用户须监护人同意（注册流程弹窗）

2. **隐私协议**：首次登录弹出，说明 AI 判题数据脱敏流程
3. **内容安全**：接入内容审核 API + 举报入口
4. **数据所有权**：明确用户数据归用户所有，可导出、可注销
5. **数据权限**（V3.1 明确）：
   - 学生只能看到自己的学习数据
   - 群主可以看到所带群组的学生数据（含排名开关配置权）
   - 家长只能看到自己孩子的学习数据
   - 付费报告需要订阅后才能查看完整内容
6. **排名合规红线**（V3.1 明确，对齐战略 V1 + 群组开关）：
   - ❌ 禁止：群组正确率排名对外暴露、优秀率、及格率、平均分对比、“X 群组倒数第 N”
   - ✅ 允许：坚持天数、完成度、★数、PK 胜场、个人与上周对比（仅与自己比）
   - ✅ **群组全局开关**：战绩榜（正确率维度）默认开启，但群主可一键关闭——把“是否允许正确率排名”的最终决定权交给群组（学校），平台默认不强制
   - ✅ 学习搭子排名互看：仅限互为 accepted 搭子，仅见排名与数值，不见答题明细（最小化暴露）

|----|------|
| 关系建立 | **双向同意**：A 发起邀请（海报二维码/链接）→ B 确认“XX 邀请你成为学习搭子”→ 同意 → 关系生效；B 可拒绝/忽略 |
| 状态机 | pending（邀请中）→ accepted（已搭子）/ rejected（已拒绝）/ removed（已解除）/ **expired**（7 天未响应，`ExpiresAt` + Hangfire 清理） |
| 数量上限 | accepted 状态下每用户 ≤5 个搭子（双向约束，超出需先解除旧搭子） |
| 排名互看 | 搭子之间互看对方在群组/年级范围的当前排名 + 趋势箭头（仅排名与数值，不暴露答题明细） |
| 可见性 | 可查看搭子的连续打卡天数 |
| 解除 | 任一方可解除搭子关系；PK/答题历史保留，不影响学习数据 |
| 未成年人保护 | 搭子邀请默认限定**同群组/同年级**用户（防陌生人社交）；单日发出邀请 ≤10 次（Redis 计数器 `buddy_invite_quota:{UserId}:{date}`） |
| 空态 | “还没有学习搭子，快邀请好友一起学习吧！” |

### 5.3 排名趋势规则（V3.1.2 快照制）

| 项 | 规则 |
|----|------|
| 计算方式 | **Hangfire 每日 0:00(UTC+8) 批量冻结**至 `RankSnapshots`（不实时写、不回溯漂移）；趋势箭头 = 今日 vs 昨日冻结快照 |
| 排名指标 | 战力榜 = 坚持天数 + 背诵量 + **PK 胜场**；战绩榜 = 正确率 + 掌握度（受群组开关控制） |
| 群组开关 | `Groups.RankEnabled` 默认 true；群主关闭后该群组**战绩榜入口隐藏、榜单不展示**（战力榜不受影响） |
| 上升 | 绿色 ↑ 箭头 |
| 下降 | 红色 ↓ 箭头 |
| 持平 | 灰色 → 箭头 |
| 搭子互看 | 搭子之间互相可见对方当前排名与趋势（读取 `RankSnapshots` 最新冻结快照，仅排名与数值，不暴露答题明细） |

### 5.4 搭子 PK 规则（V3.1 纳入 MVP）

| 项 | 规则 |
|----|------|
| 参与资格 | 仅限**互为 accepted 的搭子**；可从搭子列表选对手发起，或分享 4 位对战码加入 |
| 对战范围 | 选学科/题库范围 + 题量（默认 10 题） |
| 对战规则 | 双方同题同序，每题 30s 倒计时，答对 +10，同分比用时 |
| 结果 | 胜/负/平（`PkMatches.WinnerId` 判定）+ 双方得分 + AI 趣味点评；结束原因 `FinishReason`(score/forfeit/timeout) |
| 胜场记录 | `PkPlayerStats` 视图聚合胜场 → **PK 胜场计入战力榜排名指标**（PK 答题不入 Attempts，对齐 D02 场景隔离） |
| 实时性 | SignalR 实时同步，微信 H5 降级 30s 轮询（30s 倒计时下仍流畅） |
| 掉线处理 | 对手离线 30s → 判弃权，己方获胜 |
| 合规 | PK 结果只展示 ★数/用时，**不出现正确率对比榜** |

### 5.5 异常与边界情况

| 场景 | 处理方式 |
|------|----------|
| 首页无任务 | 显示引导卡“群主还没布置任务，先去自由背诵吧” + 按钮直达自由背诵 |
| 无到期复习 | 复习区块隐藏，不占位 |
| 任务已截止 | 任务卡红色截止标“已截止”，进度条半透明 |
| 题目加载失败 | 居中占位“题目加载失败” + 重试按钮 |
| 网络断开 | Toast“网络开小差了” + 重试按钮 |
| 空错题本 | “没有错题，记得很牢！”正面空态 |
| 未解锁学科 | 弹层说明“需要群主布置后开启” |
| 无学习搭子 | “还没有学习搭子，快邀请好友一起学习吧！” |
| 分享失败 | Toast“分享失败，请重试” + 重试按钮 |
| 家长无数据 | “孩子还没有学习记录，让他/她背第一首诗吧”引导空态 |
| 搭子邀请过期/被拒 | Toast 提示，可重新邀请 |
| 搭子已满 | 提示“搭子数量已达上限（5 个），先解除旧搭子” |
| 群组战绩榜关闭 | 隐藏战绩榜入口，显示“群主关闭了战绩榜” |
| PK 对手离线 | 30s 后判弃权，己方获胜 |
| PK 中网络断开 | 断线重连，进度保留；重连失败按离线处理 |
| 非搭子发起 PK | 拦截并提示“仅好友（搭子）之间可以 PK” |

**通用交互约定**：空态必须三步式（发生了什么 + 为什么 + 下一步做什么）；加载态用骨架屏；错误反馈用 Toast + 重试，不做全屏错误页（除硬加载失败）。

## 六、可行性分析

### （一）技术可行性

- 核心技术成熟：四阶记忆算法基于艾宾浩斯优化，规则引擎可实现；AI 判题依赖 OpenAI 兼容接口，供应商可替换，技术门槛低
- **React + shadcn/ui 生态成熟、AI 生成通过率高**（ADR-007 决策依据），H5 + PC 共享组件，微信兼容性好
- PK 对战基于 SignalR + 轮询降级，30s 倒计时场景对实时性要求可控
- 分阶段落地：阶段1 核心功能 3-4 个月完成 MVP

### （二）成本可行性

- **AI 判题成本模型**：本地关键词拦截约 60-70% 请求 → 实际 LLM 调用量 = 总答题数 × 30-40%；按 500 日活 × 30 题/日 × 35% × ¥0.005/题 ≈ **¥780/月**
- PK 的 AI 点评复用判题 LLM（按局计费，量级远低于判题，可缓存模板兜底）
- 服务器：云服务器基础配置 ¥200-500/月
- 开发人力：2 前端（React）+ 1 后端 + 1 产品，3-4 个月

### （三）用户体验可行性

- 核心流程（群主布置 → 学生背诵 → 家长报告）步骤清晰，微信 H5 即点即用
- 排行榜/学习搭子/PK/热力图/分享战报均为努力度激励（非分数），避免焦虑化
- 搭子 PK 强化同伴激励（好友之间比坚持），比陌生榜单更贴合 6-15 岁心理
- 离线 LocalStorage 暂存，弱网/无网可继续答题，联网后同步

### （四）市场可行性

- 需求明确：学生、群主、家长对“高效背诵、私域保护、坚持学习”需求旺盛
- 差异化：AI 导师化 + 四阶记忆 + 家校互动 + 搭子 PK + 非分数激励 + 家长付费报告
- 推广：微信 H5 群内分享，群主/家长为核心传播节点，冷启动成本低
- 变现验证：家长报告为付费锚点（10 元/月），学生留存 + 搭子社交驱动转化

### （五）潜在挑战与应对

| 风险 | 影响 | 对策 |
|------|------|------|
| AI 判题准确性 | 误判挫伤用户 | 题型限客观问答；置信度阈值校准；人工反馈机制 |
| 用户数据安全 | 隐私泄露 | AES-256 + TLS1.3 + 脱敏 + RLS 行级安全 |
| 冷启动题库不足 | 体验下降 | 官方基础题库 + 群主上传奖励 + 私域传播 |
| 微信 H5 功能限制 | 推送/录音受限 | 强制系统输入法；LocalStorage 离线；Taro 迁移预案 |
| AI 判题成本失控 | 商业不成立 | 两层架构拦截 + 单用户 API 上限 + 缓存 |
| 未成年人合规 | 法律风险 | 监护人同意 + 最小化收集 + 30 天注销删除 |
| 排名合规风险 | 政策/舆论风险 | 排名只指向努力度 + **群组全局开关**（战绩榜群主可关） |
| 陌生人社交风险 | 未成年人安全 | 搭子邀请限定同群组/同年级 + 单日邀请上限 + 举报入口 |
| 家长付费转化低 | 商业不成立 | 报告强调“相对进步”而非焦虑榜；试用 7 天钩子 |

## 八、备忘录：迁移小程序/原生 App 的触发条件

1. **强力系统级推送**：特定复习点需强制通知，H5 无法实现
2. **息屏/后台语音交互**：锁屏背诵、后台持续录音
3. **深度群社交集成**：需微信群列表、群成员敏感 API
4. **复杂功能扩展**：直播背书、实时连麦等

**迁移预案（V3.1 修订）**：
- 前端基于 React，H5 → 小程序经 **Taro**（React 语法）迁移，组件/逻辑大部分可复用，预估成本 2-3 周
- 数据层 API 不变，仅前端适配
- 触发条件达成时启动专项评估（数据迁移、成本、排期）
