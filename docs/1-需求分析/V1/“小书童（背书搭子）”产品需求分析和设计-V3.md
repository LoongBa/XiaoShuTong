## 一、系统概述

“小书童”是一款基于 **AI 导师引导**与**艾宾浩斯记忆原理**的私域背记工具。其核心逻辑是：**“由专业人士（老师/家长）提供高质量内容，由 AI 导师陪伴学生完成从模糊到熟练的记忆跃迁。”**

不同于传统背诵工具，本产品以“引导容错”为核心，通过多模态交互、个性化复习、私域社交与可视化激励，解决用户“背了就忘、难以坚持、内容泄露”等痛点，同时降低技术落地门槛，便于在师生、家长群中快速推广。

### 1.1 修订要点（相对 V2）

| 修订项 | V2 | V3（本次修订） |
|--------|----|---------------|
| 前端技术栈 | Blazor WebAssembly | **Vue3 + Uni-app**（放弃 Blazor，为小程序迁移预留） |
| 后端技术栈 | ASP.NET Core + Blazor Server | **ASP.NET Core + Web API**（Blazor Server 概念混淆已修正） |
| 产品形态 | 微信 H5 + PWA | **微信 H5（首期）+ 小程序（迁移预留）** |
| 记忆算法 | 固定间隔（12h/1d/3d/7d） | **固定间隔 + 正确率系数（MVP），Phase 2 引入 SM-2** |
| 首次复习 | 12 小时 | **30 分钟（艾宾浩斯科学间隔）** |
| ★ 答错降级 | 未定义 | **★→○（降一级，SM-2 实践）** |
| AI 判题 | 每次调大模型 | **两层：本地关键词 → LLM 语义** |
| 离线功能 | 离线成就报告 | **LocalStorage 暂存 + 联网增量同步** |
| 语音输入 | 手机自带输入法 | **强制系统语音输入法**（明确禁用浏览器 ASR） |
| 路线图 | Canvas 动画 | **保留但简化**（单元列表+完成率进度条） |

## 二、核心产品逻辑：从“判官”转向“导师”

不同于传统 App “对即对，错即错”的机械判题，本方案强调 **“引导与容错”**，让 AI 从“评判者”转变为“陪伴式导师”：

- **语义容错**：利用 AI 识别关键词，允许口语化表达、同义表述（如“唐太宗”与“李世民”视为正确）。
- **求助引导**：用户卡壳时，AI 提供首字、意象或逻辑线索（如“科举制度的创立朝代，提示：与隋朝相关”），而非直接显示答案。
- **二次确认**：用户语音转文字后可手动微调再提交，避免口癖/结巴/识别误差导致误判。

### 2.1 AI 导师边界（V3 新增）

- **严禁直接给答案**：提示信息 ≤20 字，只能提供首字/意象/逻辑线索
- **判题三元结果**：`正确 / 部分正确 / 错误`，附置信度
- **判错纠错**：用户可一键“判错了”，反馈进入人工复核队列，计入判题质量统计
- **内容准确性**：AI 只判题不给新知识点解释，避免幻觉污染学习内容

## 三、功能规划（三步走战略）

### 阶段 1：核心背记版（MVP）—— 解决“记住了”

目标：跑通**单人背诵闭环**，建立自我激励体系，验证核心背记功能的实用性。

#### 1. 题库管理（私域简化）

1. **导入与录入**：支持 `问题###答案` 格式的 .txt 结构化文本上传（单文件 ≤10M）、批量粘贴、单题手动录入/修改/删除、单元章节管理。
2. **隐私保护（私域核心）**：默认所有题库、背诵记录私有，仅用户本人可见。
3. **基础分类标签**：按主题、难度分类 + 自定义标签（如“高频考点”“易错点”）。

#### 2. 四阶记忆状态追踪（核心升级，V3 精确定义）

基于艾宾浩斯记忆原理，将每道题的掌握情况量化为四个阶梯状态：

| 状态 | 含义 | 初始间隔 | 最大间隔 |
|------|------|:-------:|:-------:|
| ✕ 未掌握 | 答错/未形成记忆 | 12 小时 | 12 小时 |
| △ 模糊 | 求助后才对 | 1 天 | 2 天 |
| ○ 掌握 | 独立答对 | 3 天 | 7 天 |
| ★ 熟练 | 多次独立答对，长期记忆 | 7 天 | 30 天 |

**状态转移矩阵（V3 新增，核心）**：

| 当前状态 | 独立答对 | 求助后答对 | 答错 |
|---------|:-------:|:---------:|:----:|
| ✕ | → △ | 停留 ✕ | 停留 ✕（重置间隔） |
| △ | → ○ | → △ | → ✕ |
| ○ | → ○（连续 2 次 → ★） | → △ | → △ |
| ★ | 停留 ★（间隔递增至 30 天） | → ○ | **→ ○（降一级）** |

**边界条件**：
- **首次背诵新题**：答错后 **30 分钟** 复习（艾宾浩斯科学间隔），而非 12 小时
- **“连续 2 次”**：跨 Session 累计，不清零；间隔 ≥7 天的复习答对也计入
- **跨天连续**：每日连续背诵天数按自然日计算，时区 = UTC+8
- **间隔计算**：`Next_Interval = 状态基础间隔 × 历史正确率系数（0.5~1.5）`
- **历史正确率**：近 20 次答题的正确率（含部分正确计 0.5）

#### 3. 可视化激励体系（V3 简化）

1. **记忆热力图**：借鉴 GitHub 贡献图，颜色深浅代表每日点亮 ★ 的数量（Canvas 实现）。
2. **学习路线图（简化版）**：单元列表 + 完成率进度条 + 解锁状态（不做 Canvas 动画）。
3. **离线成就报告**：导出“Todo + Checklist”报表（可打印 HTML/PDF），含当日复习任务、完成情况、未掌握题目。

#### 4. 基础背记交互（V3 明确 Session 定义）

**答题 Session 配置（V3 新增）**：

| 参数 | 默认 | 可选 |
|------|:----:|------|
| 题目数 | 20 | 10/20/30/50 |
| 新题/复习混合比 | 30% 新题 + 70% 复习 | 可配置 |
| 排序 | 到期复习优先 → 未掌握优先 → 新题 | - |
| 结束条件 | 做完任务 / 主动退出（进度保存） | - |
| 跳过 | 允许，跳过不改变记忆状态 | - |
| 退出保存 | 中途退出自动保存已答记录 | - |

**交互流程**：
1. 展示题目 → 2. 用户文字输入（系统语音输入法）→ 3. 提交判题 → 4. 判题结果（正确/部分/错误 + 引导提示）→ 5. 可点击“请提示我”（≤20 字线索）→ 6. 记录结果，更新记忆状态

**多模态说明（V3 澄清）**：
- **输入**：文字输入（强制系统语音输入法），**禁用浏览器 MediaRecorder ASR**
- **输出**：浏览器内置 TTS 朗读（Web Speech API），Phase 2 评估 Edge-TTS

#### 5. AI 导师判题（V3 明确分层架构）

**两层判题架构**：

```
第一层：本地关键词匹配（零成本）
  ├── 题目预置关键词（导入时自动提取/人工补充）
  ├── 用户答案含 ≥80% 关键词 → 直接判"正确"
  └── 命中率 <80% → 进入第二层
第二层：LLM 语义判题（火山引擎大模型 API）
  ├── 超时（>3s）或失败 → 降级本地规则引擎 + 提示用户
  ├── 返回 result / confidence / matched / missing / hint
  └── 置信度 <0.5 判错误，0.5-0.85 判部分正确，≥0.85 判正确
```

**判题接口契约（V3 新增）**：

```json
{
  "result": "correct | partial | wrong",
  "confidence": 0.92,
  "matched_keywords": ["唐太宗", "贞观"],
  "missing_keywords": ["年号"],
  "hint": "提示：与年号有关"
}
```

### 阶段 2：群组社交版 —— 解决“坚持住”

目标：引入私域社交（班级/家委会），利用同伴压力与群体激励，提升用户粘性。

1. **群主特权模式**：群主创建学习群组、上传题库、分发背诵任务；可查看组员背诵进度、记忆状态（**授权边界：群主仅可见任务相关数据的统计汇总，题目内容按 DRM 规则**）。
2. **动态激励日志**：群动态（“XXX 完成了 △→○ 跃迁”）；非分数排名（仅展示坚持天数 + ★ 增长数，不做分数排名）。
3. **班级成就汇总**：老师一键导出全班背诵进度周报。
4. **基础社交互动**：群内分享题库、背诵心得；好友添加、互看进度（双向授权）。

**群组 DRM 规则（V3 明确）**：
- **引用而非复制**：组员仅获得题库的访问引用，不可导出/转发原文
- **群主撤回题库**：历史学习记录保留，但题目原文不可见（显示“题目已下线”）
- **防爬**：题库接口“背一题取一题”按需加载，不返回明文列表

### 阶段 3：生态扩展版 —— 解决“内容源”

1. **AI 智能助手**：PDF/图片转题库（技术成熟后）。
2. **题库市集与版权保护**：付费题库分享（作者收益）+ 免费题库分享；DRM 采用**账号绑定 + 水印 + 服务端分段渲染 + 法律条款**组合（Web 端无传统 DRM，需组合方案）。
3. **高级 AI 功能**：个性化提示（根据易错点调整）、AI 错题分析、针对性复习建议。
4. **商业化拓展**：会员服务（批量导出、AI 题库生成、专属激励标识）；教育类广告（合规前提：不对未成年人推送个性化广告）。

## 四、核心技术方案

### （一）终端与架构

1. **形态选择**：**微信 H5（首期）+ 小程序（迁移预留）**
   - 首期 H5 即点即用，适配微信私域分享
   - 代码基于 **Uni-app** 开发，后期可平滑迁移小程序
2. **系统架构**：分层架构
   `用户层（Vue3/Uni-app H5）→ 应用服务层（ASP.NET Core Web API）→ 数据存储层（PostgreSQL + Redis）→ 外部服务层（火山引擎 LLM 等）`
3. **用户认证**：微信授权登录 + 手机号快速绑定（可选，见合规）。

### （二）技术选型（V3 修订）

| 层 | 选型 | 说明 |
|----|------|------|
| 前端 | **Vue3 + Uni-app** | 放弃 Blazor WASM（微信 X5 加载风险）；Vite 构建；首屏 ≤5s 目标 |
| 后端 | **ASP.NET Core + Web API** | RESTful API；SignalR 实时群动态（微信 H5 降级为 30s 轮询） |
| 数据库 | PostgreSQL | JSONB 存标签/元数据；RLS 行级安全（数据隔离） |
| 缓存 | Redis | 高频题库缓存、当前记忆状态、群动态 |
| AI 判题 | 火山引擎大模型 API | 两层架构，LLM 仅处理模糊判定 |
| 语音 TTS | 浏览器 Web Speech API | Phase 2 评估 Edge-TTS（免费、真人音质） |
| 语音 ASR | 强制系统输入法 | 禁用浏览器录音 |
| 任务调度 | Hangfire | 复习计划推送、过期任务提醒 |
| 防爬 | 按题抓取接口 | 不返回题库明文列表 |

### （三）数据模型（V3 新增，7 张核心表）

| 表 | 核心字段 |
|----|---------|
| `users` | id, openid, phone(脱敏), nickname, role, created_at |
| `banks`（题库） | id, owner_id, title, description, privacy, tags, created_at |
| `chapters`（章节） | id, bank_id, name, parent_id, sort_order |
| `questions`（题目） | id, chapter_id, question, answer, keywords[], difficulty, status |
| `answer_records`（答题记录） | id, user_id, question_id, pre_state, post_state, result, confidence, hint_used, answered_at |
| `memory_states`（记忆状态） | id, user_id, question_id, state(✕△○★), ease_factor(预留), next_review_at(独立索引), history_accuracy, consecutive_correct |
| `tags`（标签） | id, user_id, name, color |

**索引要求**：`memory_states.next_review_at` 独立索引（复习队列查询）；`answer_records (user_id, answered_at)` 复合索引。

### （四）非功能需求（V3 量化）

| 指标 | 目标 |
|------|------|
| 首屏加载 | ≤5s（微信内置浏览器，中低端安卓） |
| API 响应 | P95 ≤500ms |
| AI 判题 | P95 ≤3s（超时 3s 降级本地） |
| 并发 | ≥500 用户 |
| 可用性 | ≥99.9%（阶段1） |
| 兼容性 | 微信 8.0.30+，iOS 15+ / Android 10+ |
| 限流 | 单用户 60 次/分，单 IP 限流 |
| 存储加密 | AES-256 + HTTPS TLS1.3 |
| 手机号 | 存储脱敏（138****1234） |

### （五）安全与合规（V3 新增）

1. **未成年人数据**（个保法第 28-31 条）：
   - 不满 14 周岁用户须监护人同意（注册流程弹窗）
   - 收集最小化：仅 openid + 昵称 + 答题数据
   - 数据留存：账号注销后 30 天删除全部数据
2. **隐私协议**：首次登录弹出，说明 AI 判题数据脱敏流程
3. **内容安全**：接入内容审核 API + 举报入口
4. **数据所有权**：明确用户数据归用户所有，可导出、可注销

## 五、可行性分析

### （一）技术可行性

- 核心技术成熟：四阶记忆算法基于艾宾浩斯优化，规则引擎可实现；AI 判题依赖火山引擎 API，技术门槛低
- **Vue3 + Uni-app 生态成熟**，微信兼容性好，社区资源丰富（V3 修订：相比 Blazor 降低兼容风险）
- 分阶段落地：阶段1 核心功能 3-4 个月完成 MVP

### （二）成本可行性（V3 修正）

- **AI 判题成本模型（新增）**：本地关键词拦截约 60-70% 请求 → 实际 LLM 调用量 = 总答题数 × 30-40%；按 500 日活 × 30 题/日 × 35% × ¥0.005/题 ≈ **¥780/月**
- 服务器：云服务器基础配置 ¥200-500/月
- 开发人力：2 前端（Vue）+ 1 后端 + 1 产品，3-4 个月

### （三）用户体验可行性

- 核心流程（录入→背诵→复习）步骤清晰，微信 H5 即点即用
- 非分数排名 + 热力图 + 简化路线图，激励性强且避免焦虑化
- 离线 LocalStorage 暂存，弱网/无网可继续答题，联网后同步

### （四）市场可行性

- 需求明确：学生、考证人群、老师、家长对“高效背诵、私域保护、坚持学习”需求旺盛
- 差异化：AI 导师化 + 四阶记忆 + 私域保护 + 非分数激励
- 推广：微信 H5 群内分享，老师/家长为核心传播节点，冷启动成本低

### （五）潜在挑战与应对

| 风险 | 影响 | 对策 |
|------|------|------|
| AI 判题准确性 | 误判挫伤用户 | 题型限客观问答；置信度阈值校准；人工反馈机制 |
| 用户数据安全 | 隐私泄露 | AES-256 + TLS1.3 + 脱敏 + RLS 行级安全 |
| 冷启动题库不足 | 体验下降 | 官方基础题库 + 老师上传奖励 + 私域传播 |
| 微信 H5 功能限制 | 推送/录音受限 | 强制系统输入法；LocalStorage 离线；迁移小程序预案 |
| AI 判题成本失控 | 商业不成立 | 两层架构拦截 + 单用户 API 上限 + 缓存 |
| 未成年人合规 | 法律风险 | 监护人同意 + 最小化收集 + 30 天注销删除 |

## 七、备忘录：迁移小程序/原生 App 的触发条件

1. **强力系统级推送**：特定复习点需强制通知，H5 无法实现
2. **息屏/后台语音交互**：锁屏背诵、后台持续录音
3. **深度群社交集成**：需微信群列表、群成员敏感 API
4. **复杂功能扩展**：直播背书、实时连麦等

**迁移预案（V3 新增）**：
- 前端已基于 Uni-app，H5→小程序迁移成本预估 2-3 周
- 数据层 API 不变，仅前端适配
- 触发条件达成时启动专项评估（数据迁移、成本、排期）
