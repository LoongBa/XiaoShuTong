# 搭子待收邀请闭环 - 开发方案（V0.6.18）

## 一、背景与目标

### 1.1 背景

V0.6.10 审核报告 §七 登记配合项："待收邀请列表契约（accept/reject UI 前置）"；V0.6.16 变更记录延续项："待收邀请列表查询（accept/reject UI 前置，V0.6.10 §七 另一配合项）"。

**现状核查（后端 Service 实读 + 契约实证）**：

1. **accept/reject 后端 Service 已就绪**（V0.6.10 前已存在）：
   - `acceptBuddyInvite_Execute({inviteId})`（AcceptBuddyInviteService，UC-8.2）——BR-19 不存在→6001 / BR-20 过期已处理→6002 / BR-21 双方 accepted ≤5→6003；关系置 Accepted
   - `rejectBuddyInvite_Execute({inviteId})`（RejectBuddyInviteService，UC-8.3）——BR-22 不存在→6001 / BR-23 过期已处理→6002；关系置 Rejected
   - 入参均为 `InviteId`（邀请记录 UId，**非对方 userId**）——待收列表必须返回 UId 才能接
2. **缺口：无"待收邀请列表"查询 Service**——学生收到邀请后前端无入口查看/处理（StudyBuddySection 仅搭子列表 + 发起邀请弹窗，无 accept/reject UI）；Domain_Api.md Buddy 控制器清单 **7 个**（AcceptBuddyInvite/GetBuddyRank/InviteBuddy/ListBuddies/ListBuddyCandidates/RejectBuddyInvite/RemoveBuddy）中缺待收列表查询（Oracle C1：原稿"8 个"数量勘误，新增后为 8 个）
3. **实体字段**（DOMAIN_MAP 实证）：`StudyBuddies`：UId/InviterId/InviteeId/Status（Pending/Accepted/Rejected/Removed/Expired）/InvitedAt/AcceptedAt?/ExpiresAt
4. **昵称来源**：GroupMembers.Nickname（V0.6.16 BR-33 已定候选用此）；ListBuddiesService 用空串桩（账户域跨模块）
5. **前端现状**：StudyBuddySection（V0.6.16 改造后）——搭子头像列表 + 邀请弹窗（候选）+ 海报弹窗；rank.tsx `onInvite={() => console.log('invite buddy')}` 为占位（**组件内从未调用，死代码**，Oracle E1 登记）；buddies 数据在 rank.tsx state（`loadBuddies` 定义在 useEffect 内**闭包**，非组件级函数——Oracle C2：需提升为 useCallback 才能作为 onBuddyChanged prop 传递）

### 1.2 目标

1. **后端新增 ListPendingBuddyInvitesService**：当前用户收到的待处理邀请列表（仅 Pending + 未过期 + 被邀请人=我），展示邀请人昵称 + 邀请/过期时间，按最新优先
2. **前端待收邀请区块接真实**：StudyBuddySection 加"待处理邀请"区块（卡片 + 接受/拒绝按钮 → acceptBuddy/rejectBuddy 真实接线 + 错误码映射 + 处理后列表/搭子刷新）
3. **搭子域闭环**：发现（V0.6.16 候选）→ 发起（inviteBuddy）→ **收到（待收列表）→ 处理（accept/reject）** → 搭子列表（V0.6.10）全链路真实

### 1.3 范围决策（不做什么）

| 不做 | 理由 | 归属 |
|------|------|------|
| 微信/站外邀请渠道（二维码/海报）真实化 | 海报弹窗为产品占位（V0.6.16 范围决策延续） | 后续迭代 |
| 搭子解除（removeBuddy）接线 | UI 无解除交互（V0.6.10 不做项延续） | 后续迭代 |
| 同年级跨群候选/邀请 | BR-16 OR 语义，V0.6.16 已决策走链接/海报渠道 | 后续按需 |
| 已发送邀请的撤回/取消 | 契约无对应 Service（BR-17 幂等 6002 语义） | 不做 |

## 二、方案要点

### 2.1 新增 BR（先 tkwf-business 物化，搭子域 §2.6 追加）

| BR | 内容 |
|---|---|
| 搭子-BR-35 | 待收邀请列表：仅返回当前用户为被邀请人（InviteeId=me）且 Status=Pending 且未过期（ExpiresAt ≥ now）的邀请；已过期惰性过滤不返回（不落库 Expired——与 accept/reject 的 6002 运行时判断 `ExpiresAt < now` 口径互补一致）。**副作用（Oracle M3/C3）**：惰性过期不落库 Expired，Status 列保留 Pending；BR-17 重复邀请判断只看 Status 不看 ExpiresAt，故已过期未处理的 Pending 仍会被 BR-17 命中（→6002），导致对方无法重新邀请——本轮不修正（待收查询只读不触碰写路径），后续迭代修正 BR-17 查询条件 |
| 搭子-BR-36 | 待收邀请查询只读无处理动作；展示邀请人昵称（GroupMembers.Nickname，null 兜底 `学生{userId}`）+ 邀请时间 + 过期时间；按 InvitedAt 倒序（最新优先处理）。**无分页（Oracle M4）**：量级有限（受 BR-15 发起方当日 ≤10 + BR-18 +7 天过期约束，单用户待收上限 ≈70 条），与 ListBuddies/ListBuddyCandidates 同范式（均无分页全量返回） |

### 2.2 ListPendingBuddyInvitesService（Buddy 域新增，tkwf-service）

```csharp
// Services/Buddy/ListPendingBuddyInvitesService.cs
[GenerateController]
[AuthorityFilter<XiaoShuTongUserInfo>]
internal class ListPendingBuddyInvitesService(DomainUser<XiaoShuTongUserInfo> user)
    : DomainServiceBase<XiaoShuTongUserInfo>(user)
{
    // BR-35：InviteeId==me && Pending && ExpiresAt>=now（惰性过期）
    // BR-36：只读 + GroupMembers.Nickname + InvitedAt 倒序
    public async Task<ListPendingBuddyInvitesResDto> ExecuteAsync(CancellationToken ct = default)
}
```

- ReqDto：无参（当前用户隐式，同 ListBuddies/ListBuddyCandidates）
- ResDto：`{success, errorCode, items: [
    { inviteId: string, inviterUserId: long, nickname: string, avatarUrl: string, invitedAt: DateTime, expiresAt: DateTime }
  ]}`
- 逻辑：
  1. `StudyBuddies` 按 `InviteeId == me && Status == Pending && ExpiresAt >= now` 查询（EntitySelectAsync 表达式树内完成过滤），内存按 `InvitedAt` 倒序
  2. InviterId 集合 → `GroupMembers` 一次 IN 查询取昵称（多群同人 GroupBy 取任一；空串兜底 `学生{userId}`——V0.6.16 候选同款范式）
  3. `avatarUrl` 空串桩（账户域跨模块，同 ListBuddiesService 范式）
  4. 只读——无任何状态变更

### 2.3 前端 StudyBuddySection 待收邀请区块

- **新 state**：`pendingInvites` / `pendingLoading` / `processingId`（处理中禁点）
- **拉取**：组件挂载时 + accept/reject 成功后重拉 `listPendingBuddyInvites_Execute`（V0.6.16 候选同款模式：打开/操作后重拉）
- **展示**（搭子头像列表下方）：
  - 有 pending：`待处理邀请 (N)` 标题 + 卡片列表——邀请人昵称（null 兜底 `学生{userId}`）+ "N 天前邀请"（相对时间）+ 接受/拒绝按钮
  - **视觉强调（Oracle M1 采纳 A 附条件）**：标题 N>0 时 `text-primary` 加粗 + 标题左侧小红点，确保用户不漏处理（待收是被动触发，区块是唯一发现入口）
  - 空：**隐藏区块**（Oracle M1：产品简洁，待收无内容不占位；不采纳"暂无待处理邀请"弱文案——视觉冗余、与候选空态风格重复）
- **接受**：`acceptBuddyInvite_Execute({request:{inviteId}})` → 成功：重拉待收列表 + 触发 `onBuddyChanged` 回调刷新 rank.tsx 搭子列表（Oracle M2 采纳 A：单一数据源复用 loadBuddies）
  - 业务失败：6001/6002 → "邀请已失效/已过期或已处理" + 重拉列表（从列表移除）；6003 → "学习搭子已满（最多 5 个）"
  - **网络异常（Oracle C4）**：catch → "网络错误，请稍后重试" + **不重拉列表**（避免重拉失败雪崩）+ finally 清空 processingId
- **拒绝**：`rejectBuddyInvite_Execute({request:{inviteId}})` → 成功：重拉待收列表；**不触发 onBuddyChanged（Oracle C10：拒绝的邀请人本来就不是搭子，搭子列表不变，避免多余 RPC）**；失败：6001/6002 → 提示 + 重拉
- **处理态（Oracle C5）**：accept/reject handler 统一 `try { ... } catch { ... } finally { setProcessingId(null) }` 结构，任何分支（成功/业务失败/网络异常）都清空禁点状态，按钮恢复可点
- **错误码映射（Oracle C6）**：新增 `ACCEPT_REJECT_ERROR_MESSAGES`：`'6001': '邀请已失效'` / `'6002': '邀请已过期或已处理'` / `'6003': '学习搭子已满（最多 5 个）'`（reject 端不触发 6003，映射可复用）
- **props 扩展**：新增 `onBuddyChanged?: () => void`（rank.tsx 传提升后的 `loadBuddies` useCallback）；`onInvite` 保留（Oracle E1：死代码登记，本轮不清理）

### 2.4 mock 补齐

- `listPendingBuddyInvitesResDtos`：2 条 Pending（小刚 3 天前 / 小红 1 天前，invitedAt 倒序验证；expiresAt = invitedAt+7 天）
- `acceptBuddyInviteResDtos` / `rejectBuddyInviteResDtos` 已有（V0.6.10 检查过）——确认字段对齐

## 五、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 邀请人不在我的群（群被删/退群） | GroupMembers 查无昵称 → 兜底 | null 兜底 `学生{userId}`（V0.6.16 候选范式；Nickname 为 string? 实证） |
| accept 后搭子列表不刷新 | accepted 关系不可见 | onBuddyChanged 回调 → rank.tsx loadBuddies 复用（Oracle M2；前置：loadBuddies 提升 useCallback） |
| 待收列表与 accept 并发（对方同时撤回/已处理） | 6001/6002 错误 | 错误提示 + 重拉列表（列表为权威，自动移除失效项） |
| 惰性过期致 BR-17 命中过期 Pending（Oracle M3/C3） | 已过期未处理的邀请阻塞对方重新邀请（→6002） | 后续 V0.6.19+ 修正 BR-17 查询追加 ExpiresAt>=now；本轮 BR-35 物化记录副作用，不修正（待收查询只读不触碰写路径） |
| 多群同人昵称不一致 | 昵称取任一 | GroupBy InviterId 取 First（同 V0.6.16 候选去重逻辑） |
| 联调种子无 Pending 邀请 | 待收区块空 | V0.6.17 种子已含 10001-10012 pending（小刚）——走查可实证 |
| onInvite 为死代码（Oracle E1） | 组件内从未调用（空位按钮直接开弹窗），rank.tsx 占位 console.log | 登记后续迭代清理，本轮不处理 |
| reject 无 [Transactional]（Oracle E2） | 单实体单操作事务非必需（既有代码 Accept 有、Reject 无） | 审核报告记录差异供后续评估，本轮不处理 |
