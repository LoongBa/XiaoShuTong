# 前端页面结构与测试策略设计（D05）

> 本文档定义小书童**前端页面结构**（React + shadcn/ui 路由、状态管理，ADR-007）与**分层测试策略**（单元/集成/E2E/回归）。
> 关联文档：`docs/D01-统一题库与多学科学习平台设计.md`（框架）、`docs/D02-学习数据与记忆跟踪设计.md`（数据）、`docs/D03-API契约设计.md`（接口）、`docs/D04-部署架构与运维设计.md`（部署）、`docs/0-产品规划/产品战略与定位-V1.md`（产品战略）、`docs/adr/`（架构决策记录，见 `docs/adr/README.md` 索引）

---

## 一、总体原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | **场景驱动路由** | 页面按使用角色与学习场景组织（学生背记 / 家长报告 / 群主群组任务），对齐产品战略 V1 三方模型 |
| 2 | **API 域对齐** | 页面数据来源对应 D03 API 域（auth/bank/study/stats/pk/user/group/task） |
| 3 | **状态前端缓存** | 会话状态/记忆状态走 Zustand，服务端数据走 TanStack Query 缓存，离线数据走 LocalStorage（微信 H5 无 SW，D04 4.1） |
| 4 | **答案永不下发** | 取题接口只给题干，判题结果由服务端返回（D03 4.5/5.2） |
| 5 | **测试金字塔** | 单元测试（状态机/判题逻辑）> 集成测试（API 契约）> E2E（关键流程） |
| 6 | **契约驱动** | 后端 OpenAPI/Swagger 生成契约，前端类型与契约测试同源 |
| 7 | **AI 友好优先** | 前端统一 React 生态（ADR-007），组件用 shadcn/ui 标准模式，最大化 AI agent 生成质量 |

## 二、页面结构（React Router）

## 三、前端状态管理（Zustand + TanStack Query）

```
stores/
├── authStore.ts        # token/user_id/角色/监护人同意标记（Zustand 持久化）
├── studyStore.ts       # 会话状态机/当前题/四阶状态/hint_level（Zustand）
├── taskStore.ts        # 当前任务/进度/截止时间（Zustand + Query）
├── configStore.ts      # 学科/题型/题库筛选偏好（Zustand 持久化）
└── offlineStore.ts     # LocalStorage 离线队列（微信 H5 无 SW 降级）

queries/                # TanStack Query（服务端状态缓存）
├── banks.ts            # 题库列表/详情/知识点树
├── memory.ts           # 记忆状态/复习队列/热力图
├── tasks.ts            # 任务列表/执行状态
├── stats.ts            # 周月报/错题本
└── parent.ts           # 家长报告聚合（付费态）
```

**关键状态流**（群组任务作答）：

```
taskStore.loadTask()        → GET /tasks/{id}（题清单，不含答案）
student 进入作答            → 创建 session（POST /study/sessions, task_id 关联）
studyStore.submit(answer)   → POST /tasks/{id}/answers
    ← result/confidence/pre_state/post_state/next_review_at
taskStore.updateProgress()  → 本地进度渲染 + 完成态判定
taskStore.requestHint()     → POST /study/hint → HintBubble 展示
```

**离线降级**（微信 H5，D04 4.1）：`offlineStore` 暂存未提交作答，联网后批量同步（V3 决策：LocalStorage + 增量同步）。

## 四、测试策略

### 4.1 测试金字塔

```
         E2E（Playwright）          ← 关键用户流程
       ┌────────────────┐
       │ 集成测试（xUnit）│          ← API 契约 + 判题链路
       ├────────────────┤
       │ 单元测试（Vitest/xUnit）│   ← 状态机/判题路由/PK 计分/任务进度
       └────────────────┘
```

### 4.2 单元测试（L0）—— 核心逻辑

| 模块 | 测试点 | 框架 |
|------|--------|------|
| 四阶状态机 | **迁移矩阵全组合**（hint×result×state，D01 10.2 共 10 组用例） | xUnit / Vitest |
| 判题路由 | 阈值边界（84%/85%/86%、59%/60%/61% 命中率 → correct/partial/LLM） | xUnit |
| keywords 引擎 | 同义词组命中（"唐太宗"="李世民"）、required 未命中→partial、权重计分 | xUnit |
| 复习间隔 | 艾宾浩斯序列（首次30min→12h→1d→3d→7d→30d）、history_accuracy 系数 0.5-1.5 | xUnit |
| PK 计分 | 胜负规则（总分/同分比用时/平局）、每题超时 0 分、异步合并计分 | xUnit |
| 场景耦合 | full/feedback_only/isolated 三策略 × 答对/答错 状态影响 | xUnit |
| **任务进度** | progress 计算（完成题数/总题数）、逾期判定、截止时间边界 | Vitest |
| **家长报告聚合** | 进度趋势/薄弱点/坚持天数计算、相对进步基准 | Vitest |
| **一次性码状态机** | unused/used/expired 全状态迁移（激活成功→used、过期→expired、重复激活拒绝、过期码不可复用） | Vitest |
| **名单整理（Agent）** | 去重/非法手机号剔除计数（SourceCount→CleanedCount、DuplicateCount/InvalidCount 正确） | xUnit / Vitest |
| **激活校验** | 一次性码+手机号后四位匹配（错位拒绝、码未用/未过期校验、BoundUserId 落库） | xUnit |

### 4.3 集成测试（L1）—— API 契约 + 链路

| 测试 | 内容 | 工具 |
|------|------|------|
| 契约测试 | D03 全部接口请求/响应 Schema 校验（用 OpenAPI 生成） | Swagger + Pact（可选） |
| 判题链路 | 提交作答 → attempts 写入 → memory_states 更新 → daily_stats 聚合（事务原子性） | xUnit + Testcontainers（PG） |
| **任务链路** | 布置任务 → 成员执行 → progress 更新 → 群主看板聚合 | xUnit + Testcontainers |
| **内测邀请链路** | 内测码激活建群 → 名单导入（Agent 整理）→ 批量生成一次性码 → 成员激活 → GroupMembers 写入（事务原子性，对齐 D02 §四·补3） | xUnit + Testcontainers |
| PK 流程 | 发起→加入→作答→合并计分→AI 点评（async 模式） | xUnit + Testcontainers |
| 鉴权 | token 过期/无效/越权访问私域题库（RLS 生效）；**群主/学生/家长三端角色权限** | xUnit |
| 数据迁移 | .txt 解析器 → 3704 题 schema 校验全通过（回归基线） | xUnit |

### 4.4 E2E 测试（L2）—— 关键流程

| 流程 | 场景 | 断言 |
|------|------|------|
| 登录→背诵→判题 | 微信登录 → 选库 → 答题 5 题（含 1 次"请提示我"）→ 结果页 | 状态机迁移正确、★ 点亮、热力图更新 |
| **群主布置→成员执行** | 群主建群 → 名单导入/一次性码 → 成员激活加入 → 布置任务 → 成员完成 → 群主看板执行率更新 | 看板数字正确 |
| **内测邀请全链路** | 群主凭内测邀请码激活建群 → 导入名单（Agent 整理去重）→ 生成一次性邀请码 → 导出 CSV → 成员凭码+微信激活 → GroupMembers 写入 → 布置任务 → 看板执行率更新 | 执行率/GroupMembers/一次性码状态正确 |
| **家长查看报告**（付费） | 家长绑定孩子 → 开通报告 → 查看进度趋势/薄弱点 | 报告数据与作答一致 |
| 错题回练 | 答错 1 题 → 错题本出现 → 回练答对 → mastered | 错题消失 |
| PK 对战 | 发起 → 好友加入 → 双方作答 → 结果 + AI 点评展示 | 胜负/点评正确渲染 |
| 离线补传 | 断网答 2 题 → 联网 → 自动同步 | 增量同步成功 |

**工具**：Playwright（H5 真机 UA 模拟微信 X5）；本地起 dev 全栈（D04 D4-P1 Docker Compose）。

## 五、前端性能与体验（V3 非功能）

| 指标 | 目标 | 手段 |
|------|------|------|
| 首屏加载 | ≤5s（微信中低端安卓） | 骨架屏 + React Router 懒加载 + CDN（D04 4.1） |
| 答题交互 | 判题响应 P95 ≤3s | 本地关键词前置 + LLM 超时降级 |
| 热力图渲染 | 滚动流畅 | Canvas + 按需渲染 |
| 离线体验 | 无网可答 | LocalStorage 暂存 + 增量同步 |
| 包体控制 | H5 首屏 bundle ≤300KB（gzip） | shadcn/ui 按需引入 + Vite code splitting |
