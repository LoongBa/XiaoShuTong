## 五、关键决策与风险

| # | 决策/风险 | 说明 |
|:-:|----------|------|
| ① | **透出原始 HistoryAccuracy vs 系数化 masteryLevel（用户已裁决）** | 走查文档 JEV 缺口 3 提"masteryLevel（近 20 次正确率的 0.5~1.5 系数）"。本方案主案 = 透出**原始 `HistoryAccuracy`（0~1）**：它是最小透出（零新增计算）、前端可直接映射"掌握 70%"展示语义（UI 文档-v2 掌握度百分比）、系数 `Clamp(Acc/0.8, 0.5, 1.5)` 是后端间隔调度内部语义（前端不重算间隔）。**2026-09-25 用户确认主案**（备选系数化 0.5~1.5 弃）。 |
| ② | **契约非破坏性** | ResDto 加字段是向后兼容新增（GraphQL 加可选字段、ts-client 类型扩展），WebH5/AdminWasm 既有调用不消费即可，零破坏。与 ADR-008"判题契约本体不动"的表述不冲突（该 ADR 针对去桩，本方案是契约扩展）。 |
| ③ | **V0.6.1 已提交（基线干净）** | 并行任务已收口提交 V0.6.1（`a58338f` feat + `c0b2481` docs，全套件 389/0/2）。工作区仅剩本方案文档（untracked），T1 基于 V0.6.1 后的 `SubmitAttemptService.cs`（增量集合已就位）编码，无工作区混淆。 |
| ④ | **HistoryAccuracy 口径确认** | `CalcHistoryAccuracyAsync` L262-274 按 QuestionId 全历史窗口（HistoryWindow 常量）取均值——"近 20 次"窗口正确；断言用区间容差防 Round(,4) 边界。 |
| ⑤ | **走查文档不再误读** | T3 标注后，走查附录成为"历史时点快照 + 复核结论"双状态文档，后续 Agent 读档不再按过期缺口开工。 |
| ⑥ | **KeywordGroup 清理边界（Oracle 已实证）** | Oracle 复核：`KeywordGroup` 为独立文件（`Tools/KeywordGroup.cs`），被 QuestionMetaProvider / ImportQuestionsService / JudgingEngineService（L121-133 自解析）等消费，**与 LocalJudgmentEngine 无依赖**。T2 仅删 LocalJudgmentEngine.cs，KeywordGroup 保留，不扩大清理面。 |
