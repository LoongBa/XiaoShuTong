## 二、任务 T1：PkForfeitDetectionJob（读侧一次 IN，低复杂度）

### 2.1 现状（源码实证）

`PkForfeitDetectionJob.ExecuteAsync` L34-70：
- L34-35：一次查全部 `Status == Ongoing` 的 match ✅（无 N+1）
- L41：`foreach (var match in ongoing)` → `PlayersDs.EntitySelectAsync(x => x.MatchId == match.Id)` —— **N+1**：每对局一次查询

### 2.2 改动

一次 IN 查全部 ongoing match 的 players → 内存按 MatchId 分组：

```csharp
var ongoing = await MatchesDs.EntitySelectAsync(x => x.Status == PkMatchStatus.Ongoing, ct: ct);
if (ongoing.Count == 0) return;  // BR-22 幂等：空批跳过

var matchIds = ongoing.Select(m => m.Id).ToArray();
var allPlayers = await PlayersDs.EntitySelectAsync(x => matchIds.Contains(x.MatchId), ct: ct);
var playersByMatch = allPlayers.GroupBy(p => p.MatchId).ToDictionary(g => g.Key, g => g.ToList());

foreach (var match in ongoing)
{
    try
    {
        var players = playersByMatch.GetValueOrDefault(match.Id) ?? [];
        // ... 原 BR-21/BR-23 逻辑不变（遍历 players 判弃权）...
    }
    catch { /* BR-22 单对局失败继续 */ }
}
```

**语义保持**：BR-21（30s 重连跳过）/ BR-22（幂等、单对局失败不中断）/ BR-23（弃权结算）不变——仅把"逐对局查 players"改为"一次 IN + 内存分组"。

```csharp
var masteryByKey = userMastery.ToDictionary(

```

**语义保持**：BR-47（无作答跳过）/ BR-48（单用户失败不中断）/ BR-49（聚合口径）/ BR-50（按需触发）不变。幂等（全量重算 + Upsert）不变——仅读侧从逐分组查改一次批量。

## 四、任务 T3：RankSnapshotFreezeJob（批量 IN 取指标 + 快照 map，高复杂度）

### 4.1 现状（源码实证）

`RankSnapshotFreezeJob.ExecuteAsync` L43-125：
- L47-48：一次查全部 Active 群组 ✅
- L65-66：`FreezeGroupAsync` 内一次查组成员（GroupId + Role=Student）✅
- L79-83：`foreach (var memberId in memberIds)` → `DailyDs.EntitySelectAsync(x => x.UserId == memberId)` + `MasteryDs.EntitySelectAsync(x => x.UserId == memberId)` —— **N+1**：每成员 2 次查询
- L131-133：`UpsertSnapshotAsync` → `SnapshotsDs.EntityGetAsync(x => x.UserId == userId && ScopeType==Group && ScopeId==groupUid && Subject=="All" && MetricType==metric && SnapshotDate==date)` —— **N+1**：每(成员×5 指标)一次查询

### 4.2 改动

**第一步：一次 IN 取全部成员的指标**（替代逐成员 2 次查询）：

```csharp
// 在 FreezeGroupAsync 内、逐用户循环前：
var allDaily = await DailyDs.EntitySelectAsync(x => memberIds.Contains(x.UserId), ct: ct);
var allMastery = await MasteryDs.EntitySelectAsync(x => memberIds.Contains(x.UserId), ct: ct);
var dailyByUser = allDaily.GroupBy(d => d.UserId).ToDictionary(g => g.Key, g => g.ToList());
var masteryByUser = allMastery.GroupBy(m => m.UserId).ToDictionary(g => g.Key, g => g.ToList());

// 逐用户循环内改为内存取值：
dailyByUser.GetValueOrDefault(memberId) ?? []  // 替代 DailyDs 查询
masteryByUser.GetValueOrDefault(memberId) ?? []  // 替代 MasteryDs 查询
```

**第二步：一次批量取已有快照建 map**（替代每(成员×指标) EntityGetAsync）：

```csharp
// 在 5 指标循环前：
var existingSnapshots = await SnapshotsDs.EntitySelectAsync(
    x => memberIds.Contains(x.UserId)
         && x.ScopeType == RankScopeType.Group && x.ScopeId == group.UId
         && x.Subject == "All" && x.SnapshotDate == snapshotDate, ct: ct);
var snapByKey = existingSnapshots.ToDictionary(
    s => (s.UserId, s.MetricType), s => s);

// UpsertSnapshotAsync 改为内存查 map（签名不变，键 (UserId, MetricType) 唯一——Scope/Subject/Date 已外提过滤）：
if (!snapByKey.TryGetValue((userId, metric), out var existing))
    await SnapshotsDs.EntityCreateAsync(...);
else { existing.MetricValue = value; existing.Rank = rank; await SnapshotsDs.EntityUpdateAsync(existing, ct); }
```

**语义保持**：BR-09（无成员/无指标跳过）/ BR-10（单范围失败不中断）/ BR-11（战力组成）/ BR-12（战绩组成）/ BR-13（同一 (User,Scope,Subject,Metric,Date) 幂等 upsert）不变。

> **注意（决策点 M1）**：快照键 map 用 `(UserId, MetricType)`——因查询已外提 `ScopeId=group.UId && Subject=="All" && SnapshotDate==snapshotDate` 过滤，同组同日期下该键唯一。若担心后续 Scope/Subject 扩展，可改用全键 `(UserId, ScopeType, ScopeId, Subject, MetricType, SnapshotDate)` 更稳（见 Oracle 评审）。

## 五、任务 T4：BankHintBackfillJob（写侧批量更新，中复杂度）

### 5.1 现状（源码实证）

`BankHintBackfillJob.ExecuteAsync` L30-82：
- L40-41：一次查全部（或按 bankId）✅
- L42：内存过滤 Hint 空行 + Take(1000) ✅
- L75-76：`foreach question` → `QuestionsDs.EntityUpdateAsync(question, ct)` —— **N+1（写侧）**：每行一次提交

### 5.2 改动

收集待更新的 question 列表 → `EntityUpdateBatchAsync` 批量提交：

```csharp
var toUpdate = new List<Questions>(BatchSize);
foreach (var question in chunk)
{
    // ... 卡片匹配逻辑不变（(a) 精确 (b) 包含匹配）...
    if (string.IsNullOrWhiteSpace(hint)) { unmatched++; continue; }
    question.Hint = hint;
    toUpdate.Add(question);
}
if (toUpdate.Count > 0)
{
    await QuestionsDs.EntityUpdateBatchAsync(toUpdate, ct);
    filled += toUpdate.Count;
}
```

**语义保持**：幂等（已回填跳过 / 不覆盖已有 Hint）不变；返回 (Filled, Unmatched, Total) 不变。写侧从逐行提交改批量一次——`EntityUpdateBatchAsync` 为框架 sealed 批量写（自动事务/审计）。

> **注意（决策点 M2）**：`EntityUpdateBatchAsync` 是否单事务提交——需确认框架批量写的事务语义（对比逐行 `EntityUpdateAsync` 各为独立原子操作；批量若单事务则整体失败回滚 vs 逐行部分成功）。Job 语义容忍度：Hint 回填非关键路径，若批量失败可整体重跑（幂等）。见 Oracle 评审。

## 九、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| IN 查询参数上限（数千 Id） | 超大批 IN 可能超参数数限制 | Job 场景成员/对局数有限（群组规模）；如遇超限可分块 IN（Chunk 50-100） |

| 批量写事务语义（M2） | 批量失败整体回滚 vs 逐行部分成功 | 确认框架 `EntityUpdateBatchAsync` 事务语义；Hint 回填幂等可整体重跑 |
| 既有测试缺失（BankHint） | 修复无回归保障 | 按 tkwf-test 补基础用例 |
