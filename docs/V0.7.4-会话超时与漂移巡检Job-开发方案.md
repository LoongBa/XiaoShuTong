## 二、任务 T1：会话超时 Job（SessionTimeoutJob）

### 2.1 现状与问题（ADR-009 + 源码实证）

**BR-05 幂等语义**（`.TKWF/Business.md` L72）："同一任务续做幂等：已存在进行中会话则复用，不重复建"——`CreateStudySessionService` L53-60：`SessionsDs.EntityGetAsync(x => x.UserId == userId && x.TaskId == taskId && x.EndedAt == null)` 命中则复用。

**问题**（ADR-009 G-4 + S4 + 后续待办）：`StudySessions.EndedAt` 由 `EndStudySessionService` 写入（前端主动调用）——**用户中途弃用（不调 endStudySession）→ 会话永远 EndedAt==null**：
- BR-05 永远复用同一会话（用户无法开新会话，任务进度 SessionId 指针卡住）
- 历史会话无法审计（无结束信号）
- `GetSessionQuestionService` 的 EndedAt==null 校验因无写入方而 moot（ADR-009 G-4 原文）

**ADR-009 裁决**（L40/L74）："不引入会话超时定时 Job（触发时机选'前端主动 + 题集耗尽兜底'，Job 兜底后续评估）"——**本轮评估落地**。

### 2.2 设计

**扫描条件**：`EndedAt == null && StartedAt < now - TimeoutWindow`（超时窗口，建议 **24h**——超过 24h 无收尾信号的会话视为弃用）。

**收尾动作**（决策点 M1）：
- **M1 选项 A（推荐）**：仅置 `EndedAt = StartedAt + TimeoutWindow`（业务时间语义：会话实际存活到超时点）——最小改动，释放 BR-05 复用即可，CorrectCount/TotalTimeMs 不聚合（弃用会话的统计无意义，且聚合需扫 attempts 成本高）。
- **M1 选项 B**：对齐 `EndStudySessionService` 聚合写全值（CorrectCount/TotalTimeMs + EndedAt）——统计完整但成本高（每会话扫 attempts），弃用会话价值低。

**为什么 A 合理**：核心诉求 = 释放 BR-05 幂等复用（用户能开新会话）+ 会话生命周期闭环（EndedAt 有值可审计）。CorrectCount/TotalTimeMs 是作答统计，弃用会话（超时未主动收尾）的统计本身不可信（可能作答到一半弃用）。若需完整统计，前端正常收尾路径（endStudySession）已覆盖。

**语义保持**：
- 后续 `CreateStudySessionService` BR-05 查询 `EndedAt == null` → 超时会话已被置值 → 新建（不复用）✅
- `GetSessionQuestionService` EndedAt 校验 → 超时会话后续访问走 `SessionEnded` 路径（对齐正常收尾语义）✅
- 幂等：重复执行只扫描仍未收尾的会话（已置 EndedAt 的不再扫描）✅
- 单会话失败不中断整批（BR 模式对齐 TaskOverdueScanJob BR-21）✅

### 2.3 代码骨架

```csharp
[BackgroundJob]
internal class SessionTimeoutJob(DomainUser<XiaoShuTongUserInfo> user)
    : DomainServiceBase<XiaoShuTongUserInfo>(user)
{
    private const int TimeoutWindowHours = 24;
    private StudySessionsDataService? _sessionsDs;
    private StudySessionsDataService SessionsDs => _sessionsDs ??= User.Use<StudySessionsDataService>();

    public async Task ExecuteAsync(CancellationToken ct = default)
    {
        var cutoff = DateTime.UtcNow.AddHours(-TimeoutWindowHours);

        // 一次查全部超时未收尾会话（读侧一次 IN，V0.7.3 范式）
        var stale = await SessionsDs.EntitySelectAsync(
            x => x.EndedAt == null && x.StartedAt < cutoff, ct: ct);
        if (stale.Count == 0)
            return;

        foreach (var session in stale)
        {
            try
            {
                session.EndedAt = session.StartedAt.AddHours(TimeoutWindowHours); // M1-A：业务时间语义
                await SessionsDs.EntityUpdateAsync(session, ct);
            }
            catch
            {
                // 单会话失败继续（对齐 TaskOverdueScanJob BR-21 模式）
            }
        }
    }
}
```

**注意**：Job 无 `[GenerateController]`（无对外接口）——对齐 TaskOverdueScanJob（`[BackgroundJob]` 声明 + SG 自动登记 DI + AddBackgroundJobs 接线）。

## 三、任务 T2：漂移周期巡检 Job（ProgressDriftAuditJob）

### 3.1 现状与问题（V0.6.1 §七-2 + SubmitAttemptService 源码实证）

**BR-24 进度派生**（Business.md L91 + SubmitAttemptService L376-454）：
- 增量式：每次作答按 QuestionId 查本题跨会话 attempts → 判定"新消费" → 增量入 `ConsumedQuestionIds` → `Progress = 集合大小 / QuestionCount × 100`
- **近完成校验**（L436-437）：`consumedSet.Count >= totalCount - 1` 才触发 `RebuildIfDriftedAsync` 全量重算
- **漂移极端**（V0.6.1 §七-2 登记）：若 `consumedSet` 含缺失/多余元素（并发、遗留、增量 bug）→ Progress 卡在 <100 **且不再触发近完成校验**（用户不再作答时永不触发）→ "卡 <100 永不触发" 极端

**V0.6.1 处置**："近完成触发放宽已缓解；周期 Job 成本不匹配，登记后续项"——本轮落地。

### 3.2 设计

**扫描条件**：`Status == Pending || Status == InProgress` 的任务分配（已完成/逾期不巡检）。

**巡检动作**（决策点 M2）：
- 对每条分配：从该分配关联的任务会话 attempts **全量重算** `actualConsumed`（复用 `SubmitAttemptService.RebuildIfDriftedAsync` L487-491 算法：任务会话 attempts → GroupBy QuestionId → 消费判定 `Correct || Count >= MaxAttempts`）
- 与 `ConsumedQuestionIds` 增量集合 `SetEquals` 比对 → 不一致 → 校正集合 + 重算 Progress + 状态迁移（Pending→InProgress / ≥100→Completed+CompletedAt，对齐 BR-24）
- 一致 → 跳过（不写入）

**M2 选项**：
- **A（推荐）**：Job 内独立实现全量重算逻辑（复制 RebuildIfDriftedAsync 算法核心 ~10 行）——Job 与 SubmitAttemptService 各自独立演进，避免跨类耦合；算法稳定（BR-24 判定口径），复制风险低
- **B**：提取公共方法（如 `TaskProgressHelper.RebuildConsumedAsync`）供两端复用——单一事实源，但触碰 SubmitAttemptService 核心路径（回归风险）

**为什么 A 合理**：RebuildIfDriftedAsync 是 `private` 方法（依赖 SubmitAttemptService 的私有字段状态），提取需改动热路径（SubmitAttempt 每次作答都走）；Job 是低频巡检（非热路径），独立实现算法副本（~10 行）成本远低于热路径改动风险。判定口径从 Business.md BR-24 抄录（唯一权威），非臆造。

**全量重算细节**：
- 该分配关联的任务会话：`SessionsDs.EntitySelectAsync(x => x.TaskId == assignment.TaskId && x.UserId == assignment.UserId)` → sessionIds
- 任务 attempts：`AttemptsDs.EntitySelectAsync(a => a.UserId == userId && a.SessionId != null && sessionIds.Contains(a.SessionId.Value))`
- `actualConsumed = attempts.GroupBy(QuestionId).Where(消费判定).Select(Key).ToHashSet`
- `MaxAttempts` 常量：与 SubmitAttemptService 一致（查源码确认值，对齐口径）

**语义保持**：
- 一致 → 不写（巡检幂等，无副作用）
- 不一致 → 校正（重建集合 + 重算 Progress + 状态迁移，对齐 BR-24 判定口径）
- 单分配失败不中断整批 ✅
- Completed/Overdue 不巡检（已完成幂等）✅

### 3.3 代码骨架

```csharp
[BackgroundJob]
internal class ProgressDriftAuditJob(DomainUser<XiaoShuTongUserInfo> user)
    : DomainServiceBase<XiaoShuTongUserInfo>(user)
{
    private TaskAssignmentsDataService? _assignmentsDs;
    private TaskAssignmentsDataService AssignmentsDs => _assignmentsDs ??= User.Use<TaskAssignmentsDataService>();
    private StudySessionsDataService? _sessionsDs;
    private StudySessionsDataService SessionsDs => _sessionsDs ??= User.Use<StudySessionsDataService>();
    private AttemptsDataService? _attemptsDs;
    private AttemptsDataService AttemptsDs => _attemptsDs ??= User.Use<AttemptsDataService>();
    private TasksDataService? _tasksDs;
    private TasksDataService TasksDs => _tasksDs ??= User.Use<TasksDataService>();

    private const int MaxAttempts = 2; // 对齐 SubmitAttemptService（消费判定口径，BR-24）

    public async Task ExecuteAsync(CancellationToken ct = default)
    {
        // 一次查全部未完成任务分配（Pending/InProgress）
        var assignments = await AssignmentsDs.EntitySelectAsync(
            x => x.Status == AssignmentStatus.Pending || x.Status == AssignmentStatus.InProgress, ct: ct);
        if (assignments.Count == 0)
            return;

        foreach (var assignment in assignments)
        {
            try
            {
                await AuditOneAsync(assignment, ct);
            }
            catch
            {
                // 单分配失败继续
            }
        }
    }

    private async Task AuditOneAsync(TaskAssignments assignment, CancellationToken ct)
    {
        // 1. 该分配关联的任务会话
        var taskSessions = await SessionsDs.EntitySelectAsync(
            x => x.TaskId == assignment.TaskId && x.UserId == assignment.UserId, ct: ct);
        var sessionIds = taskSessions.Select(s => s.Id).ToHashSet();
        if (sessionIds.Count == 0)
            return; // 无会话 → 无作答记录，不巡检

        // 2. 全量重算消费集合（对齐 BR-24 判定口径：Correct 或 ≥MaxAttempts）
        var taskAttempts = await AttemptsDs.EntitySelectAsync(
            a => a.UserId == assignment.UserId && a.SessionId != null && sessionIds.Contains(a.SessionId.Value), ct: ct);
        var actualConsumed = taskAttempts
            .GroupBy(a => a.QuestionId)
            .Where(g => g.Any(a => a.Result == JudgmentResult.Correct) || g.Count() >= MaxAttempts)
            .Select(g => g.Key)
            .ToHashSet(StringComparer.Ordinal);

        // 3. 与增量集合比对 → 不一致则校正（对齐 RebuildIfDriftedAsync SetEquals 语义）
        var persisted = ParseConsumedSet(assignment.ConsumedQuestionIds);
        if (actualConsumed.SetEquals(persisted))
            return; // 一致 → 不写（幂等）

        var task = await TasksDs.EntityGetAsync(x => x.Id == assignment.TaskId, ct);
        var totalCount = task?.QuestionCount ?? actualConsumed.Count;
        if (totalCount <= 0) return;

        assignment.ConsumedQuestionIds = string.Join(",", actualConsumed.OrderBy(x => x, StringComparer.Ordinal));
        assignment.Progress = Math.Clamp((int)Math.Round((double)actualConsumed.Count / totalCount * 100), 0, 100);
        if (assignment.Status == AssignmentStatus.Pending && actualConsumed.Count > 0)
            assignment.Status = AssignmentStatus.InProgress;
        if (assignment.Progress >= 100)
        {
            assignment.Status = AssignmentStatus.Completed;
            assignment.CompletedAt = DateTime.UtcNow;
        }
        await AssignmentsDs.EntityUpdateAsync(assignment, ct);
    }

    private static HashSet<string> ParseConsumedSet(string serialized) // 对齐 SubmitAttemptService.ParseConsumedSet
        => string.IsNullOrWhiteSpace(serialized)
            ? new HashSet<string>(StringComparer.Ordinal)
            : serialized.Split(',', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries)
                .Where(x => x.Length > 0).ToHashSet(StringComparer.Ordinal);
}
```

| 风险 | 影响 | 对策 |

| SessionTimeoutJob 误杀进行中会话 | 用户长时间学习（>24h）被强制收尾 | 超时窗口 24h 合理（单次学习会话远小于 24h）；误杀后用户可新建会话（BR-05 不复用旧）——语义可接受 |
