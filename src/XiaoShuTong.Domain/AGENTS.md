# AGENTS.md - 小书童-领域层 XiaoShuTong.Domain

> 本目录为 **TKWF 领域层**（Entity / Service / Tools / Jobs），`TKWFRole=Domain`，Dll 模式引用框架。所有业务逻辑在此实现，不承载表现层/传输层代码。
> **代码纪律见仓库根 `Agents_Use_TKWF.md`（OpenCode 项目级自动加载）**，本文档为领域子产品的落地细则。

## 项目定位

- 小书童领域层：9 个业务域（群组 / 题库 Bank / 学习 Learning / 判题 Judging / 任务 / 激励 Stats / 排行榜 Rank / 搭子 Buddy / PK / 家长 Parent / 平台 Platform），26 实体 + 1 视图（PkPlayerStatsView）+ 80+ Service。
- 生成链路：`Entity → dotnet build → xCodeGen 生成 Dto/DataService/Conditions → Service → dotnet build → SG1 生成 Controller/契约接口`。**禁止绕过生成链路手写生成物**。
- 业务规则唯一权威：`.TKWF/Business.md`（已物化，9 域 BR + 20 跨实体约束）。**禁止从源码反推规则**。

## 生成物禁区（硬性）

- ❌ 禁止读 `*.g.cs` / `*.biz.cs` / `DataServices\*.cs` / `Entities\*.cs`（生成源码 500+ 行/文件，冗余且易误导）——结构以活态文档 + Skill 注入为准
- ❌ 禁止手写 `.g.cs` / DataService / Conditions / Controller 接口 / DI 注册（由 xCodeGen/SG 生成）
- ❌ 禁止降低守卫规则 Severity、删除 `[GeneratedBySg]`、修改 `// <auto-generated>`、吞掉规则异常
- ❌ 禁止修改框架代码（`$env:TKWFDeployPath`）
- ✅ 数据访问必须经 `DomainUser.Use<T>()`；写入必须处于 `[Transactional]`（类级）
- ✅ DataService **不构造函数注入**（throw-factory），用 `User.Use<T>()` 懒加载（V4.9+ 统一 API）

> **委托 subagent 的 prompt 必须内联「读取禁区」约束块**（见 `Agents_Use_TKWF.md §7.1`），否则 subagent 可能读生成源码导致文档失效、绕过生成规则。

## tkwf-business 使用时机（写 Service 前检查）

- **首次编写该域 Service 前**：检查 `.TKWF/Business.md` 是否已物化（骨架占位符 → 先执行 `tkwf-business` 物化，再写 Service）
- **业务需求变更时**：涉及业务规则/状态流转/枚举含义 → 增量更新 Business.md（不覆盖已有 BR）
- **审核发现 BR 缺失/有误时**：修正 Business.md 并记 LOG.md
- 红线：每条 BR 必须可从需求/设计文档溯源；溯不到标记"待补充"并报告主 Agent

## Service 编写要点（tkwf-service 核心节制）

- Service 类名 `{DomainNoun}{Action}Service`（如 `SubmitAttemptService`）；`[GenerateController]` 类级；类 `internal`（SG 生成 public 接口）
- DTO 与 Service **同文件内联**（Request Dto 服务接收，Response Dto 返回）
- Response 复用 `{Entity}Dto`/VEntity Dto + 字段裁剪，不新建 POCO（三关检查）；跨表聚合用 VEntity
- `public async` 方法加 `CancellationToken ct = default`；enum switch 必有 default 分支
- 实现后**输出 BR 实现检查清单**（对照 Business.md 逐条 ✅/❌）
